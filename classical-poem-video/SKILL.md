# 静帧短片流水线

把一首古诗词、或者一个历史小故事，做成一支带运镜、字幕、配乐的短片。
成片由本地 ffmpeg 合成，横竖两种版式。

这条流水线的核心不是 ffmpeg 命令，而是**几件必须量出来、不能靠眼睛判断的事**。
凭感觉做出来的版本一定会在这几处翻车，而且往往要到成片才看得出来。
下面把"为什么"写清楚——理解了原因，遇到没写到的情况也能自己判断。

**每一条数字都是踩出来的，不是理论。** 括号里标了是在哪一支上踩的。

## 先选模式

| | **诗词模式** `make_v.py` / `make_h.py` | **讲述模式** `make_story_v.py` |
|---|---|---|
| 做什么 | 一首诗，一句一镜，片尾竖排诗文页 | 一个历史小故事 / 冷知识，有旁白 |
| 时间轴由什么定 | 字数 × 0.45 + 1.8 的可读下限 | **旁白实测时长**（`sync` 量完自动推） |
| 字幕 | 竖排、右侧、楷体 | 横排、左下、黑体 |
| 每镜停留 | 10~13s | 3~8s，12~16 镜 |
| 音频 | 音乐 + 音效 | 旁白 + 音乐**侧链躲闪** + 音效 |
| 最大的风险 | 字看不清 | **把推断说成史实** |

**两种模式共用下面写的绝大部分**：运镜行程的缩放约束、`probe`/`trace`/`measure`
三级实测、平台安全区、调色判据、素材分辨率门槛、音乐时长与 maximin 切入点、
四趟渲染。讲述模式独有的那些（事实分级、旁白气口与语速、横排字幕怎么避开操作栏、
转场当叙事标点、侧链躲闪的数值）看 `references/storytelling.md`。

**故事片和荐书片在出图之前有两道门禁**，两个都要**人**点头，不是检查通过：

| | 门禁 | 怎么过 | 它拦住的是 |
|---|---|---|---|
| 一 | **讲述稿人工确认** | 把稿子交给用户读一遍 | 哪句是废话、哪个转折跳了、第三幕是不是在替读者下结论 |
| 二 | **只有字幕+声音的检查片** | `python make_story_*.py preview` 出片，交给用户听 | 旁白好不好听、断句与气口、字幕跟不跟得上、**片长** |

脚本里是 `GATE_SCRIPT_OK` / `GATE_PREVIEW_OK` 两个字符串，**留空就拦住 `budget`**
（出图前那一步）。写人话不写 `True`。第二道经常直接改数字 ——
《经度》段五按 `est` 排 138.0s，旁白实测回来 **130.5s**，差 7.5s；
有平台硬线时这个差额是致命的，而它只在这个窗口里看得见。
详见 `references/storytelling.md` 第〇节。

**旁白 TTS 有一套定死的配置，照抄别调参**（doubao / 渊博小叔 / storytelling /
emotionScale 3 / **不设 speedRatio**），加一条统一的 `performancePrompt` 再挑十来句
单独加写。"有 AI 味"九成是这几条没照做，尤其是「句尾略收不上扬」。
见 `references/storytelling.md` 第八节。

**交付物不只是成片。** 还要附一份 `发布文案.md` —— 各平台的标题、简介、关键词，
**复制粘贴就能用**。骨架 `python publish.py new 片名`，写完 `python publish.py check`
量标题在各平台被切在第几个字（同一句话小红书切在第 20 字、YouTube 能留到 100）。
最要紧的一条规矩：**标题不能剧透第三幕的反转**。见 `references/publishing.md`。

已跑通并交付的讲述片：《没有夏天的那一年》（1816 无夏之年 → 自行车，
13 镜 / 25 条旁白 / 113.97s / −15.1 LUFS）。它的完整配置就在 `make_story_v.py` 里。

**讲述模式有一个子型：荐书片**（介绍一本书 —— 简介 + 内容 + 评论 + 现实意义）。
机件全一样，但结构、片长、版权三处不同：三幕、165~185s、第三幕**只问
「这本书自己在问什么」**（外挂社会议题会把书盖住，踩过）、不用书封不用剧照。
见 `references/storytelling.md` 第七节。第一支：《吞下宇宙的男孩》（21 镜 / 180.1s）。

**讲述模式还有第二个子型：小说第一人称片**（让书里的一个角色自己把那段经历讲一遍，
**一本书连载多集，一集 600s ± 60**）。它和荐书片正好相反 —— 荐书片站在书外面，
这个站在书里面。机件仍然全一样，但**横版 + 外挂 SRT + 分幕 join**（走《经度》那条路）、
`MOTION` 默认翻成 `static`、**TTS 那套配置不能照抄**（讲述者的声音 ≠ 角色的声音），
另外多两张表：**人称合约**（谁在讲 / 何时讲 / 对谁讲 / 为什么现在讲）和
**忠实度分级**（原著 / 暗示 / 我加的）。版权上有一个极容易踩的坑：
**原著公版 ≠ 角色形象公版**（怪物的螺栓头是 1931 年环球影业的美术设计，至今在版权内）。
见 `references/storytelling.md` 第九节。**第一支还没跑完，那一节里标「待实测」的都别当数。**

## 三条轴：开工前定死，两种模式都适用

选完模式，还有三件事要先定。它们各自有默认值，**但每一条都会往回改前面的决定**
（片长、素材门槛、分镜方式），做到一半再改要重来，所以放在最前面。

| 轴 | 值 | 默认 | 改了会连带什么 |
|---|---|---|---|
| `MOTION` | `kenburns` / `static`，**可逐镜覆盖** | `kenburns` | 素材分辨率门槛、每镜停留、粒子层的价值 |
| `MUSIC_MODE` | `library` / `generated` / `public_domain` / `none` / **`song`** | `generated` | 片长怎么排、`pick` 挑什么、归一化策略、要不要附授权 |
| `IMG_SOURCE` | `generated` / `found` | `generated` | **分镜跟着图走还是图跟着分镜走**、要不要登记来源 |

三条都有对应的自检，`check` 会跑，而且都带**回归自测**（造一个错，检查必须报警）。

- 运动 → 下面「静帧模式」那一节
- 配乐 → 下面「音乐」那一节，公版那一路详见 `references/music.md`；
  **`song` 是 MV**（用户给一条带演唱的成品歌），它改的东西最多，见「MV」那一节
- 素材来源 → `references/sourcing.md`「自己去找图」那一节

**这三条不要替用户默认。** 和画种一样，先问清楚；区别是它们没有画种那么不可逆，
所以问一句就够，不用摆候选。

## 开工前定五件事（诗词模式）

这五件事决定后面所有参数，先问清楚或先说清楚你的默认选择，不要边做边改：

1. **版式**。竖版 1080×1920（抖音/小红书/Reels）还是横版 1920×1080（YouTube/B站）。
   两种版式的字幕布局、运镜方向、构图要求都不同，不是裁一下就能互换。
2. **画种**。见下面「画种与极性」那一节。这一条会**反转**字幕极性、调色方向、
   以及给出图任务书的核心要求（留白还是留暗），选错了后面全错。
   **这一条不要替用户定**——按题材筛出 2~3 个候选、写清各自的取舍，让他挑；
   挑完还要先出一张样图实测才算定。它是全流水线唯一一个既不可逆又纯审美的决定。
3. **有没有诵读**。没有诵读时，屏幕上的时间就是全部的时间，
   字幕必须按"读得完"排。有诵读时见下面「诵读」那一节——
   **注意诗词模式和讲述模式在这一条上是相反的**，别照搬。
4. **图文是否强相关**。逐句图解，还是只按情绪和视觉逻辑走。
   后者自由得多——`不尽长江滚滚来`配一片望不到头的高层住宅，
   比老老实实找一条江更有力。
5. **片长**。**要倒着从配乐的封顶算**，见下面「音乐」那一节。这一条最容易漏，
   而漏了要么重排时间轴、要么成片有一段撑不住。

## 时间轴先定死

后面的一切都挂在时间轴上，所以先把它排完、跑通 `check`，再去碰素材和渲染。

**无诵读时的可读下限**：每字 0.45 秒 + 1.8 秒起读。七言一句就是 4.95 秒。
这比通行的中文字幕上限（5~9 字/秒）慢得多，是有意的——诗要读得慢。
实排建议在下限之上再留一到两秒。

**每一镜的长度 = 可读下限 + 进来的转场 + 出去的转场 + 0.8 秒呼吸。**
转场吃掉的那两截必须算进去，字幕不能压在溶解上。

**四言要拆两列（横版是两行），不能挤成一列。** 七言、长短句一句一列就够；
四言（《观沧海》《短歌行》这类）是两句一组、一组一镜。竖版排成右侧**两列**，
右列前四字、左列后四字，自右向左读。连带四处跟着变：

- 可读下限按含标点的九字算 = 5.85 秒
- 字幕带要比一列时更宽：实测两列占到画宽的 76%~93%，
  **选图/写生成提示词时就得按这个宽度要求**，事后没法补救
- 片尾诗文页是一组八字一列，七组就是七列——不要拆成十四列，1080 宽排不下
- 镜数变了，成片长度跟着变

**分隔符用 `|` 不要用逗号。** 句内有该上屏的标点时（「冷落清秋节！」的叹号、
「今宵酒醒何处？」的问号、「不是清泉，是天上虹」的逗号），
拿逗号当分隔符会把它们吃掉，还会把本该一列的句子错拆成两列。（《再别康桥》踩过）

**左列延后出现。** 两列不要整块蹦出来，左列延后这一句时长的 28%~30% 再出，
两列一起留到句末。长短句本来就有停顿，一列一列落下来贴得多。

### 转场时长不该是一个常数

`XFADE` 只是**默认值**，任何一镜都可以写 `xf=` 单独覆盖。
十几镜全用同一个 1.2 秒溶解，节奏会被抹平——观众感觉不到任何段落。

已经在成片上验过好使的排法：

- **词的上下阕之间给 2.0~2.5 秒长溶解**，当作"翻片"，是全片唯一一次段落感
- **情绪陡转或两个特写之间给 0.6 秒短切**（「执手相看泪眼」→「竟无语凝噎」）
- **一问一答之间给 0.8 秒**（「今宵酒醒何处？」→「杨柳岸，晓风残月」），
  短一点才像答上了
- 末镜转诗文页 2.5 秒，其余 1.2 秒

`check` 会验转场不短于 0 也不长于相邻镜头。

### 组诗（一次做多首）

- **片尾一首一页**，每页四列，页右上题「其一/其二/其三」，页左下落款。
  不要一页塞十二列（1080 宽列距只剩 76px）
- **三首之间不用字卡分段，用末句长留**：每首最后一镜给 12~13 秒，其余 10 秒
- **诗文页字号随列数反着调**：七八列 46 号刚好；四列要抬到 56、列距放宽到 168

## 四件必须量、不能看的事

### 一、运镜行程受缩放限制（最常翻车的一条）

`zoompan` 的取景窗被 clip 在画面内，所以缩放 z 时焦点只能落在
`[1/(2z), 1-1/(2z)]` 里。想让画面走过 `d` 比例的行程，**必须** `z ≥ 1/(1-d)`：

| 想走的行程 | 需要的最小 z |
|---|---|
| 10% | 1.12 |
| 20% | 1.25 |
| 30% | 1.43 |
| 40% | 1.67 |

写了位移却不给足缩放，成片就是**原地微缩放**——看起来镜头没动，
而且这个错误在参数表上完全看不出来。这条在一个系列里拦下过十一镜。
`check_moves()` 会算"想走多远"对"实际走得了多远"并报警。

**慢推镜的起幅 z 越小，能摆的余地越窄。** z=1.12 时焦点只能落在 [0.446,0.554]，
`fy=0.44` 就已经出界了。（《雨霖铃》镜 1）

### 二、内容位置要量，而且**要量对区域**

三个测量命令量的是**三个不同区域**，不能互相替代：

| 命令 | 量什么区域 | 什么时候跑 | 性质 |
|---|---|---|---|
| `probe` | 整张图 / 整条字幕带，从头量到尾 | `prep` 之后（自动） | 定位问题，**报警常是误报** |
| `trace` | 镜头**真正经过**的那一段 | 出图之后，渲染之前 | 判一张图能不能用 |
| `measure` | 渲染出来的**无字 master** | `a`+`b` 之后 | 成片阶段最终验 |

`probe` 能发现两类错误：落幅摇进无特征区域（镜头在里面走等于没走）、
字幕压在读不出的底上。**但它量整张图，而镜头只经过其中一段，所以会误报**：

- 曾报"字幕列偏暗、最暗 75"，实际暗的是图顶那片夜空，字幕全程走在 149~193
- 《清平调》报右侧被石绿披帛占了，实际字幕只扫过原图 y 0.415~0.676，够不到
- 落幅：规则说的是**落幅那一帧**，`probe` 报的却是整张图的平坦行。
  《清平调》镜 11 看着完全不能落幅，实测落幅帧整帧极差 103、平坦行 0/16

**这两次如果只有 `probe`，都会去换掉本来完全没问题的图。**

所以跑完 `prep` 一定要跑 `trace`。它按 zoompan 的取景窗公式
`src = (f - 1/(2z)) + (out/边长) × (1/z)` 反查每条字幕在它那一镜里
**实际扫过原图的哪一块**，以及**每一镜落幅那一帧**的平坦度。
缺图会自动跳过，所以出一张就能验一张，不用等图齐。

`trace` 打的扫过范围要取**并集**：上摇时落幅的框底在起幅框底之上，
打"起帧框顶→止帧框底"会把行程严重低估（实测有一镜印成 0.498→0.527，
实际扫过 0.083~0.700）。模板已经修好，自己改的时候别退回去。

**平坦行报警也要复核。** 漆黑的室内（船舱、夜戏）大多数行本来就是均匀的黑，
`trace` 会报"7/16 行几乎无明暗变化，会像静止"——但平坦行量的是**每一行内部的
横向变化**，抓不到缩放。推近镜里主体会变大，照样看得见。
复核办法：`a` 趟跑完抽这一镜的首尾帧比一比。（《雨霖铃》镜 11 就是误报）

### 三、trace 和 measure 要对得上——**但先确认两者建模同一条流水线**

`a`+`b` 跑完之后跑 `measure`，然后和 `trace` 的结果**逐条对一遍**。
两者量的是同一批位置（一个在原图上算、一个在成片上量），应该只差几级。

**对不上通常是运镜没走在你以为的位置上**，那比字幕糊了严重得多，
而且没有别的办法能发现它。这是这套工具唯一一处能自检运镜的地方。

**但在下结论之前，先确认 `pass_a` 里有没有 `trace` 没建模的滤镜。**
《雨霖铃》第一次跑完，measure 一律比 trace 低 5~31 级、且越亮差得越多
（比值稳定在 0.64~0.81）。看着完全像运镜出错。**不是。**
把 `pass_a` 的 `vignette` 关掉重渲同一帧，量到 119，而 trace 报 118——差 1 级。
是 trace 少算了暗角，而字幕带正好在右上角、落在暗角上。

模板里 `vig_factor()` 已经补上了：拿一张纯灰跑一遍 `VIGNETTE`、按画心归一，
改参数会自动跟着变。修完逐条差 0~5 级、两者都判同一句最差，才是该有的样子。

**这个坑有三只脚，《没有夏天的那一年》把另外两只都踩了。** 通用规律是：
`pass_a` / `pass_c` 每加一道影响亮度的滤镜，`trace` **和** `measure` 两边都得跟着补。

| 滤镜 | 加在哪一趟 | 要补的地方 | 不补的后果 |
|---|---|---|---|
| `vignette` | pass_a | `trace` 的 `vig_factor()` | measure 一律低 5~31 级，越亮差得越多 |
| scrim | **pass_c** | `trace` 的 `scrim_factor()` | trace 一律偏亮，字幕余量被低估（52 级 vs 真实 76 级） |
| scrim | **pass_c** | `measure` 抽帧后叠回 scrim | measure 一律偏亮（trace 166 / measure **192**，差 26 级） |

第三只脚最阴：`measure` 按规矩读的是无字的 `master.mp4`，而那是 **pass_b** 的产物，
scrim 是 pass_c 才叠的，所以它量到的是"没压过的底"。
scrim 和文字无关，所以抽帧之后 `overlay` 一次 `scrim.png` 就行，
不违反"必须量无字帧"那条。补完 trace 166 / measure 169，**差 3 级**。

**一个长期报假警的检查等于没有检查**，而这是唯一能自检运镜的地方，不能让它坏着。

### 三之再补：**`trace_pred.json` 会过期 —— 改了 GRADE 必须重跑 `trace`**

上面那张表说的是「加了一道滤镜要两边都补」。**改一个已有滤镜的参数，后果一模一样。**

《白衣女人》集三踩到的：先跑 `trace` → 再量直方图发现这批图比前两集亮、把 `GRADE`
的 curves 收了一档 → `prep`/`a`/`b` → `measure`。结果 **429 处对不上，最大偏差 74.7 级**。

看起来完全像运镜错了。**不是。** 这一支全片静帧、`motion` 刚验过 101 镜均差 0.1，
运镜出错在结构上不可能 —— 这本身就是最快的判据：
**先问「这支片子有没有运镜」，没有的话对不上一定是建模问题。**

`trace` 把预测写进 `trace_pred.json`，`measure` 拿成片和那个文件比。
文件的时间戳停在改 `GRADE` 之前，于是比的是两套不同的调色。
重跑 `trace` 之后：**429 处 → 3 处，最大 74.7 → 8.3 级**，
偏差形状变成「边 −3.7 / 心 −1.6」，正是暗角该有的样子。

**规矩**：`GRADE` / `VIGNETTE` / `SCRIM_ALPHA` / `CLIPS` 的裁切，改任何一个之后，
`measure` 之前都要重跑一次 `trace`。**`trace_pred.json` 比 `prep` 早，就是过期的。**


### 三之补：`motion`——落幅平坦度对暗调图天生爱误报

`trace` 的落幅平坦度数的是"落幅那一帧有几行几乎没有明暗变化"。
对暗调实拍它**结构性地误报**：大片夜空、暗地面本来就是平的，
《没有夏天的那一年》里整帧极差 147~181 的四张好图照样报"会像静止"。

真正要紧的不是落幅那一帧长什么样，而是**这一镜从头走到尾画面变了多少**——
`motion` 命令量的就是这个：每镜渲出来的首尾帧平均绝对差，判据 ≥4 级
（亮度可觉察差约 2~3 级）。那四镜实测 11.0~18.1，全部是假警。

和 `measure` 之于 `probe` 是同一个关系：**筛子在源头上估，判据在流水线的真实输出上量。**

附带一条：`motion` 第一版把读不出的镜头（还在写、moov atom 没落盘）跳过之后
照样打印"全部都看得出来"，**又造了一个不会报警的检查**。
现在"没量到 = 不算通过"。凡是写检查，都要问一句：这一条在最坏情况下会不会静默放行。

### 四、字幕必须在真实成片上验，而且有两个陷阱

**陷阱一：`-ss` 放在 `-i` 前面是输入定位，会把帧的 PTS 重置为 0。**
`subtitles` 滤镜按 PTS 找字幕，于是每一张抽帧都去找 0 秒那一刻的字幕，
结果一个字都渲染不出来——而画面是正常的，很容易误判成字幕样式有问题。
正确做法：**先整片烧一版低码率预览，再从预览里抽帧**（`still` 就是这么做的）。

**陷阱二：要量字幕底的亮度，必须量无字的 `master.mp4`。**
在烧过字的帧上框出字幕区求极值，量到的是**字本身**，不是它压着的底——
每条字幕会整整齐齐报同一个数，看起来条条危险，其实一条都没问题。骗过一次。

判据：底离字色至少差 50 级，用 **1%/99% 分位数**不用绝对极值
（字幕框有四五万像素，一两笔浪尖或一颗星就能把 min 拉到很低）。
每条量**起、中、止**三次——摇镜会把字幕拖过明暗分界，只量中间会漏掉最差的时刻。

**看和量都要做。** `still` 会漏掉"勉强能认但很脏"，
`measure` 会漏掉"数值够但压在人脸、发丝、窗框上"。

## 静帧模式：不做运镜的时候

`MOTION = "static"`，一镜一张不动的画。逐镜可覆盖：`dict(..., motion="static")`，
所以"整片静帧"和"只有尾板静帧"是同一个开关的两种用法。

**什么时候选它**：图本身信息量大、值得停着看（长卷、地图、老照片、信息图）；
素材分辨率不够做运镜；片子有强的语音在带节奏（讲述片尤其）；
或者就是要那个"一页一页翻"的调子。

### 声明要显式，不能靠"z 起止写成一样"

静帧和运镜在参数上只差"起止一不一样"，所以看起来把 `z=(1.2,1.2)`、`f0==f1`
写下去就够了。**不行**：这条流水线最贵的那个 bug——写了位移却没给足缩放、
成片变成原地微缩放——长出来的样子正是"起止实际上一样"。
如果允许隐式，那个 bug 从此变成一个合法配置，`check_moves` 再也拦不住它。

所以两边都拦，而且不去猜哪个是真的：

- 标了 `static` 却写了行程 → 报错
- 标了 `kenburns` 却起止完全一样 → 报错（**这正是那个 bug 的样子**）
- `motion` 写错字 → 报错

### `motion` 命令反过来判静帧镜

渲完跑 `motion`，它量每镜首尾帧的平均绝对差：

| | 判据 | 实测（testsrc2 两镜） |
|---|---|---|
| 运镜镜 | 均差 **≥ 4.0** 级 | 37.7 |
| 静帧镜 | 均差 **≤ 0.6** 级 | 0.1 |

**"静帧镜其实在动"和"运镜镜其实不动"一样是错**，而且更隐蔽——
静帧片里混进一镜缓慢的推近，看片时只会觉得"这一段怪怪的"。
如果只判运镜那一边，静帧片跑 `motion` 会全绿，那又是一个不会报警的检查。
（两个方向都拿故意标反的配置回归验过。）

### 连带改的三件事

**一、素材分辨率门槛从 pp 1.20 降到 1.00。** 这是静帧模式最实际的收益。

运镜镜要 1.20 的余量，是因为 `zoompan` 每一帧都在**非整数倍率**上重采样
（实测 pp=1.0 时只剩 92% 的顶层细节，1.20 才到 98%）。静帧镜没有这回事：
pp=1.0 时裁出来的窗**正好等于输出尺寸**，是恒等重采样，根本不过滤波器。

所以静帧镜要的源图短边就是 `z × 1080`——z=1 时**就是 1080**。
**这不是把检查放松了，是这一镜本来只需要这么多。** 而它决定了能不能用
博物馆开放数据里的画、档案馆的老照片——那些东西很多刚好卡在这条线附近。

**二、每镜停留要缩短，节奏全落在转场和声音上。**（**推测，还没有一支静帧片验过**）
运镜片每镜停 10~13s 是因为镜头一直在走；静帧片画面不动，同样的停留会显得更长。
起手可以试 6~9s，但仍受可读下限约束（每字 0.45s + 1.8s 起读，七言一句 4.95s）。
片长跟着缩，反过来让配乐余地更宽裕，那是好事。
转场时长这时**更不该是常数**——它是全片唯一的视觉节拍。

**三、粒子层从加分项变成全片唯一的真运动。** 雨、落叶、星辉那三种做法不变
（见「粒子层」那一节），但在静帧片里它们的性价比高得多。

### `trace` 的落幅平坦度对静帧镜换了含义

平坦行原本在问"落幅停在这里会不会像静止"，而静帧镜本来就静止，那个问题不成立。
静帧镜只剩一个有意义的问题：**这张画停这么久够不够看**。
所以脚本对静帧镜只在整帧极差 < 25 时提示"会很空"，而且只是提示，不是判据。

### 画种不要替用户定——摆 2~3 个候选让他选

**画种是这条流水线里唯一一个既不可逆、又纯审美的决定。**

不可逆：运镜、字幕、调色、配乐切入点都能单独重跑，画种不能——
它一旦出了图就是十几张的成本，而且"留白还是留暗"这类要求事后补不回来。

纯审美：技能能判的只是**哪几种扛得住这个题材**（下面那张表）；
扛得住之后哪一种更对，是审美，不是判据。那是用户的决定，不是你的。

所以流程是：**按题材筛出 2~3 个扛得住的候选，每个写清楚它买到什么、代价是什么，
让用户挑。** 不要只报一个推荐项，也不要挑完就闷头出图。

3. **连带的硬要求** —— 字幕极性、底子要留白还是留暗、调色重手还是几乎不调

### 选定了也只是"候选定了"

**先出一张样图、跑 `trace` 实测，才算真的定了。** 理由见「画种与极性」那张表上面
那几条：极性和调色都是量出来的，不是按画种套的。《清平调》先入为主差点换掉好图，
《雨霖铃》照抄纸本的调色把中位数压成 0——两次都是"画种定了就以为参数也定了"。

出新画种（表里没有的）时，交付前**在上面那张表里加一行**：
已做过哪一支、正文字幕什么色、底子要求、调色用量。下一支才有得抄。

讲述模式同理，只是候选池不同（多数是电影写实或纪实摄影质感），
但"摆候选让用户选 + 样图实测才算定"这两条一样。

### 纸本 → 写实，一共要翻五处

| | 纸本（浅底墨字） | 暗调写实（白字） |
|---|---|---|
| 正文字幕 | 墨色 + 纸色浅晕描边 | 近白 + **不透明黑**描边 + 投影 |
| scrim | 关（浅底叠浅带像镜头上有指印） | 看实测定，多数时候也不需要 |
| 淡入淡出 | **白场** | **黑场** |
| vignette / 颗粒 | **一律不加**（纸自己有纹理，叠上去就是脏） | **都加**（vignette 还顺手把右上压暗一档） |
| 出图任务书 | 右侧**留白** | 右侧**留暗** |

最后一条最容易想反，而且最贵：**留白事后还能压，留暗不行。**
浅底上加白字要靠加 scrim 压暗，会把画面压脏；换极性又让其余部分消失。

### 先问一句：**画面让字幕，还是字幕让画面**

这条流水线默认的是**画面让字幕**——出图任务书里写死"右侧留白/留暗"，
图按这个要求生成，字幕极性全片统一。前六支都是这么做的，也从没出过事。

但这是**一个可以反过来的取舍，而且要用户来定**（《天净沙·秋思》MV 上被反过来了）：

| | 画面让字幕（默认） | **字幕让画面** |
|---|---|---|
| 出图任务书 | 写死留白/留暗矩形 | **不提任何避让**，画面按最好看的样子画 |
| 字幕极性 | 全片统一 | **逐镜翻**（`FLIP_SHOTS`），底暗的翻白字 |
| 字幕对比度 | 宽裕（实测常在 140~190 级） | 贴着判据过（50 级）也算过 |
| 风险 | 生成器为了"留素"画出**一整块空白板**（见 `references/sourcing.md`） | 某几镜的底花，白字压上去仍然吃力 |
| 什么时候选 | 系列片、要统一感 | 单支、画面本身就是卖点、或者用户明说了画面优先 |

**反过来之后，判据一条都不放松**——`trace` / `measure` 照跑，"离字色至少 50 级"
照验。变的只是**够不到判据时改什么**：默认那条改图，反过来那条改极性。

**别自己替用户翻。** 和画种一样，这是审美优先级，不是技术问题。
问一句就够，不用摆候选。

### 白字版的暗区要求要给精确矩形

不要只说"右上留暗"。把十几镜的 zoompan 取景窗反查取并集，给出一个矩形。
《雨霖铃》给的是：**画宽 55%~95%、画高 10%~55%**，并写明这块里不能有
脸、灯笼、烛火、月亮、亮天、水面反光、浅色衣料、密集枝叶、任何镜面高光。

两处要单独交代：
- **唯一横移的那一镜**字幕扫过的横向范围宽一倍，暗区要从画面中线一直铺到右缘
- **有月亮的那一镜，月必须放画面左侧**——放右上正好落进字幕带，
  而「晓风残月」这种名句重出的代价最大

### 极性开关是对称的，别先入为主

`FLIP_SHOTS` 里放"极性和全局相反"的镜号。**先出图、量了再填。**
《清平调》十五张工笔重彩看着浓艳，实测字幕列 197~226，**零告警**，全程为空。
《雨霖铃》十四条最差 118（离白字 124 级），也是全程为空。
不要因为"这张看着亮/浓"就先改。

## 调色：判据是**量出来的直方图**，不是画种

旧版本这条写的是"一次生成的 AI 图几乎不要调"。**那只对浅底纸本成立。**

《雨霖铃》的生成器交回来的是**技术上欠曝**的片子：
平均亮度 15~19、中位数 8、六到七成面积在 16 以下、**全图最亮只有 133**（一处白都没有），
人脸落在 39~83——手机上开自动亮度就是一团深灰。
而照抄纸本那句 `eq=contrast=1.06:saturation=0.92` 实测把平均从 15.1 压到 8.9、
**中位数直接压成 0**。不是"几乎不调"，是负的。

正确做法分两步，顺序不能换：

```
colorlevels=rimax=0.58:gimax=0.58:bimax=0.58,   # 1. 白点 133 -> 用满动态范围
eq=gamma=1.25:contrast=1.02:saturation=0.94     # 2. 抬中间调，把脸救回来
```

实测结果：平均 41/47，中位数 27/26，最亮 232/237。
**连带收益**：`trace` 的落幅整帧极差从 68/72 涨到 126/134，运镜明显更看得出来。

所以流程是：**先出两张样图 → 量直方图 → 再定调色**，不要按画种套。
用量的：`mean / p50 / p90 / p99 / max`，以及"亮度 < 16 的面积占比"。

### 欠曝有两种，救法不一样（《没有夏天的那一年》）

上面那套 `colorlevels` + `gamma` 是针对**白点塌了**的片子（最亮只有 133，一处白都没有）。
但生成器还会交回另一种：**白点正常、分布极暗**——实测 max 248 / p99 136，
而 median 只有 14、p25 只有 1~8。这种图 `colorlevels` 无事可做，得换招：

- **加反差还是负的**（同一个坑）：`eq=contrast=1.04` 把 median 从 14 压到 **8**、
  p25 从 8 压到 2
- **`eq=gamma` 这次也不能用**：gamma=1.25 把 p1 从 1 抬到 **14**，
  黑位整个浮起来，火山那道黑山脊变成灰的，画面立刻显脏

要的是**只抬中间调、保住真黑**，所以用 `curves`：

```
curves=all='0/0 0.08/0.13 0.28/0.42 0.60/0.70 1/1',eq=saturation=0.98
```

实测 median 14→23、p75 29→47，而 **p1 仍是 0~1**。
连带收益一样：`trace` 的落幅整帧极差从 125/131 涨到 148/153。

**判断用哪一招看 max/p99**：白点塌了（max < 200）用 `colorlevels`；
白点在而中位极低用 `curves`。两种都不要加 contrast。

图库实拍是另一回事：多个摄影师的白平衡、反差、季节甚至黑白彩色都不一样，
**必须重手统一**，不做的话串起来就是 PPT 换页。

## 音乐：**先要长度，再倒推片长**

`MUSIC_MODE` 四个值。下面这一整节写的是 `generated`；
其余三个的取舍、判据和陷阱在 **`references/music.md`**，这里留必须记住的几句：

- **`library`（从素材库挑一条已有的）—— 对音乐要求不高的片子先走这一条。**
  书评、故事、冷知识、科普：全程有旁白盖着，音乐只在句间的缝里露出来，
  库里现成的多半够用，而生成一条要花额度、封顶还是 180~245s 随机不可控。

  ```bash
  python music_index.py find --dur 160 --mode story
  ```

  库在 `ani/_素材库/`，**不在 git 仓库里**（配乐 188MB）。
  首批收编了 19 条配乐 + 14 条音效，其中 **5 条配乐是从没用过的落选候选**——
  做一支片子通常生成 2~3 条只用一条，落选的那些付过费、量过、结构完全可用。

  **诗词片多半仍要新生成**：没有旁白时音乐是唯一的音源，配器还要跟着画种走。
  但落选候选值得先翻一遍——同一个画种做第二支时，上一支的候选 B 常常正合适。

  用完**一定要回去 `music_index.py add --used` 记一笔**，否则下一支不知道它用过了；
  **同一个系列里重复用同一条，观众记得住**。脚本里 `MUSIC_FROM_LIBRARY` 不填 `check` 会拦。

- **`public_domain`（自己找公版）——录音权和作品权是两回事。**
  贝多芬的曲子是公版，某乐团 2010 年的录音不是。这个错在流水线上完全不会被拦，
  要到被投诉才知道，所以 `MUSIC_CREDIT` 五项填不全 `check` 直接不让过。
  拿到之后先跑 `mquality` 量底噪、带宽、声道、头尾静音。
- **`none`（不要背景音乐）——它会改归一化策略，不是少做一步。**
  `loudnorm` 的整合响度带门限，静音段会被剔掉；只剩稀疏音效时，
  归一化会把一层本该若有若无的蝉声硬抬到 −15 LUFS，
  把 SFX 表里逐条写的目标响度全部作废。所以脚本在"只有音效"时**不归一**；
  什么音源都没有时**不产出静音轨**（静音轨会被归一化放大成一片底噪），
  直接出一条无音轨的 mp4，并在 `check` 和 `pass_c` 两处明说。

生成的配乐几乎**一定**自带一段弱前奏或爬坡。再叠一个长淡入，成片开头七八秒
基本是静音——对一支没有诵读、全靠音乐抓注意力的片子，这是致命的。

### 提示词管不住这件事（试过三轮）

- 第一轮写 `full ensemble at bar one`，成品 −20 LUFS 起、一路爬坡
- 第二轮把否定项全列了（no introduction / no build-up / no fade-in / no silence），
  还加了「把第零秒当作全曲最大段落的中间」，成品前 4 秒**仍然**是 −40 → −30 → −22
- 第三轮（《雨霖铃》）写死「至少 4 分 30 秒」，**拿回来 193.4s**

**mureka 的实测范围是 109~245 秒之间随机，提示词管不住。**

下限那个 109s 是《虞美人》踩出来的：同样写死「至少 4 分 30 秒」，拿回 **109.1s**，
比此前记录的下限还低 71 秒。**所以"按最坏的 180s 规划片长"这条以前的建议偏乐观了。**
它的直接后果：93.1s 的片子只剩 16.0s 余地（0.17 倍），
而曲上两处谷相距 59.4s < 片长，**扫遍所有切入点都躲不开**——
这正是"余地不够就怎么挪都撞"的教科书案例。

### 所以片长要倒着从 180s 算

真正解决问题的是**切入余地 = 全曲 − 片长**：

- 《再别康桥》片长 164.8s、曲子 179.9s，只剩 **15.1s**，怎么挪都有要紧落点撞进谷里
- 《雨霖铃》故意把 103 字的词压到 137.6s，拿到 193.4s 时余地 **55.9s**，宽裕得多

**没法靠规划片长来保证余地** —— 拿回 109s 时，除非片子短到 68s 才有 0.6 倍余地，
而那对多数词都不现实。所以真正的做法是**拿到曲子先跑 `pick` 看躲不躲得开**：
谷少而浅就用（《虞美人》两处 0.6/0.7s、降 14~17 dB，接受了），
有中段 breakdown 或长静音才重发。片长仍然别排太长（135~145s 是个好区间），
但要知道那只是提高概率，不是保证。
提示词里仍然要争取时长（写「至少 4 分 30 秒」），但别指望它。
（mureka 提示词上限 **1024 字符**，超了在校验阶段就退回，不消耗额度。）

### 切入点用 maximin 选，不要用加权和

用 `ebur128` 量整首的瞬时响度曲线，扫遍所有可用切入点，按成片上真正要紧的
那几个窗口打分：情绪核心、每段收尾长留、成片中点、末句、诗文页、片尾淡出。

**目标函数是 maximin——最大化这些落点里最弱的那一个**，不是加权求和。
加权和会把开场分拉满、却把成片中点和末句推进曲子最弱处（《清平调》栽过）。
没有诵读的片子怕的不是平均值不够高，是某一处塌下去。

**开场可以故意不放进打分窗口**：片头镜前六七秒只有标题在走、一个字幕都没有，
曲子最弱的一段落在那儿反而合适。把开场让出来，剩下的落点才挑得动。

### 拿到曲子先翻一遍低谷，再决定要不要第二条候选

**`pick` 现在会自动列。** 以前这是句手工提醒，而手工翻要看几百行响度采样，
翻漏是必然的。它把用到的那一段里 < −25 LUFS 的谷全打出来，
并说清每一处落在片上的哪一镜。判读方法没变：

- 《雨霖铃》全曲最低 −70.6，但在 191.1~193.4s——那只是**结尾的自然收尾**，
  不是中段 breakdown；另外只有两处 0.5 秒的浅坑在前奏里，49.5s 切入全避开。
  **判定为干净，第二条候选省了。**
- 《再别康桥》候选 A 在 121~130s 藏了 1.7s 近乎静音，只能弃用

**别盲发第二条候选。** 先量，量出来有中段 breakdown 再发。

音色好坏**量不出来**——挑候选时"这个编制更贴这个画种"是从乐器清单推的，
不是听出来的。多出一条备选、把最终选择权交回给用户，比自己拍板诚实。

淡入收到 0.8 秒左右——听不出是淡入，只避免硬切的瞬态爆音。

## MV：拿一条**带演唱的成品歌**来做片子

用户给一个 mp3（自己写的、suno/mureka 生成的、买了授权的）加一份歌词，
要一支字幕跟着唱腔走的 MV。跑 `lyric_sync.py` + `make_v.py` 的 `MUSIC_MODE="song"`。

**它不是第四种模式，是诗词模式换了个时间轴的主人。** 别的都一样（运镜、竖排楷体、
安全区、调色、素材门槛、四趟渲染），只有一件事反过来：

| | 诗词模式 | **MV** |
|---|---|---|
| 时间轴谁定 | 字数 × 0.45 + 1.8 的可读下限 | **唱腔**。歌已经录好了，改不了 |
| 片长 | 自己排，配乐去迁就 | **必须等于歌长**，多一秒少一秒都是错 |
| 配乐切入点 | `pick` 用 maximin 挑 | 没有切入点，歌从第 0 秒开始 |
| 转场 | 默认 1.2s，段落处给 2.0~2.5s | **由句间空档定，通常 0.2s 上下** |
| 片尾诗文页 | 最后一镜 | 只放得进**尾奏**（这支歌 10.19s，刚好够）；尾奏太短就放前奏，`POEMS` 写 `shot=` 指定挂哪一镜 |

### 先认清一件做不到的事：**唱腔位置检测不出来**

在《断肠人在天涯》（suno 生成，50.6s，吉他伴奏 + 演唱）上试过三条纯 ffmpeg 的路，
**三条都不成立**，别再重试一遍：

1. **中/边声道差**（人声居中、伴奏散开）：抽 FC 中心声道减 side，
   全曲差值在 +1.4 ~ +14.4 dB 之间摇摆，唱与不唱的段落**完全重叠**。
   民谣编制里吉他也在正中间——"居中"根本不是人声的特征。
2. **谱通量找起音**：50.6s 里 **132 个**起音峰，而全词只有 28 个字。
   拨弦每秒 2~3 下，每下都是漂亮的起音，检测器分不出是嗓子还是琴弦。
3. **颤音检测**（人声长音有 4~8Hz 频率颤动，窄带里成同频调幅）：
   24 条 1/6 倍频程带做调制谱，颤音带占比 0.05 ~ 6.96，最高的几个窗口出现在
   **−55 ~ −66 dB 的近乎静音处**（分母塌了），而谱图上肉眼认得出的演唱段只有 0.3。
   判据本身对，信噪比不够就是不够。

真要盲检得先做人声分离（demucs 那一类），是另一个量级的依赖，本地这条流水线扛不住。
**所以时间从人来，机器只做它做得对的三件事：吸附、推导、验证。**

### 时间从哪儿来（按可靠性排）

1. **人报每句的起和止**：听一遍，或在波形编辑器上读。`lyric_sync.py spans`。
   **这是最好的一路**——比只报起点多给一样关键信息：唱段到哪儿结束。
2. **现成时间戳**：平台导出的 LRC。`lyric_sync.py lrc`
3. **手打点**（只有起点）：听一遍，每句开口敲一下，报给 `snap`。
4. 都没有：`probe --spec` 出谱图切片，在谱图上认演唱段。**但见下面那一节——
   这条路我实测是错的，只能当"先摆个位置等人来纠"，不能当结论。**

### 谱图上猜出来的位置，实测五句错四句

我在《断肠人在天涯》上按谱图猜了五句的起点，然后用户听了一遍报回真值：

| 句 | 我猜的 | 实测 | 差 |
|---|---|---|---|
| 枯藤老树昏鸦 | 16.04 | 16.478 | −0.44 |
| 小桥流水人家 | 23.76 | 20.120 | **+3.64** |
| 古道西风瘦马 | 29.51 | 24.900 | **+4.61** |
| 夕阳西下 | 37.00 | 32.200 | **+4.80** |
| 断肠人在天涯 | 42.96 | 36.500 | **+6.46** |

**第一句几乎猜对，之后越拖越晚**——这个形状说明根因不是"某一句认错了"，
是一个结构性的错误假设：我把"唱段 = 第一个强起音到最后一个强起音"，
于是把五句摊到 16~50s 上。而真相是**唱段 16.48~40.45，后面 10.19s 全是尾奏**，
尾奏里照样密密麻麻全是起音（拨弦），检测器一点都分不出来。

**尾奏和前奏的长度是猜不出来的，尤其尾奏。** 前奏还能靠"第一个强起音"蒙个大概，
尾奏没有任何信号说"人不唱了"——这正是本节开头那三条失败的直接后果。

顺带一个可以自己查的旁证：猜错的那版每句 0.72~1.12 字/秒，
实测是 1.11~1.85。**唱得比"读得完"的下限快得多**，一句六字只有 3~4.6 秒。
排出来每句超过 5 秒还很"从容"的，多半是把间奏算进句子里了。

拿到真值之后再回头看起音检测：五句起点里四句落在最近强起音的 0.21s 以内
（+0.052 / +0.180 / −0.210 / −0.080），第五句 −0.320 被 `spans` 标出来复听。
**所以检测器不是没用，它只能当"印证"，不能当"来源"**——
有了正确的句子位置它能把精度收到 0.2s 以内，没有的话它连句子在哪儿都不知道。

### 人报了起止之后，字幕收在哪儿

唱止不是字幕止：末字停了还有余韵，字幕跟着人声硬切下去显得急。
所以挂到 `唱止 + 0.60s`，再让下一句至少提前 0.40s 出来。

**两句几乎连着时两条同时满足不了**（这支歌第 1、2 句只隔 **0.082s**）。
这时不压缩谁，让字幕**直接换**（留 0.04s，一帧多一点），并且报出来：
这一处放不下任何转场，**两句必须合一镜**——于是「枯藤老树昏鸦」和
「小桥流水人家」共用一张远景，七镜而不是八镜。

### 手打点系统性偏晚，而这是可以量出来减掉的

人对着音乐敲键盘，反应时间 0.15~0.25s，**且这个滞后在一首歌里是稳定的**——
所以它是系统误差，不是噪声。`snap` 先用 0.6s 粗窗给每个点找最强峰，
取偏移的**中位数**当滞后整体校回去，再用 0.2s 窗精吸附。

造过一次：把五个真实起音各推后 0.200s 当成"人手报的"喂进去，
量出滞后 −0.200s、各句离差 0.000s，五句里四句吸回原位、残差 0.000。

还要看**中位绝对离差**：离差小说明这批点只是整体晚了，减掉就好；
离差大（>0.15s）说明点本身没敲稳，这时吸附不可信，宁可报出来让人重敲。

### 吸附窗的上限是量出来的，而且要拿**强峰**去量

吸附只在强峰（通量分位 55% 以上）里找，所以约束是**强峰**间隔的一半，
不是全部峰的。这支歌：全部峰间隔中位 0.30s，强峰间隔中位 0.51s。
第一版拿全部峰比，把一个合法的 0.20s 窗判成"偏大"——**判据用错了对象**。

窗内取**最强**不取最近：人手报的时刻有 100ms 级抖动，"最近"会被一个弱起音
（拨弦余波、换气声）抢走，而唱句开口一定是窗内最强的那一个。

### 换镜余地：MV 最容易翻的一处，而且比想象中小一个量级

**转场压在唱句上，字和画会一起断。** 所以换镜只能落在句间空档里。
这支歌四处空档实测 **0.04 / 0.94 / 2.12 / 0.70s**（按字幕收掉到下一句起点算），
最长溶解分别是 0 / 0.74 / 1.92 / 0.50s ——**默认的 1.2s 只有一处放得下**。
乐句之间的空档是歌给的，不是自己排的，所以 MV 的 `XFADE` 必须逐镜写。

`make_v.py` 的 `check_sung()` 按转场**整段**和唱句求交，不是只看中点——
一个 1.2s 溶解实际横跨 c±0.6，拿中点判会漏掉伸出去的那两截。
反过来，通用的"转场中点 ±0.3s 不许碰字幕"那条在 MV 里**必然误报**
（句间只有 0.4s），所以唱句那几条走 `check_sung`，不走通用规则。

**空档不够就合镜，不是把数调小。** 这支歌第 3、4 句之间只隔 0.15s，
`lyric_sync` 直接报"这两句合一镜"——于是「古道西风瘦马」和「夕阳西下」
共用一张图，六镜而不是七镜。

### 字幕收在哪儿：末字还没唱完，字幕不能先走

一句的末字在最后一个强起音处起音，之后还要拖一段腔。
字幕收在它前面，观众会看见"字没了人还在唱"。规则是两条取小：
下一句出来前 0.40s 收掉；且末字起音之后至少还挂 0.50s。
两条撞上（句子贴得太紧）就报出来——那说明该合镜。

### 诗文页挤在尾奏里，两处会撞（都是 `check` 报出来的）

尾奏 10.19s 听起来很宽裕，实际排下来两头都紧：

- **列数按最长一列反推，不是按诗的自然分段。** 天净沙排三列时最长一列 21 字，
  列底 600+21×46=**1566**，撞上落款顶端(1500)。改成五列（一句一列，
  本来就是它的样子）最长 7 字，列底 922，两头都松。
- **进诗文页那次转场要短。** 给 2.0s 的"翻页"会把诗文页起点推到 43.5s，
  五列 × 0.5s 显完已经 46.7s，而片尾淡出 46.6s 就开始了——字还没出全画面先暗了。
  压到 1.0s 转场 + 0.4s 列距，45.0s 出全，留 1.6s 余量。

### 音频链路上跟着改的三件事

- **不做那 5 秒硬淡出**。成品歌自带收尾，再叠一道等于把人家的结尾抹掉一半。
  淡入同理，歌的前奏就是它的淡入（只留 0.02s 防爆音）。实测尾段电平和原曲一致。
- **`MUSIC_GAIN` 不许压**。压了就成了"背景音乐"，而 MV 里唱是主角。用 0，
  响度交给成片归一（`TARGET_I`）。`check` 会拦 < −3 dB 的写法。
- **`MUSIC_IN` 必须是 0**，`pick` 直接拒跑：歌有自己的头，从中间切进去就不是这首歌了。

### 验证：结构对不等于同步对

`check` 能验片长、重叠、越界、换镜余地——**验不了同步**。同步只有耳朵能验。
`lyric_sync.py proof` 出两样东西，必须过一遍：

- `proof_click.mp3` —— 每句开口处混一声嗒。**嗒在字前面 = 报早了，嗒在字中间 = 报晚了**，
  差多少就把那一句挪多少。
- `proof.mp4` —— 黑底 + 字幕 + 打点 + 走秒。按走秒报"第几句差多少"，改完重跑。

**这一步不能跳。** 前面所有的吸附精度都建立在"人报的那个大概时刻是对的句子"之上，
而句子认错了（少数一句、把间奏当成一句）机器一点都看不出来。

## 诵读：**时间轴不动，语音放进去**（和讲述模式相反）

### 真人朗读只有一整条时，先跑 `vo_split.py`

好的诗词朗读很难找到合适的 TTS，真人读一遍反而容易 —— 但拿到的是**整首读完的
一个文件**，而下面这条链路要的是一句一个文件。补这一步就够了，下游一行都不用改：

```bash
python vo_split.py analyze 朗读.mp3 --from-make-v    # 先看切不切得开
python vo_split.py split   朗读.mp3 --from-make-v    # 再真切
```

**不要按"检测到几段静音就切几刀"**：读七言常是 4+3，句内自带停顿，还会换气。
正确做法是**利用已知的句数 N**，把句间候选静音按时长排序、取最长的 N−1 个——
句内换气一定比句间停顿短，这是朗读的物理事实，比调阈值稳。
（实测一条 11 句的朗读检出 13 处候选，正确取到那 10 处，切点误差最大 99ms、
平均 54ms，且每个切点都落在它该在的那段静音里。）

**切完必须验，而且要两层** —— 两种错法的形状不一样：句数给**少**了是少数几段错
（逐段残差抓）；句数给**多**了是多数段错位，这时 MAD 被自己抬高、
谁都不显得离群（只有查拟合本身的斜率和残差占比才抓得住）。
详见脚本头部的注释。

**这一条工作量落在字幕上：切分是按 `LINES` 的句子走的，所以 `LINES` 必须先定死。**

讲述片的旁白是连着说的，时间轴由语音落点推出来——`SHOTS` 连 `dur` 都不写。
**词不能这么做。** 词是一句一镜、句间大段的静，那个「密→疏」的结构本身就是内容；
让诵读去驱动它，结构就散了。所以诗词模式是反过来的：**时间轴照排，语音放进去。**

落点也不手写：每条诵读挂在它那句字幕上，字幕先出、语音后跟 `VO_LEAD`（默认 0.5s）。
在十几个偏移量上手工凑，一定会漏一两处，而漏掉的那处要到成片才听得出来。

```python
VO = [("东风夜放花千树", "VO_01.mp3"), ...]   # 留空 = 无诵读，整条链路自动跳过
VO_LEAD, VO_TAIL_MIN = 0.5, 0.3
VO_TARGET = -18.0     # 比讲述旁白轻：诵读是画面的一部分，不是信息载体
VO_DUCK = dict(threshold=0.08, ratio=4, attack=40, release=600)   # 压得浅、放得慢
```

`check_vo()` 验两条硬约束，两条都是漏一句就毁一处、而参数表上看不出来的：

- **不能跨转场**——画面切开的瞬间语音被拦腰截断，听感像卡带
- **必须在字幕消失前读完**（留 `VO_TAIL_MIN`）——否则下一句字幕会压上来

### 落点按**出声点**排，不是按文件起点

TTS 逐条的头部静音不一样——《青玉案》十一条实测 0~0.38s。按文件起点排，
"字幕先出多久语音才进来"会一句一个样，**而这个不齐比整体偏晚更难听**。
`vo_onset()` 用 `silencedetect` 量出声点，落点自动往前提那么多。

`vosync` 打落点表：出声点、语音区间、字幕区间、余量、是否跨转场，外加语速。

**语速没有可抄的判据。** 《青玉案》用渊博小叔 speedRatio 0.85 实测 1.8~2.5 字/秒
（扣掉头部静音之后），比讲述片的 4.6 慢一半有余。这个数是记下来当参照的，
不是及格线——**慢到什么程度算对，只能听，量不出来**，和"音色贴不贴"是同一类事，
把最终判断交回给用户。

**诵读该是稀的。** 《青玉案》11 句实测净时长 32.9s，占片长 106.2s 的 **31%** ——
剩下那 69% 的静不是没做完，是词的呼吸。讲述片反过来，旁白占到 78%。

## 音效：增益不能写死 dB，要写目标响度

音乐管情绪的底，音效管"这一刻发生了什么"。四五个声音成本极低、质感差一截。

**先查自己的素材库，再查 ChatCut 内置库，最后才生成。**

```bash
python sfx_index.py            # 自己的库：ani/_素材库/sfx，首批 14 条
```

自己的库里存的是 **mp3 + 提示词 + 分频段实测**，而**判一条音效能不能用必须分频段量**
（见下面第 3 条），量一次存下来就不用再量。首批 14 条已经覆盖了
水声 / 桨声 / 夏虫 / 晚钟 ×2 / 秋风 / 雁鸣 / 雨 / 寒蝉 / 檐滴 / 解缆 / 江风 / 晓风。

ChatCut 的 sound-effects 库只有 35 条，全是 UI / 转场 / 器械类，
**没有任何自然环境声**——所以新的自然声确实要 `submit_sound` 生成，
但先把两个库都查过再说，别直接花额度。生成完 `sfx_index.py add` 记进库。

### 三条硬规矩

1. **每一条都必须写死播放长度。** 让音效"放到自然结束"会互相盖掉，
   而混音本身是"成功"的、参数上完全看不出来
   （18 秒的秋风把后面的雁鸣整个埋掉，《声声慢》踩过）。
   一律 `-stream_loop -1` 进来再按长度裁。
   **生成时就要得比播放长度长**，这样实际不会循环、也就没有接缝。

2. **增益写成"目标响度"，让脚本按实测反算。**
   《雨霖铃》五条生成音效实测 −8.3 / −30.6 / −14.8 / −53.5 / −18.6，**跨度 45 dB**。
   同一个 −21 dB 加在蝉声上是刺耳，加在江风上是 −74 LUFS、等于没有。
   写死增益在这种素材上不可能对，错了还看不出来。
   模板里 `SFX` 第三列是目标 LUFS，`build_audio()` 算 `gain = 目标 − 实测`，
   并在需要提超过 +12 dB 时报警（说明素材本身太轻，底噪会一起上来）。

   目标怎么定：音乐实测响度 + `MUSIC_GAIN` = 音乐在混音里的位置，
   音效一律排在它下面 1~9 dB。动作声最近，环境底最远。

3. **判一条音效能不能用要分频段量，LUFS 会骗人。**
   《雨霖铃》的江风第一版 −53.5 LUFS，看着像生成失败。分频段量之后才明白：
   能量几乎全在 120 Hz 以下（<120Hz −45.2，120–2k −65.1，>2k −79.2），
   是**提示词自己要的** "a low-frequency bed, more felt than heard"，
   而 LUFS 的 K 加权对低频衰减极大——**仪表在说实话**。
   但成片发手机，手机喇叭 500 Hz 以下基本没响应，那条在目标平台上等于不存在。

   所以要量 `<120Hz / 120–2k / >2kHz` 三段，和一条正常的音效对照。
   重生成时在提示词里写死 "must be clearly audible on a small phone speaker,
   not a subsonic rumble"。
   （ElevenLabs SFX 提示词上限 **450 字符**，451 就会被打回，校验阶段退回不消耗额度。）

## 粒子层：加一处真运动，但方向必须自动验

全片是静止的画在被推拉，加一处真运动就换一个量级。由便宜到贵：
ffmpeg 合成的雨/落叶/星辉粒子层（纯滤镜，不用素材）→ 生成带 alpha 的前景元素做视差
→ 关键镜直接生成视频。

已经验过好使的三种：**残雨**（「骤雨初歇」，随字幕落下正好收干净）、
**落叶**（「冷落清秋节」）、**星辉**（「满载一船星辉」）。

### 必须知道的四件事

1. **方向。`crop` 的 y 是取景窗在源图上的位置**，源图第 S 行出现在画面第 (S−y) 行，
   所以 **y 递增 = 画面内容往上跑**。照抄 `t*v mod H`（递增）雨就是往上飘的。
   要往下必须让 y 从 H 递减到 0 再绕回。

   **这个错在系列里活了两支。** 因为它正好落在这条流水线验证习惯的盲区里：
   `still` 抽静帧逐张看是主要的目视关卡，而**单帧的雨丝就是一道竖线、没有方向**；
   参数表上 `t*v mod H` 也长得很正常。只有连续看才发现。
   所以模板里做成了 `make_fx()` 渲完**自动跑的量化检查** `_verify_fx_direction()`：
   雨用垂直互相关、叶用亮像素平均 y，位移为正 = 往下。
   **改完一定要拿旧的有 bug 的文件回归验一次**，确认它真的会报警。

2. **在成片上复验要用带符号帧差。** 绝对值帧差会把方向抹掉——一滴雨从 p 移到 p+k，
   `|f2−f1|` 在 p 和 p+k 两处都留能量，相邻两次帧差共享中间那份，
   相关峰恒定落在 0，看起来像"根本没在动"。带符号时 `d2(y) = d1(y−k)` 才成立。

3. **叠加层必须真的会结束。** 落叶从第 20 秒起冻在画面上一路挂到片尾，
   而它是"正确地"叠在每一帧上的，参数上完全看不出来。
   根不在 `overlay` 的 `eof_action`（加了没用），在上一级：给 `alphamerge` 当底的
   `color=` 源是**无限长**的，`alphamerge` 又默认 `repeatlast=1`。
   三处一起收紧：纯色源给定长 `d=`、`alphamerge` 加 `shortest=1:repeatlast=0`、
   `overlay` 加 `eof_action=pass:repeatlast=0`。

4. **柔边用拉伸不用模糊。** 点打在小图上再放大，每个点被双线性拉成一小团软光；
   用 `gblur` 会把 255 摊到二十几个像素上只剩十几级，星点变成灰疙瘩。

**起点要落在对的镜头里。** 星辉起点取早了 1.6 秒，星星就浮在大白天的河面上——
`check_fx` 只管"盖住那一句"，拦不住这个，是抽静帧才看得出来的那一类。
另外粒子层要叠在 scrim **之前**，否则右上那条压暗会把它一起压掉一档。

## 平台安全区（竖版，**真机验过**）

2026-08-13 用《声声慢》在真机上比过：抖音/小红书竖屏右侧的头像/赞/评论/分享
压在 **x 0.86~1.00、y 0.45~0.85**，顶部导航压在 y 0~0.09。
字幕在 x 0.758~0.932 这同一条竖带上，**所以列底是硬约束**。

**要往上移，不要往左移。** 往左移会挡住画面主体（写实版尤其不能挡脸），
而且连带要求素材的空白/暗带更宽——那是出图时就得定的事。

`SUB_TOP` 按**最长一列的字数**反算：`SUB_TOP + 最长列字数 × 字号 ≤ 864`。
- 7 字一列 → 420 够用
- 9 字一列 → 必须提到 270（420 会掉进操作栏）
- 8 字一列 → 290，上下各留约 80~120px

模板里 `check_safe()` 会验，并且带一个**回归自测**：把字幕放回真机上撞了的旧位置
（`SUB_TOP=700`），检查必须报警。
第一版曾把 `(x0,x1,y0,y1)` 按 `(x0,y0,x1,y1)` 解包，于是检查在确实撞了的位置上
一声不吭——**一个永远不报警的检查比没有检查更糟**，所以回归自测不能省。

诗文页竖排时，**右起第一列离操作栏最近**，整块的列心要左移（1080 画心是 540，
《雨霖铃》八列算下来只能到 500）。横排诗文页文字全在画心，只有顶部导航要看。

## 素材的分辨率是硬门槛

判据是 **pp = 源像素 / 输出像素**，按**每一镜自己的最紧取景**算：
`pp = 裁后有效短边 / 这一镜最大的 z / 1080`。

**旧版写的是"短边 ≥ 成片对应边的 1.5 倍"，那是个 flat 判据，两头都不对**：
对缓推镜多要一倍多的像素，对大推镜反而放行（4K 配 z=2.7 时 pp 只有 1.0 也能过）。

### 拐点是量出来的，而且和画面类型无关

两张**验过是真原生**的图库照片（一密一疏），同一个镜头走完整流水线，
量落幅帧的最高倍频程：

| pp | 0.70 | 0.85 | 1.00 | 1.20 | 1.30 | 1.45 |
|---|---|---|---|---|---|---|
| 保住的顶层细节 | 67% | 83% | 92% | 98% | 99% | 100% |

**两条曲线差不到两个百分点** —— 密和疏一样。所以尺寸只由**运动**决定；
画面类型改的是"最后那几个百分点值不值得买"，不改公式。

于是三档目标：

| | pp 目标 | 为什么 |
|---|---|---|
| 静帧镜 | **1.00** | pp=1.0 时裁出来正好等于输出尺寸，**恒等重采样**，不过滤波器 |
| 运镜镜 | **1.20** | 98%。zoompan 每帧在非整数倍率上重采样，所以要余量 |
| 细节镜 | **1.30** | 99%。人脸特写、工笔织物、市井细节、封面 |

判据分两级：**pp < 1.0 = 在放大，是缺陷，`check` 拦下**；
1.0 到目标之间是取舍不是缺陷，只提示。

### 上限是 PREP，不是钱包

`prep` 第一步就 `scale` 到 `PREP`（竖横版短边都是 2160）。
**源图短边超过 2160 的部分，在流水线第一步就被丢掉了**，后面所有环节都碰不到。
要 2896 等于交给流水线 2160，白付 26% 的线性分辨率、45% 的像素。

某一镜的 z 大到需要 > 2160 时，`budget` 会标出来：那不是素材问题，
是**流水线的天花板**——再大的源图也补不回来，要么降 z、要么改静帧、要么抬 PREP。

### 出图之前跑 `budget`

它按镜反推需要的尺寸并分档汇总，**出图任务书直接抄那张分档表**。
实测在两支已交付的片子上，按镜要比统一 2896 省 **60%~63%** 的像素。

低于 pp=1.0 的代价是**运镜没法做**：941×1672 那一张（当年下限的 0.65 倍），
那一镜的行程只能从 30% 压到 11%，几乎不能动；而这是一支每镜要停十秒半的片子，
镜头一旦不动，十秒会显得非常长。

AI 生成时**务必显式指定尺寸**——很多工具默认出 1K，9:16 的 1K 只有约 1024×1820，
在典型的 z≈1.45 下 pp 只有 0.65，实测只剩 **6 成**的顶层细节。这一条被坑过两次。
但**指定的那个数要来自 `budget`，不是一律填 4K**。

### 第三次：**文件尺寸会骗人**（《青玉案》）

生成器封顶在 941×1672，于是把图**放大**到 2896×5152 再进项目。
文件上写着 2896×5152，任何只看像素尺寸的检查从此必然通过，
而细节还是 941 那么多——有效值是下限的 **0.65 倍**，最紧那一镜每个输出像素
只摊到 **0.59 个源像素**，成片会软。

**试过从像素上自动判"是不是放大的"，判不出来**，两条路都不行：

- 把图降到**恰好**原生尺寸再放大回来，量残差：结果 0.23~0.57 灰阶，
  而原生 4K 是 0.53~0.83——**一个量级，分不开**。
  放大器不是简单重采样（AI 超分会造出细节）时尤其如此
- 1:1 目视对比也不可靠：两张图的"软"可能只是画风、题材或光线不同。
  拿雾夜灯市和硬光工坊比"锐不锐"，比不出东西

唯一站得住的证据是**生成器吐出来的原始文件**（去它的生成目录看尺寸）。

所以这一条**只能靠记录，不能靠检测**：脚本里的 `SRC_NATIVE` 写生成器实际出的尺寸，
`check_resolution()` 按它折算有效短边，而不是读文件。

配套的 `pixels` 命令从每张源图裁 1:1 原始像素贴片拼一张，让你看一眼——
它是辅助，不是判据，理由见上面第二条。**和 `still` 之于字幕是同一个套路：
自动判不出来的，就做成必须看一眼的东西。**

## 渲染分四趟，改什么跑哪趟

| 趟 | 做什么 | 什么时候要重跑 |
|---|---|---|
| `prep` | 裁切 + 统一调色 → img01..N，并自动 `probe` | 换图、改调色、改裁切位 |
| `a` | 每张图做 Ken Burns（+ vignette）**或按 `MOTION` 出静帧** → shots/ | 改运镜、改 `MOTION` 或改了 prep |
| `b` | xfade 溶解转场串成无字无声的 master.mp4 | 改镜头时长、转场或改了 a |
| `c` | 粒子 + 混音 + 归一 + 烧字幕 → 成片 | 改字幕、scrim、音乐、音效、粒子颜色 |

外加十一个验证/工具命令：`check`（永远先跑它）、
`budget`（**出图之前**，按每镜的运动反推要多大的图，分档抄进任务书）、
`trace`（缺图会跳过，出一张验一张）、
`pixels`（**出图之后**，1:1 原始像素贴片联系表，看素材有没有真细节）、
`motion`（**跑在 `a` 之后**，量每镜首尾帧差；运镜镜要看得出动，静帧镜要真的不动）、
`fx`（生成粒子层，自带方向自验）、`pick`（maximin 选音乐切入点，并自动列低谷）、
`mquality`（**公版配乐必跑**，量底噪/带宽/声道/头尾静音）、
`credits`（导出素材来源表，用了找来的素材时是交付物）、
`still`（烧预览抽静帧，用眼睛看）、`measure`（量字幕底，用数字验）。

出图之后的三道，缺一道就会漏掉一类问题：
`check`（有效分辨率，**要先填 `SRC_NATIVE`**）→ `trace`（字幕底与落幅）→ `pixels`（真细节）。

**改了字幕只跑 `c`**——a/b 两趟不含任何文字和声音，重渲是纯浪费。
**改粒子颜色/浓度/方向只跑 `fx` + `c`。**

讲述模式多一趟 `sync`（量旁白实测时长→推整条时间轴），**排在 `check` 前面**；
而且它的 `SHOTS` 不写 `dur`，改了旁白或气口之后要从 `a` 重跑（每镜时长变了）。

## 图从哪儿来：任务书 or 自己找

`IMG_SOURCE` 两个值，选哪个**改的是流水线的方向**：

| | `generated`（默认） | `found` |
|---|---|---|
| 做法 | 写一份自包含的出图任务书交给用户去生成 | 从公版开放数据、图库里找现成的 |
| 方向 | **图跟着分镜走**——"右侧留白"这类硬要求提得出来 | **分镜跟着图走**——一张宋画的留白位置改不了 |
| 主要工作量 | 写提示词、保持风格统一 | 检索、核对、定裁切（`zoom`/`cx`/`cy`） |
| 字幕极性 | 全局定一个，`FLIP_SHOTS` 通常为空 | **多半要一镜一议**，`FLIP_SHOTS` 会真的用上 |
| 分辨率 | 生成时按 `budget` 分档逐镜写 | 常卡在 pp 1.0 上下——**这正是静帧模式的用处** |
| 交付 | 无第三方权利 | **每张登记来源与授权**，`check` 会拦，`credits` 导出 |

具体怎么找、去哪儿找、怎么核对，见 `references/sourcing.md`。
两条容易想反的：

- **`found` 不是省事的那一条。** 省掉的是等出图，换来的是检索和核对，
  而核对那一步有个已经踩过的坑：**永远不要根据文件名、alt 文本或搜索结果的描述
  判断一张图是什么**（见最后一节）。
- **"公有领域"是对**作品**说的，不一定对**这一张翻拍/这一次录音**成立。**
  和配乐那条是同一个道理。填不出 `CREDITS` 的五项就是还没查清楚。

## 出图和配乐往往不在这个会话里

不要假设当前会话有图像生成工具。实践中经常**根本没有**
（ChatCut 连接器只有 music / video / voice / sound），而配乐即使生成成功，
**下载接口也要用户的登录会话——Agent 直接取会 401**（实测确认过）。

**所以"写一份自包含的图片生成任务书交给用户"不是退路，它就是这条流水线的正常形态。**
任务书要能脱离本项目其他文件独立看懂，内容见 `references/sourcing.md`。

**任务书里的尺寸一律来自 `budget`，逐镜（或逐档）写，不写一个统一的 4K 数字。**
出图是这条流水线上最贵的一步，而尺寸是唯一一个**算得出来、不用试**的成本项：
按每镜的运动反推，实测比统一 2896 省 60%~63% 的像素，成片上量不出差别。
早点把它写出来、早点把生成和下载这两件需要用户动手的事说清楚，
比做到一半才发现要卡住强。

**样图出两张，一头一头把风格夹住**：先出全片情绪核心那一张（它定人物长相、
肤质、笔性，后面每一张都要把它当参考图传进去），再出**全片最满最亮、
字幕带留空最难的那一张**——它过了说明这套风格扛得住极端情况；
只用最简的那张确认，等于没确认。这两张过了再出其余的，一次成、零返工。

## 双语音轨：一条画面，两条音轨

**只在横版这一路做**（`make_story_h.py` + `join.py`）：讲述长片、小说第一人称连载。
`LANGS = ["zh", "en"]` 打开，出**一条画面 + 中英两条音轨 + 两份 SRT**。

竖版（`make_story_v.py`）**不做**：抖音小红书没有外挂字幕这回事，那一路必须烧字，
而烧进画面的中文字幕会跟着英文轨一起播。竖版要英文版是另渲一支片子，不是加一条轨。

一句话推出全部设计：**YouTube 的多语言音轨是一条视频 + N 条音轨，画面只有一份。**

- **时间轴归中文。** 英文塞进中文量出来的槽里，画面一帧不动 ——
  反过来让画面迁就英文，两条轨就是两支片子，多音轨本身没有意义了
- **逐句压，不是整条一个倍率**（那是竖版 `vofit` 解决另一个问题的办法）。
  `langfit` 逐句 atempo，上限 ×1.06；**压不进去的不压**，报出这一句还得砍几个词。
  把 1.2 倍的活交给 atempo，是用一个听得出来的毛病换一个看不出来的错位
- **镜末那一句借不到静默** —— 镜末的静默正中骑着转场，借了就把话说到转场底下去
- **英文稿是配音改写，不是翻译。** 逐句直译一定长出去（中文一个字信息更密），
  长出去的那几句要**换个说法**，不是靠压

三处会静默出错，都做了检查：

1. **改了翻译忘了跑 `langfit`** —— `check` 每次从**磁盘上的英文文件**重新量对不对得上槽
2. **`concat` 默认只留一条音轨** —— 不给 `-map` 时 ffmpeg 每种类型只挑一条，
   拼完只剩中文轨，而且返回码 0、能播、时长对。`join.py` 显式 `-map 0`，
   自测里先跑一遍不加 `-map 0` 的命令验证危险是真的
3. **两条轨各自归一** —— 说话密度不同，整合响度天生不同；共用一个测量值会差出台阶，
   而观众正是在切换音轨的那一刻听见它

细则、流程、还没实测的四个数，见 `references/storytelling.md` 第十节。

## 交付

成片规格：H.264 + AAC 48k 立体声，响度归一到 **−15 LUFS**（平台标准 −14~−16）。
双语片是**一个 mp4 里两条音轨**（语言元数据 `zho` / `eng` 写进文件，YouTube 直接认），
字幕中英各一份外挂 SRT，发布文案多一块 `## YouTube (EN)`。
封面单独出一张，同时用 `-disposition:v:1 attached_pic` 嵌进 mp4 做封面帧
（脚本没做这一步，`c` 跑完之后手动 remux 一次，`-c copy` 不重编码）。

**用了找来的素材（图或音乐）时，`credits` 导出的素材来源表是交付物的一部分**，
不是附赠——CC-BY 要求署名，而署名要跟着片子走（发布时贴进简介，必要时进片尾）。

交付时要**主动说**三件事：

- 哪几处是妥协的（素材达不到、音效在手机上会很轻、图文对应牵强）
- 哪几处做了跟原计划不同的决定，以及为什么
- 还留了什么可以改的口子（换某一张图只需要重跑哪几趟）

三条轴的取值也要**明说**，不要让它默默生效：这一支是运镜还是静帧（混用的话哪几镜）、
配乐是生成/公版/没有、图是生成的还是找来的。
**"没有背景音乐"和"完全没有音轨"尤其要说**——它们看起来像做漏了。

## 一条贯穿始终的纪律：看过再说

**永远不要根据文件名、alt 文本、搜索结果的描述或接口返回的元数据判断一张图是什么。**
在一个系列里，靠读缩略图上的编号选图，九张里错了三张——
下载回来一张是城堡、一张是红山茶花、一张是森林。而且尺寸校验全部通过，
因为下到的确实是那个 ID 的图，只是那个 ID 不是看中的那张。

正确做法：图多的时候先拼一张**联络表**（`hstack`/`vstack` 排成网格）核对
序号和画面对不对得上，再单独打开有具体风险的那几张看细节。
渲染完成后**抽静帧真正看一眼**——ffmpeg 退出码是 0 不等于画面是对的。

**但也要知道目视的盲区。** 静帧看不出粒子的运动方向、看不出运镜幅度够不够、
看不出音效会不会互相盖。这三类只能量。**看和量都要做，谁也替不了谁。**

## 还没做过的

按性价比排，下一支挑一两个试，不要一次全上：

1. **片尾一枚朱文印**。生成的图里禁止出现印章（生成出来是乱码），
   但**脚本自己画一枚**盖在落款下方是另一回事，是中国画收尾最认的符号
2. **正文逐字显**。诗文页的逐列显已经做过、效果好；正文逐字会牺牲可读性，
   建议做成开关而不是默认
3. **生成视频代替静帧**（Seedance / Kling）。「解释春风无限恨」那种镜头，
   花瓣真飘起来就是全片的高光——但成本和一致性风险都高，先做单镜试
4. **把 `make_h.py` 升级到和 `make_v.py` 同代**。横版模板已经补上了三条轴
   （`MOTION` / `MUSIC_MODE` / `IMG_SOURCE`）和 `motion` 命令，仍然缺
   `check_safe` / `vig_factor` / `FLIP_SHOTS` / 目标响度音效 / 粒子层 / `pick`
5. **跑一支真的静帧片**，把「静帧模式」那一节里标了「推测」的两条
   （每镜停留 6~9s、静帧片音效要整体抬）换成实测。同理 `references/music.md` 里
   公版配乐底噪判据的那个 30 dB 参考值

- `scripts/join.py` — 把分段渲好的片子拼成全片：concat + **一次**全局响度归一 +
  按实际段起点合并 SRT + 接缝校验。分段制作的坑全在接缝上，且大半不报警。
  多音轨时**每条轨各自归一**、接缝逐条判台阶，concat 显式 `-map 0`
  （不加会静默丢掉英文轨，自测里把这个危险演了一遍）
- `references/sourcing.md` — 找图与生成图：五个画种的共用风格前缀（可原样复用）、
  暗调写实的"留暗"要求怎么写、**`IMG_SOURCE='found'` 那一路怎么走**、验证纪律。
  **要选图或写生成提示词时读它**
- `scripts/vo_split.py` — **把一整条真人朗读切成一句一个文件**。
  好的诗词 TTS 难找，真人读一遍容易，但拿到的是整首读完的一个文件。
  切完填进 `VO` 表，下游一行都不用改
- `scripts/vo_trim.py` — **把 TTS 每条 mp3 头尾的边缘静音剪掉**（`measure` 干量 /
  `apply` 真剪，原件进 `vo_orig/`）。**讲述片下载完旁白后、`sync` 之前必跑的一步**：
  不剪的话每句被"文件自带静音 + `GAP_*`"两层包着，片长凭空涨一成多
  （《潘多拉的瓮》44 条 180.9s → 164.4s，从超硬线变成余量 15.6s）。
  两个会**静默出错**的坑写在 `references/storytelling.md` 第八节：
  `astats` 的 `reset` 是**帧数不是秒**（写 0.05 会变成累积平均、尾部静音全检不出来，
  而脚本照样报"量完了"），以及**阈值要为每个音色重新量**（−45dB 只对 `zhixingnv` 成立）
- `references/codex.md` — **在 Codex 里怎么跑**：环境前提、目录结构、三种模式的
  命令序列、PowerShell 和 bash 的分工（带 drawtext 的 ffmpeg 在 bash 下会段错误）、
  长渲染的后台纪律、报错对照表。**第一次在 Codex 上开工先读它**
- `scripts/lyric_sync.py` — **MV**：把一条带演唱的成品歌和一份歌词对上轴。
  `probe`（起音表/空档/谱图切片）→ **`spans`（人报每句起止，最可靠的一路）**
  / `snap`（只报起点，自动校人手滞后再吸附）/ `lrc`（吃现成时间戳）
  → `check`（结构 + 换镜余地）→ `proof`（打点混轨 + 预览片，**必须听一遍**）。
  出来的 `SUNG` 表整块粘进 `make_v.py`
- `scripts/music_index.py` / `scripts/sfx_index.py` — **素材库**（`ani/_素材库/`，不在仓库里）。
  存 mp3 + 提示词 + 实测数据 + 用过哪几支。
  `music_index.py find --dur <片长> --mode story|poem` 是查库的入口。
  **书评、故事这类对音乐要求不高的片子先查库**
- `references/music.md` — 配乐四种来源：库里挑 / 生成 / 公版 / 不要。
  **录音权与作品权的区别、公版录音怎么量（`mquality` 的四项）、
  没有音乐时归一化为什么要换策略。选 `public_domain` 或 `none` 时读它**
- `references/checklist.md` — 开工到交付的逐项检查表，含所有硬性数值。
  **做完一支准备交付前对一遍**
