# 静帧短片流水线

把一首古诗词、或者一个历史小故事，做成一支带运镜、字幕、配乐的短片。
成片由本地 ffmpeg 合成，横竖两种版式。

这条流水线的核心不是 ffmpeg 命令，而是**几件必须量出来、不能靠眼睛判断的事**。
凭感觉做出来的版本一定会在这几处翻车，而且往往要到成片才看得出来。
下面把"为什么"写清楚——理解了原因，遇到没写到的情况也能自己判断。

**每一条数字都是踩出来的，不是理论。** 括号里标了是在哪一支上踩的。

## 先选模式

| | **诗词模式** `make_v.py` / `make_h.py` | **讲述模式** `make_story_v.py` |
|---|---|---|
| 做什么 | 一首诗，一句一镜，片尾竖排诗文页 | 一个历史小故事 / 冷知识，有旁白 |
| 时间轴由什么定 | 字数 × 0.45 + 1.8 的可读下限 | **旁白实测时长**（`sync` 量完自动推） |
| 字幕 | 竖排、右侧、楷体 | 横排、左下、黑体 |
| 每镜停留 | 10~13s | 3~8s，12~16 镜 |
| 音频 | 音乐 + 音效 | 旁白 + 音乐**侧链躲闪** + 音效 |
| 最大的风险 | 字看不清 | **把推断说成史实** |

**两种模式共用下面写的绝大部分**：运镜行程的缩放约束、`probe`/`trace`/`measure`
三级实测、平台安全区、调色判据、素材分辨率门槛、音乐时长与 maximin 切入点、
四趟渲染。讲述模式独有的那些（事实分级、旁白气口与语速、横排字幕怎么避开操作栏、
转场当叙事标点、侧链躲闪的数值）看 `references/storytelling.md`。

已跑通并交付的讲述片：《没有夏天的那一年》（1816 无夏之年 → 自行车，
13 镜 / 25 条旁白 / 113.97s / −15.1 LUFS）。它的完整配置就在 `make_story_v.py` 里。

## 开工前定五件事（诗词模式）

这五件事决定后面所有参数，先问清楚或先说清楚你的默认选择，不要边做边改：

1. **版式**。竖版 1080×1920（抖音/小红书/Reels）还是横版 1920×1080（YouTube/B站）。
   两种版式的字幕布局、运镜方向、构图要求都不同，不是裁一下就能互换。
2. **画种**。见下面「画种与极性」那一节。这一条会**反转**字幕极性、调色方向、
   以及给出图任务书的核心要求（留白还是留暗），选错了后面全错。
   **这一条不要替用户定**——按题材筛出 2~3 个候选、写清各自的取舍，让他挑；
   挑完还要先出一张样图实测才算定。它是全流水线唯一一个既不可逆又纯审美的决定。
3. **有没有诵读**。没有诵读时，屏幕上的时间就是全部的时间，
   字幕必须按"读得完"排；有诵读时，时间轴由语音落点决定。
4. **图文是否强相关**。逐句图解，还是只按情绪和视觉逻辑走。
   后者自由得多——`不尽长江滚滚来`配一片望不到头的高层住宅，
   比老老实实找一条江更有力。
5. **片长**。**要倒着从配乐的封顶算**，见下面「音乐」那一节。这一条最容易漏，
   而漏了要么重排时间轴、要么成片有一段撑不住。

## 时间轴先定死

后面的一切都挂在时间轴上，所以先把它排完、跑通 `check`，再去碰素材和渲染。

**无诵读时的可读下限**：每字 0.45 秒 + 1.8 秒起读。七言一句就是 4.95 秒。
这比通行的中文字幕上限（5~9 字/秒）慢得多，是有意的——诗要读得慢。
实排建议在下限之上再留一到两秒。

**每一镜的长度 = 可读下限 + 进来的转场 + 出去的转场 + 0.8 秒呼吸。**
转场吃掉的那两截必须算进去，字幕不能压在溶解上。

**四言要拆两列（横版是两行），不能挤成一列。** 七言、长短句一句一列就够；
四言（《观沧海》《短歌行》这类）是两句一组、一组一镜。竖版排成右侧**两列**，
右列前四字、左列后四字，自右向左读。连带四处跟着变：

- 可读下限按含标点的九字算 = 5.85 秒
- 字幕带要比一列时更宽：实测两列占到画宽的 76%~93%，
  **选图/写生成提示词时就得按这个宽度要求**，事后没法补救
- 片尾诗文页是一组八字一列，七组就是七列——不要拆成十四列，1080 宽排不下
- 镜数变了，成片长度跟着变

**分隔符用 `|` 不要用逗号。** 句内有该上屏的标点时（「冷落清秋节！」的叹号、
「今宵酒醒何处？」的问号、「不是清泉，是天上虹」的逗号），
拿逗号当分隔符会把它们吃掉，还会把本该一列的句子错拆成两列。（《再别康桥》踩过）

**左列延后出现。** 两列不要整块蹦出来，左列延后这一句时长的 28%~30% 再出，
两列一起留到句末。长短句本来就有停顿，一列一列落下来贴得多。

### 转场时长不该是一个常数

`XFADE` 只是**默认值**，任何一镜都可以写 `xf=` 单独覆盖。
十几镜全用同一个 1.2 秒溶解，节奏会被抹平——观众感觉不到任何段落。

已经在成片上验过好使的排法：

- **词的上下阕之间给 2.0~2.5 秒长溶解**，当作"翻片"，是全片唯一一次段落感
- **情绪陡转或两个特写之间给 0.6 秒短切**（「执手相看泪眼」→「竟无语凝噎」）
- **一问一答之间给 0.8 秒**（「今宵酒醒何处？」→「杨柳岸，晓风残月」），
  短一点才像答上了
- 末镜转诗文页 2.5 秒，其余 1.2 秒

`check` 会验转场不短于 0 也不长于相邻镜头。

### 组诗（一次做多首）

- **片尾一首一页**，每页四列，页右上题「其一/其二/其三」，页左下落款。
  不要一页塞十二列（1080 宽列距只剩 76px）
- **三首之间不用字卡分段，用末句长留**：每首最后一镜给 12~13 秒，其余 10 秒
- **诗文页字号随列数反着调**：七八列 46 号刚好；四列要抬到 56、列距放宽到 168

## 四件必须量、不能看的事

### 一、运镜行程受缩放限制（最常翻车的一条）

`zoompan` 的取景窗被 clip 在画面内，所以缩放 z 时焦点只能落在
`[1/(2z), 1-1/(2z)]` 里。想让画面走过 `d` 比例的行程，**必须** `z ≥ 1/(1-d)`：

| 想走的行程 | 需要的最小 z |
|---|---|
| 10% | 1.12 |
| 20% | 1.25 |
| 30% | 1.43 |
| 40% | 1.67 |

写了位移却不给足缩放，成片就是**原地微缩放**——看起来镜头没动，
而且这个错误在参数表上完全看不出来。这条在一个系列里拦下过十一镜。
`check_moves()` 会算"想走多远"对"实际走得了多远"并报警。

**慢推镜的起幅 z 越小，能摆的余地越窄。** z=1.12 时焦点只能落在 [0.446,0.554]，
`fy=0.44` 就已经出界了。（《雨霖铃》镜 1）

### 二、内容位置要量，而且**要量对区域**

三个测量命令量的是**三个不同区域**，不能互相替代：

| 命令 | 量什么区域 | 什么时候跑 | 性质 |
|---|---|---|---|
| `probe` | 整张图 / 整条字幕带，从头量到尾 | `prep` 之后（自动） | 定位问题，**报警常是误报** |
| `trace` | 镜头**真正经过**的那一段 | 出图之后，渲染之前 | 判一张图能不能用 |
| `measure` | 渲染出来的**无字 master** | `a`+`b` 之后 | 成片阶段最终验 |

`probe` 能发现两类错误：落幅摇进无特征区域（镜头在里面走等于没走）、
字幕压在读不出的底上。**但它量整张图，而镜头只经过其中一段，所以会误报**：

- 曾报"字幕列偏暗、最暗 75"，实际暗的是图顶那片夜空，字幕全程走在 149~193
- 《清平调》报右侧被石绿披帛占了，实际字幕只扫过原图 y 0.415~0.676，够不到
- 落幅：规则说的是**落幅那一帧**，`probe` 报的却是整张图的平坦行。
  《清平调》镜 11 看着完全不能落幅，实测落幅帧整帧极差 103、平坦行 0/16

**这两次如果只有 `probe`，都会去换掉本来完全没问题的图。**

所以跑完 `prep` 一定要跑 `trace`。它按 zoompan 的取景窗公式
`src = (f - 1/(2z)) + (out/边长) × (1/z)` 反查每条字幕在它那一镜里
**实际扫过原图的哪一块**，以及**每一镜落幅那一帧**的平坦度。
缺图会自动跳过，所以出一张就能验一张，不用等图齐。

`trace` 打的扫过范围要取**并集**：上摇时落幅的框底在起幅框底之上，
打"起帧框顶→止帧框底"会把行程严重低估（实测有一镜印成 0.498→0.527，
实际扫过 0.083~0.700）。模板已经修好，自己改的时候别退回去。

**平坦行报警也要复核。** 漆黑的室内（船舱、夜戏）大多数行本来就是均匀的黑，
`trace` 会报"7/16 行几乎无明暗变化，会像静止"——但平坦行量的是**每一行内部的
横向变化**，抓不到缩放。推近镜里主体会变大，照样看得见。
复核办法：`a` 趟跑完抽这一镜的首尾帧比一比。（《雨霖铃》镜 11 就是误报）

### 三、trace 和 measure 要对得上——**但先确认两者建模同一条流水线**

`a`+`b` 跑完之后跑 `measure`，然后和 `trace` 的结果**逐条对一遍**。
两者量的是同一批位置（一个在原图上算、一个在成片上量），应该只差几级。

**对不上通常是运镜没走在你以为的位置上**，那比字幕糊了严重得多，
而且没有别的办法能发现它。这是这套工具唯一一处能自检运镜的地方。

**但在下结论之前，先确认 `pass_a` 里有没有 `trace` 没建模的滤镜。**
《雨霖铃》第一次跑完，measure 一律比 trace 低 5~31 级、且越亮差得越多
（比值稳定在 0.64~0.81）。看着完全像运镜出错。**不是。**
把 `pass_a` 的 `vignette` 关掉重渲同一帧，量到 119，而 trace 报 118——差 1 级。
是 trace 少算了暗角，而字幕带正好在右上角、落在暗角上。

模板里 `vig_factor()` 已经补上了：拿一张纯灰跑一遍 `VIGNETTE`、按画心归一，
改参数会自动跟着变。修完逐条差 0~5 级、两者都判同一句最差，才是该有的样子。

**这个坑有三只脚，《没有夏天的那一年》把另外两只都踩了。** 通用规律是：
`pass_a` / `pass_c` 每加一道影响亮度的滤镜，`trace` **和** `measure` 两边都得跟着补。

| 滤镜 | 加在哪一趟 | 要补的地方 | 不补的后果 |
|---|---|---|---|
| `vignette` | pass_a | `trace` 的 `vig_factor()` | measure 一律低 5~31 级，越亮差得越多 |
| scrim | **pass_c** | `trace` 的 `scrim_factor()` | trace 一律偏亮，字幕余量被低估（52 级 vs 真实 76 级） |
| scrim | **pass_c** | `measure` 抽帧后叠回 scrim | measure 一律偏亮（trace 166 / measure **192**，差 26 级） |

第三只脚最阴：`measure` 按规矩读的是无字的 `master.mp4`，而那是 **pass_b** 的产物，
scrim 是 pass_c 才叠的，所以它量到的是"没压过的底"。
scrim 和文字无关，所以抽帧之后 `overlay` 一次 `scrim.png` 就行，
不违反"必须量无字帧"那条。补完 trace 166 / measure 169，**差 3 级**。

**一个长期报假警的检查等于没有检查**，而这是唯一能自检运镜的地方，不能让它坏着。

### 三之补：`motion`——落幅平坦度对暗调图天生爱误报

`trace` 的落幅平坦度数的是"落幅那一帧有几行几乎没有明暗变化"。
对暗调实拍它**结构性地误报**：大片夜空、暗地面本来就是平的，
《没有夏天的那一年》里整帧极差 147~181 的四张好图照样报"会像静止"。

真正要紧的不是落幅那一帧长什么样，而是**这一镜从头走到尾画面变了多少**——
`motion` 命令量的就是这个：每镜渲出来的首尾帧平均绝对差，判据 ≥4 级
（亮度可觉察差约 2~3 级）。那四镜实测 11.0~18.1，全部是假警。

和 `measure` 之于 `probe` 是同一个关系：**筛子在源头上估，判据在流水线的真实输出上量。**

附带一条：`motion` 第一版把读不出的镜头（还在写、moov atom 没落盘）跳过之后
照样打印"全部都看得出来"，**又造了一个不会报警的检查**。
现在"没量到 = 不算通过"。凡是写检查，都要问一句：这一条在最坏情况下会不会静默放行。

### 四、字幕必须在真实成片上验，而且有两个陷阱

**陷阱一：`-ss` 放在 `-i` 前面是输入定位，会把帧的 PTS 重置为 0。**
`subtitles` 滤镜按 PTS 找字幕，于是每一张抽帧都去找 0 秒那一刻的字幕，
结果一个字都渲染不出来——而画面是正常的，很容易误判成字幕样式有问题。
正确做法：**先整片烧一版低码率预览，再从预览里抽帧**（`still` 就是这么做的）。

**陷阱二：要量字幕底的亮度，必须量无字的 `master.mp4`。**
在烧过字的帧上框出字幕区求极值，量到的是**字本身**，不是它压着的底——
每条字幕会整整齐齐报同一个数，看起来条条危险，其实一条都没问题。骗过一次。

判据：底离字色至少差 50 级，用 **1%/99% 分位数**不用绝对极值
（字幕框有四五万像素，一两笔浪尖或一颗星就能把 min 拉到很低）。
每条量**起、中、止**三次——摇镜会把字幕拖过明暗分界，只量中间会漏掉最差的时刻。

**看和量都要做。** `still` 会漏掉"勉强能认但很脏"，
`measure` 会漏掉"数值够但压在人脸、发丝、窗框上"。

### 画种不要替用户定——摆 2~3 个候选让他选

**画种是这条流水线里唯一一个既不可逆、又纯审美的决定。**

不可逆：运镜、字幕、调色、配乐切入点都能单独重跑，画种不能——
它一旦出了图就是十几张的成本，而且"留白还是留暗"这类要求事后补不回来。

纯审美：技能能判的只是**哪几种扛得住这个题材**（下面那张表）；
扛得住之后哪一种更对，是审美，不是判据。那是用户的决定，不是你的。

所以流程是：**按题材筛出 2~3 个扛得住的候选，每个写清楚它买到什么、代价是什么，
让用户挑。** 不要只报一个推荐项，也不要挑完就闷头出图。

| 题材 | 扛得住的候选（★ = 已验证过的画种） |
|---|---|
| 苍茫，写景写志（登高 / 观沧海） | ★水墨淡彩 · ★电影写实 · 南宋边角山水 |

### 候选池：还没验证过的画种（**极性是推测的，必须实测**）

上面那张「画种与极性」表里的每一行都是**量出来的**——某一支片子跑过
`trace` + `measure` 才写进去的。下面这些只是能用的方向，
**极性、调色、留白还是留暗全都是推测**，选了就必须先出样图实测，
交付时再把实测结果补进上面那张表。

| 画种 | 买到什么 | 代价 | 推测的底子 |
|---|---|---|---|
| **青绿山水**（千里江山图一路） | 石青石绿加泥金，装饰性极强而不俗；山河题材的天花板 | 只有昼景；人物极小，写人的词托不住 | 中高亮度彩底 → 大概率墨色字 |

1. **它买到什么** —— 这一首里哪一句因为它成立

   重彩压不住「无边落木」；实拍出不了留白）
3. **连带的硬要求** —— 字幕极性、底子要留白还是留暗、调色重手还是几乎不调

### 选定了也只是"候选定了"

**先出一张样图、跑 `trace` 实测，才算真的定了。** 理由见「画种与极性」那张表上面
那几条：极性和调色都是量出来的，不是按画种套的。《清平调》先入为主差点换掉好图，
《雨霖铃》照抄纸本的调色把中位数压成 0——两次都是"画种定了就以为参数也定了"。

出新画种（表里没有的）时，交付前**在上面那张表里加一行**：
已做过哪一支、正文字幕什么色、底子要求、调色用量。下一支才有得抄。

讲述模式同理，只是候选池不同（多数是电影写实或纪实摄影质感），
但"摆候选让用户选 + 样图实测才算定"这两条一样。

### 纸本 → 写实，一共要翻五处

| | 纸本（浅底墨字） | 暗调写实（白字） |
|---|---|---|
| 正文字幕 | 墨色 + 纸色浅晕描边 | 近白 + **不透明黑**描边 + 投影 |
| scrim | 关（浅底叠浅带像镜头上有指印） | 看实测定，多数时候也不需要 |
| 淡入淡出 | **白场** | **黑场** |
| vignette / 颗粒 | **一律不加**（纸自己有纹理，叠上去就是脏） | **都加**（vignette 还顺手把右上压暗一档） |
| 出图任务书 | 右侧**留白** | 右侧**留暗** |

最后一条最容易想反，而且最贵：**留白事后还能压，留暗不行。**
浅底上加白字要靠加 scrim 压暗，会把画面压脏；换极性又让其余部分消失。

### 白字版的暗区要求要给精确矩形

不要只说"右上留暗"。把十几镜的 zoompan 取景窗反查取并集，给出一个矩形。
《雨霖铃》给的是：**画宽 55%~95%、画高 10%~55%**，并写明这块里不能有
脸、灯笼、烛火、月亮、亮天、水面反光、浅色衣料、密集枝叶、任何镜面高光。

两处要单独交代：
- **唯一横移的那一镜**字幕扫过的横向范围宽一倍，暗区要从画面中线一直铺到右缘
- **有月亮的那一镜，月必须放画面左侧**——放右上正好落进字幕带，
  而「晓风残月」这种名句重出的代价最大

### 极性开关是对称的，别先入为主

`FLIP_SHOTS` 里放"极性和全局相反"的镜号。**先出图、量了再填。**
《清平调》十五张工笔重彩看着浓艳，实测字幕列 197~226，**零告警**，全程为空。
《雨霖铃》十四条最差 118（离白字 124 级），也是全程为空。
不要因为"这张看着亮/浓"就先改。

## 调色：判据是**量出来的直方图**，不是画种

旧版本这条写的是"一次生成的 AI 图几乎不要调"。**那只对浅底纸本成立。**

《雨霖铃》的生成器交回来的是**技术上欠曝**的片子：
平均亮度 15~19、中位数 8、六到七成面积在 16 以下、**全图最亮只有 133**（一处白都没有），
人脸落在 39~83——手机上开自动亮度就是一团深灰。
而照抄纸本那句 `eq=contrast=1.06:saturation=0.92` 实测把平均从 15.1 压到 8.9、
**中位数直接压成 0**。不是"几乎不调"，是负的。

正确做法分两步，顺序不能换：

```
colorlevels=rimax=0.58:gimax=0.58:bimax=0.58,   # 1. 白点 133 -> 用满动态范围
eq=gamma=1.25:contrast=1.02:saturation=0.94     # 2. 抬中间调，把脸救回来
```

实测结果：平均 41/47，中位数 27/26，最亮 232/237。
**连带收益**：`trace` 的落幅整帧极差从 68/72 涨到 126/134，运镜明显更看得出来。

所以流程是：**先出两张样图 → 量直方图 → 再定调色**，不要按画种套。
用量的：`mean / p50 / p90 / p99 / max`，以及"亮度 < 16 的面积占比"。

### 欠曝有两种，救法不一样（《没有夏天的那一年》）

上面那套 `colorlevels` + `gamma` 是针对**白点塌了**的片子（最亮只有 133，一处白都没有）。
但生成器还会交回另一种：**白点正常、分布极暗**——实测 max 248 / p99 136，
而 median 只有 14、p25 只有 1~8。这种图 `colorlevels` 无事可做，得换招：

- **加反差还是负的**（同一个坑）：`eq=contrast=1.04` 把 median 从 14 压到 **8**、
  p25 从 8 压到 2
- **`eq=gamma` 这次也不能用**：gamma=1.25 把 p1 从 1 抬到 **14**，
  黑位整个浮起来，火山那道黑山脊变成灰的，画面立刻显脏

要的是**只抬中间调、保住真黑**，所以用 `curves`：

```
curves=all='0/0 0.08/0.13 0.28/0.42 0.60/0.70 1/1',eq=saturation=0.98
```

实测 median 14→23、p75 29→47，而 **p1 仍是 0~1**。
连带收益一样：`trace` 的落幅整帧极差从 125/131 涨到 148/153。

**判断用哪一招看 max/p99**：白点塌了（max < 200）用 `colorlevels`；
白点在而中位极低用 `curves`。两种都不要加 contrast。

图库实拍是另一回事：多个摄影师的白平衡、反差、季节甚至黑白彩色都不一样，
**必须重手统一**，不做的话串起来就是 PPT 换页。

## 音乐：**先要长度，再倒推片长**

生成的配乐几乎**一定**自带一段弱前奏或爬坡。再叠一个长淡入，成片开头七八秒
基本是静音——对一支没有诵读、全靠音乐抓注意力的片子，这是致命的。

### 提示词管不住这件事（试过三轮）

- 第一轮写 `full ensemble at bar one`，成品 −20 LUFS 起、一路爬坡
- 第二轮把否定项全列了（no introduction / no build-up / no fade-in / no silence），
  还加了「把第零秒当作全曲最大段落的中间」，成品前 4 秒**仍然**是 −40 → −30 → −22
- 第三轮（《雨霖铃》）写死「至少 4 分 30 秒」，**拿回来 193.4s**

**mureka 的封顶实测是 180~245 秒之间随机，提示词管不住。**

### 所以片长要倒着从 180s 算

真正解决问题的是**切入余地 = 全曲 − 片长**：

- 《再别康桥》片长 164.8s、曲子 179.9s，只剩 **15.1s**，怎么挪都有要紧落点撞进谷里
- 《雨霖铃》故意把 103 字的词压到 137.6s，拿到 193.4s 时余地 **55.9s**，宽裕得多

**按最坏的 180s 规划片长。** 想要余地 ≥ 片长 0.6 倍（技能线）就得 ≤ 112s；
现实一点，控制在 **135~145s** 能拿到 40~60s 余地，够 maximin 挑。
提示词里仍然要争取时长（写「至少 4 分 30 秒」），但别指望它。
（mureka 提示词上限 **1024 字符**，超了在校验阶段就退回，不消耗额度。）

### 切入点用 maximin 选，不要用加权和

用 `ebur128` 量整首的瞬时响度曲线，扫遍所有可用切入点，按成片上真正要紧的
那几个窗口打分：情绪核心、每段收尾长留、成片中点、末句、诗文页、片尾淡出。

**目标函数是 maximin——最大化这些落点里最弱的那一个**，不是加权求和。
加权和会把开场分拉满、却把成片中点和末句推进曲子最弱处（《清平调》栽过）。
没有诵读的片子怕的不是平均值不够高，是某一处塌下去。

**开场可以故意不放进打分窗口**：片头镜前六七秒只有标题在走、一个字幕都没有，
曲子最弱的一段落在那儿反而合适。把开场让出来，剩下的落点才挑得动。

### 拿到曲子先翻一遍低谷，再决定要不要第二条候选

`pick` 选完之后，**把全曲 < −25 LUFS 的低谷段全列出来**，看它们落在哪：

- 《雨霖铃》全曲最低 −70.6，但在 191.1~193.4s——那只是**结尾的自然收尾**，
  不是中段 breakdown；另外只有两处 0.5 秒的浅坑在前奏里，49.5s 切入全避开。
  **判定为干净，第二条候选省了。**
- 《再别康桥》候选 A 在 121~130s 藏了 1.7s 近乎静音，只能弃用

**别盲发第二条候选。** 先量，量出来有中段 breakdown 再发。

音色好坏**量不出来**——挑候选时"这个编制更贴这个画种"是从乐器清单推的，
不是听出来的。多出一条备选、把最终选择权交回给用户，比自己拍板诚实。

淡入收到 0.8 秒左右——听不出是淡入，只避免硬切的瞬态爆音。

## 音效：增益不能写死 dB，要写目标响度

音乐管情绪的底，音效管"这一刻发生了什么"。四五个声音成本极低、质感差一截。

**先查内置音效库再生成。** ChatCut 的 sound-effects 库只有 35 条，
全是 UI / 转场 / 器械类，**没有任何自然环境声**——所以蝉、檐滴、桨、风这些
确实要 `submit_sound` 生成，但要先查过再说，别直接花额度。

### 三条硬规矩

1. **每一条都必须写死播放长度。** 让音效"放到自然结束"会互相盖掉，
   而混音本身是"成功"的、参数上完全看不出来
   （18 秒的秋风把后面的雁鸣整个埋掉，《声声慢》踩过）。
   一律 `-stream_loop -1` 进来再按长度裁。
   **生成时就要得比播放长度长**，这样实际不会循环、也就没有接缝。

2. **增益写成"目标响度"，让脚本按实测反算。**
   《雨霖铃》五条生成音效实测 −8.3 / −30.6 / −14.8 / −53.5 / −18.6，**跨度 45 dB**。
   同一个 −21 dB 加在蝉声上是刺耳，加在江风上是 −74 LUFS、等于没有。
   写死增益在这种素材上不可能对，错了还看不出来。
   模板里 `SFX` 第三列是目标 LUFS，`build_audio()` 算 `gain = 目标 − 实测`，
   并在需要提超过 +12 dB 时报警（说明素材本身太轻，底噪会一起上来）。

   目标怎么定：音乐实测响度 + `MUSIC_GAIN` = 音乐在混音里的位置，
   音效一律排在它下面 1~9 dB。动作声最近，环境底最远。

3. **判一条音效能不能用要分频段量，LUFS 会骗人。**
   《雨霖铃》的江风第一版 −53.5 LUFS，看着像生成失败。分频段量之后才明白：
   能量几乎全在 120 Hz 以下（<120Hz −45.2，120–2k −65.1，>2k −79.2），
   是**提示词自己要的** "a low-frequency bed, more felt than heard"，
   而 LUFS 的 K 加权对低频衰减极大——**仪表在说实话**。
   但成片发手机，手机喇叭 500 Hz 以下基本没响应，那条在目标平台上等于不存在。

   所以要量 `<120Hz / 120–2k / >2kHz` 三段，和一条正常的音效对照。
   重生成时在提示词里写死 "must be clearly audible on a small phone speaker,
   not a subsonic rumble"。
   （ElevenLabs SFX 提示词上限 **450 字符**，451 就会被打回，校验阶段退回不消耗额度。）

## 粒子层：加一处真运动，但方向必须自动验

全片是静止的画在被推拉，加一处真运动就换一个量级。由便宜到贵：
ffmpeg 合成的雨/落叶/星辉粒子层（纯滤镜，不用素材）→ 生成带 alpha 的前景元素做视差
→ 关键镜直接生成视频。

已经验过好使的三种：**残雨**（「骤雨初歇」，随字幕落下正好收干净）、
**落叶**（「冷落清秋节」）、**星辉**（「满载一船星辉」）。

### 必须知道的四件事

1. **方向。`crop` 的 y 是取景窗在源图上的位置**，源图第 S 行出现在画面第 (S−y) 行，
   所以 **y 递增 = 画面内容往上跑**。照抄 `t*v mod H`（递增）雨就是往上飘的。
   要往下必须让 y 从 H 递减到 0 再绕回。

   **这个错在系列里活了两支。** 因为它正好落在这条流水线验证习惯的盲区里：
   `still` 抽静帧逐张看是主要的目视关卡，而**单帧的雨丝就是一道竖线、没有方向**；
   参数表上 `t*v mod H` 也长得很正常。只有连续看才发现。
   所以模板里做成了 `make_fx()` 渲完**自动跑的量化检查** `_verify_fx_direction()`：
   雨用垂直互相关、叶用亮像素平均 y，位移为正 = 往下。
   **改完一定要拿旧的有 bug 的文件回归验一次**，确认它真的会报警。

2. **在成片上复验要用带符号帧差。** 绝对值帧差会把方向抹掉——一滴雨从 p 移到 p+k，
   `|f2−f1|` 在 p 和 p+k 两处都留能量，相邻两次帧差共享中间那份，
   相关峰恒定落在 0，看起来像"根本没在动"。带符号时 `d2(y) = d1(y−k)` 才成立。

3. **叠加层必须真的会结束。** 落叶从第 20 秒起冻在画面上一路挂到片尾，
   而它是"正确地"叠在每一帧上的，参数上完全看不出来。
   根不在 `overlay` 的 `eof_action`（加了没用），在上一级：给 `alphamerge` 当底的
   `color=` 源是**无限长**的，`alphamerge` 又默认 `repeatlast=1`。
   三处一起收紧：纯色源给定长 `d=`、`alphamerge` 加 `shortest=1:repeatlast=0`、
   `overlay` 加 `eof_action=pass:repeatlast=0`。

4. **柔边用拉伸不用模糊。** 点打在小图上再放大，每个点被双线性拉成一小团软光；
   用 `gblur` 会把 255 摊到二十几个像素上只剩十几级，星点变成灰疙瘩。

**起点要落在对的镜头里。** 星辉起点取早了 1.6 秒，星星就浮在大白天的河面上——
`check_fx` 只管"盖住那一句"，拦不住这个，是抽静帧才看得出来的那一类。
另外粒子层要叠在 scrim **之前**，否则右上那条压暗会把它一起压掉一档。

## 平台安全区（竖版，**真机验过**）

2026-08-13 用《声声慢》在真机上比过：抖音/小红书竖屏右侧的头像/赞/评论/分享
压在 **x 0.86~1.00、y 0.45~0.85**，顶部导航压在 y 0~0.09。
字幕在 x 0.758~0.932 这同一条竖带上，**所以列底是硬约束**。

**要往上移，不要往左移。** 往左移会挡住画面主体（写实版尤其不能挡脸），
而且连带要求素材的空白/暗带更宽——那是出图时就得定的事。

`SUB_TOP` 按**最长一列的字数**反算：`SUB_TOP + 最长列字数 × 字号 ≤ 864`。
- 7 字一列 → 420 够用
- 9 字一列 → 必须提到 270（420 会掉进操作栏）
- 8 字一列 → 290，上下各留约 80~120px

模板里 `check_safe()` 会验，并且带一个**回归自测**：把字幕放回真机上撞了的旧位置
（`SUB_TOP=700`），检查必须报警。
第一版曾把 `(x0,x1,y0,y1)` 按 `(x0,y0,x1,y1)` 解包，于是检查在确实撞了的位置上
一声不吭——**一个永远不报警的检查比没有检查更糟**，所以回归自测不能省。

诗文页竖排时，**右起第一列离操作栏最近**，整块的列心要左移（1080 画心是 540，
《雨霖铃》八列算下来只能到 500）。横排诗文页文字全在画心，只有顶部导航要看。

## 素材的分辨率是硬门槛

裁成目标比例之后，**短边至少是成片对应边的 1.5 倍**，2 倍以上才舒服。
竖版 1080×1920 的下限就是裁后 1440×2560。

低于这条线的代价是**运镜没法做**：941×1672 那一张（下限的 0.65 倍），
那一镜的行程只能从 30% 压到 11%，几乎不能动；而这是一支每镜要停十秒半的片子，
镜头一旦不动，十秒会显得非常长。

AI 生成时**务必显式指定尺寸**——很多工具默认出 1K，9:16 的 1K 只有约 1024×1820，
低于下限。要 4K（**2896×5152** 正好 9:16）。这一条被坑过两次。

### 第三次：**文件尺寸会骗人**（《青玉案》）

生成器封顶在 941×1672，于是把图**放大**到 2896×5152 再进项目。
文件上写着 2896×5152，任何只看像素尺寸的检查从此必然通过，
而细节还是 941 那么多——有效值是下限的 **0.65 倍**，最紧那一镜每个输出像素
只摊到 **0.59 个源像素**，成片会软。

**试过从像素上自动判"是不是放大的"，判不出来**，两条路都不行：

- 把图降到**恰好**原生尺寸再放大回来，量残差：结果 0.23~0.57 灰阶，
  而原生 4K 是 0.53~0.83——**一个量级，分不开**。
  放大器不是简单重采样（AI 超分会造出细节）时尤其如此
- 1:1 目视对比也不可靠：两张图的"软"可能只是画风、题材或光线不同。
  拿雾夜灯市和硬光工坊比"锐不锐"，比不出东西

唯一站得住的证据是**生成器吐出来的原始文件**（去它的生成目录看尺寸）。

所以这一条**只能靠记录，不能靠检测**：脚本里的 `SRC_NATIVE` 写生成器实际出的尺寸，
`check_resolution()` 按它折算有效短边，而不是读文件。

配套的 `pixels` 命令从每张源图裁 1:1 原始像素贴片拼一张，让你看一眼——
它是辅助，不是判据，理由见上面第二条。**和 `still` 之于字幕是同一个套路：
自动判不出来的，就做成必须看一眼的东西。**

## 渲染分四趟，改什么跑哪趟

| 趟 | 做什么 | 什么时候要重跑 |
|---|---|---|
| `prep` | 裁切 + 统一调色 → img01..N，并自动 `probe` | 换图、改调色、改裁切位 |
| `a` | 每张图做 Ken Burns（+ vignette）→ shots/ | 改运镜或改了 prep |
| `b` | xfade 溶解转场串成无字无声的 master.mp4 | 改镜头时长、转场或改了 a |
| `c` | 粒子 + 混音 + 归一 + 烧字幕 → 成片 | 改字幕、scrim、音乐、音效、粒子颜色 |

外加八个验证/工具命令：`check`（永远先跑它）、`trace`（缺图会跳过，出一张验一张）、
`pixels`（**出图之后**，1:1 原始像素贴片联系表，看素材有没有真细节）、
`motion`（**跑在 `a` 之后**，量每镜渲出来的首尾帧差，判运镜看不看得出来）、
`fx`（生成粒子层，自带方向自验）、`pick`（maximin 选音乐切入点）、
`still`（烧预览抽静帧，用眼睛看）、`measure`（量字幕底，用数字验）。

出图之后的三道，缺一道就会漏掉一类问题：
`check`（有效分辨率，**要先填 `SRC_NATIVE`**）→ `trace`（字幕底与落幅）→ `pixels`（真细节）。

**改了字幕只跑 `c`**——a/b 两趟不含任何文字和声音，重渲是纯浪费。
**改粒子颜色/浓度/方向只跑 `fx` + `c`。**

讲述模式多一趟 `sync`（量旁白实测时长→推整条时间轴），**排在 `check` 前面**；
而且它的 `SHOTS` 不写 `dur`，改了旁白或气口之后要从 `a` 重跑（每镜时长变了）。

## 出图和配乐往往不在这个会话里

不要假设当前会话有图像生成工具。实践中经常**根本没有**
（ChatCut 连接器只有 music / video / voice / sound），而配乐即使生成成功，
**下载接口也要用户的登录会话——Agent 直接取会 401**（实测确认过）。

**所以"写一份自包含的图片生成任务书交给用户"不是退路，它就是这条流水线的正常形态。**
任务书要能脱离本项目其他文件独立看懂，内容见 `references/sourcing.md`。
早点把它写出来、早点把生成和下载这两件需要用户动手的事说清楚，
比做到一半才发现要卡住强。

**样图出两张，一头一头把风格夹住**：先出全片情绪核心那一张（它定人物长相、
肤质、笔性，后面每一张都要把它当参考图传进去），再出**全片最满最亮、
字幕带留空最难的那一张**——它过了说明这套风格扛得住极端情况；
只用最简的那张确认，等于没确认。这两张过了再出其余的，一次成、零返工。

### 在 Codex 里跑这条流水线

- ChatCut 相关的技能在 Codex 里叫 `chatcut-plugin-basics`（不是 `-claude` 那个），
  配乐用 `music` 技能、音效和 TTS 用 `voice` 技能
- 需要结构化提问时 Codex 用 `ask_followup_questions`
- 生成任务一律 `submit_*` 拿 jobId，再用 `track_progress` 等；
  **非终态时不要忙轮询**，按它给的 `checkBackAfterSeconds` 睡一次再查一次
- 本地 `ffmpeg` / `ffprobe` 是这条流水线的主力，**成片就是本地合成的**，
  ChatCut 项目只用来生成音频素材

## 交付

成片规格：H.264 + AAC 48k 立体声，响度归一到 **−15 LUFS**（平台标准 −14~−16）。
封面单独出一张，同时用 `-disposition:v:1 attached_pic` 嵌进 mp4 做封面帧
（脚本没做这一步，`c` 跑完之后手动 remux 一次，`-c copy` 不重编码）。

交付时要**主动说**三件事：

- 哪几处是妥协的（素材达不到、音效在手机上会很轻、图文对应牵强）
- 哪几处做了跟原计划不同的决定，以及为什么
- 还留了什么可以改的口子（换某一张图只需要重跑哪几趟）

## 一条贯穿始终的纪律：看过再说

**永远不要根据文件名、alt 文本、搜索结果的描述或接口返回的元数据判断一张图是什么。**
在一个系列里，靠读缩略图上的编号选图，九张里错了三张——
下载回来一张是城堡、一张是红山茶花、一张是森林。而且尺寸校验全部通过，
因为下到的确实是那个 ID 的图，只是那个 ID 不是看中的那张。

正确做法：图多的时候先拼一张**联络表**（`hstack`/`vstack` 排成网格）核对
序号和画面对不对得上，再单独打开有具体风险的那几张看细节。
渲染完成后**抽静帧真正看一眼**——ffmpeg 退出码是 0 不等于画面是对的。

**但也要知道目视的盲区。** 静帧看不出粒子的运动方向、看不出运镜幅度够不够、
看不出音效会不会互相盖。这三类只能量。**看和量都要做，谁也替不了谁。**

## 还没做过的

按性价比排，下一支挑一两个试，不要一次全上：

1. **片尾一枚朱文印**。生成的图里禁止出现印章（生成出来是乱码），
   但**脚本自己画一枚**盖在落款下方是另一回事，是中国画收尾最认的符号
2. **正文逐字显**。诗文页的逐列显已经做过、效果好；正文逐字会牺牲可读性，
   建议做成开关而不是默认
3. **生成视频代替静帧**（Seedance / Kling）。「解释春风无限恨」那种镜头，
   花瓣真飘起来就是全片的高光——但成本和一致性风险都高，先做单镜试
4. **把 `make_h.py` 升级到和 `make_v.py` 同代**。横版模板目前缺
   `check_safe` / `vig_factor` / `FLIP_SHOTS` / 目标响度音效 / 粒子方向自验
