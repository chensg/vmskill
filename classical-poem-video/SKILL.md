# 静帧短片流水线

把一首古诗词、或者一个历史小故事，做成一支带运镜、字幕、配乐的短片。
成片由本地 ffmpeg 合成，横竖两种版式。

这条流水线的核心不是 ffmpeg 命令，而是**几件必须量出来、不能靠眼睛判断的事**。
凭感觉做出来的版本一定会在这几处翻车，而且往往要到成片才看得出来。
下面把"为什么"写清楚——理解了原因，遇到没写到的情况也能自己判断。

**每一条数字都是踩出来的，不是理论。** 括号里标了是在哪一支上踩的。

## 先选模式

| | **诗词模式** `make_v.py`（只做竖版） | **讲述模式** `make_story_v.py` / `make_story_h.py` |
|---|---|---|
| 做什么 | 一首诗，一句一镜，片尾竖排诗文页 | 一个历史小故事 / 冷知识，有旁白 |
| 时间轴由什么定 | 字数 × 0.45 + 1.8 的可读下限 | **旁白实测时长**（`sync` 量完自动推） |
| 字幕 | 竖排、右侧、楷体 | 横排、左下、黑体；`SUB_MODE` 定烧录还是外挂 SRT |
| 每镜停留 | 10~13s | 3~8s，12~16 镜 |
| 音频 | 音乐 + 音效 | 旁白 + 音乐**侧链躲闪** + 音效 |
| 最大的风险 | 字看不清 | **把推断说成史实** |

**两种模式共用的判据**（运镜行程的缩放约束、`probe`/`trace`/`measure` 三级实测、
平台安全区、调色、素材分辨率门槛、音乐时长与 maximin 切入点、四趟渲染）这里只留摘要，
细则按文末「按需读」那张表去翻 `references/`。讲述模式独有的那些（事实分级、旁白气口
与语速、横排字幕怎么避开操作栏、转场当叙事标点、侧链躲闪的数值）看 `references/storytelling.md`。

**故事片和荐书片在出图之前有两道门禁**，两个都要**人**点头，不是检查通过：

| | 门禁 | 怎么过 | 它拦住的是 |
|---|---|---|---|
| 一 | **讲述稿人工确认** | 把稿子交给用户读一遍 | 哪句是废话、哪个转折跳了、第三幕是不是在替读者下结论 |
| 二 | **只有字幕+声音的检查片** | `python make_story_*.py preview` 出片，交给用户听 | 旁白好不好听、断句与气口、字幕跟不跟得上、**片长** |

脚本里是 `GATE_SCRIPT_OK` / `GATE_PREVIEW_OK` 两个字符串，**留空就拦住 `budget`**
（出图前那一步）。写人话不写 `True`。第二道经常直接改数字 ——
《经度》段五按 `est` 排 138.0s，旁白实测回来 **130.5s**，差 7.5s；
有平台硬线时这个差额是致命的，而它只在这个窗口里看得见。
详见 `references/storytelling.md` 第〇节。

**旁白 TTS 有一套定死的配置，照抄别调参**（doubao / 渊博小叔 / storytelling /
emotionScale 3 / **不设 speedRatio**），加一条统一的 `performancePrompt` 再挑十来句
单独加写。"有 AI 味"九成是这几条没照做，尤其是「句尾略收不上扬」。
见 `references/storytelling.md` 第八节。

**交付物不只是成片。** 还要附一份 `发布文案.md` —— 各平台的标题、简介、关键词，
**复制粘贴就能用**。骨架 `python publish.py new 片名`，写完 `python publish.py check`
量标题在各平台被切在第几个字（同一句话小红书切在第 20 字、YouTube 能留到 100）。
最要紧的一条规矩：**标题不能剧透第三幕的反转**。见 `references/publishing.md`。

已跑通并交付的讲述片：《没有夏天的那一年》（1816 无夏之年 → 自行车，
13 镜 / 25 条旁白 / 113.97s / −15.1 LUFS）。它的完整配置就在 `make_story_v.py` 里。

**讲述模式有一个子型：荐书片**（介绍一本书 —— 简介 + 内容 + 评论 + 现实意义）。
机件全一样，但结构、片长、版权三处不同：三幕、165~185s、第三幕**只问
「这本书自己在问什么」**（外挂社会议题会把书盖住，踩过）、不用书封不用剧照。
见 `references/storytelling.md` 第七节。第一支：《吞下宇宙的男孩》（21 镜 / 180.1s）。

**讲述模式还有第二个子型：小说第一人称片**（让书里的一个角色自己把那段经历讲一遍，
**一本书连载多集，一集 600s ± 60**）。它和荐书片正好相反 —— 荐书片站在书外面，
这个站在书里面。机件仍然全一样，但**横版 + 外挂 SRT + 分幕 join**（走《经度》那条路）、
`MOTION` 默认翻成 `static`、**TTS 那套配置不能照抄**（讲述者的声音 ≠ 角色的声音），
另外多两张表：**人称合约**（谁在讲 / 何时讲 / 对谁讲 / 为什么现在讲）和
**忠实度分级**（原著 / 暗示 / 我加的）。版权上有一个极容易踩的坑：
**原著公版 ≠ 角色形象公版**（怪物的螺栓头是 1931 年环球影业的美术设计，至今在版权内）。
见 `references/storytelling.md` 第九节。**第一支还没跑完，那一节里标「待实测」的都别当数。**

## 三条轴：开工前定死，两种模式都适用

选完模式，还有三件事要先定。它们各自有默认值，**但每一条都会往回改前面的决定**
（片长、素材门槛、分镜方式），做到一半再改要重来，所以放在最前面。

| 轴 | 值 | 默认 | 改了会连带什么 |
|---|---|---|---|
| `MOTION` | `kenburns` / `static`，**可逐镜覆盖** | `kenburns` | 素材分辨率门槛、每镜停留、粒子层的价值 |
| `MUSIC_MODE` | `library` / `generated` / `public_domain` / `none` / **`song`** | `generated` | 片长怎么排、`pick` 挑什么、归一化策略、要不要附授权 |
| `IMG_SOURCE` | `generated` / `found` | `generated` | **分镜跟着图走还是图跟着分镜走**、要不要登记来源 |

三条都有对应的自检，`check` 会跑，而且都带**回归自测**（造一个错，检查必须报警）。

- 运动 → `references/visuals.md`「静帧模式」
- 配乐 → `references/music.md`（先要长度再倒推片长、maximin 切入点、公版那一路）；
  **`song` 是 MV**（用户给一条带演唱的成品歌），它改的东西最多，见 `references/mv.md`
- 素材来源 → `references/sourcing.md`「自己去找图」那一节

**这三条不要替用户默认。** 和画种一样，先问清楚；区别是它们没有画种那么不可逆，
所以问一句就够，不用摆候选。

## 必须量、不能看的事（摘要，细则 `references/measuring.md`）

凭感觉做出来的版本一定会在这几处翻车，而且往往要到成片才看得出来：

1. **运镜行程受缩放限制**。想让画面走过 `d` 比例的行程，必须 `z ≥ 1/(1-d)`
   （10% → 1.12、20% → 1.25、30% → 1.43）。不给足缩放就是原地微缩放，
   参数表上完全看不出来。`check_moves()` 会拦
2. **三级实测量的是三个不同区域**：`probe` 量整张图（报警常是误报）→ `trace` 量镜头
   **真正经过**的那一段（判图能不能用）→ `measure` 量渲出来的无字 master（成片终验）。
   跳过 `trace` 会去换掉本来没问题的图
3. **`trace` 和 `measure` 必须建模同一条流水线**。`pass_a`/`pass_b`/`pass_c` 每加一道
   影响亮度的滤镜（vignette、淡场、scrim），两边都要补；改了 `GRADE` / `VIGNETTE` /
   `SUB_MODE` / 裁切之后 `trace_pred.json` 就过期，`measure` 之前重跑 `trace`。
   对不上时先问「这支有没有运镜」，没有的话一定是建模问题
4. **字幕在真实成片上验**。抽帧先烧低码率预览再抽（`-ss` 放在 `-i` 前会让字幕消失）；
   量字幕底必须量无字的 `master.mp4`，用 1%/99% 分位，每条量起/中/止，离字色 ≥ 50 级

`motion` 量每镜首尾帧差：运镜镜 ≥ 4 级、静帧镜要真的不动。**看和量都要做** ——
`still` 会漏掉「勉强能认但很脏」，`measure` 会漏掉「数值够但压在人脸、发丝、窗框上」。

## 竖版平台安全区（真机验过）

抖音/小红书竖屏右侧的头像/赞/评论/分享压在 **x 0.86~1.00、y 0.45~0.85**
（1080×1920 上是 x 929~1080 / y 864~1632），顶部导航压在 y 0~0.09。
字幕要躲开它；**要往上移，不要往左移**（往左会挡住画面主体）。
`check_safe()` 会验，带回归自测。诗词竖排字幕按最长一列反算 `SUB_TOP` 见 `references/poem.md`。

## 渲染分四趟，改什么跑哪趟

| 趟 | 做什么 | 什么时候要重跑 |
|---|---|---|
| `prep` | 裁切 + 统一调色 → img01..N，并自动 `probe` | 换图、改调色、改裁切位 |
| `a` | 每张图做 Ken Burns（+ vignette）**或按 `MOTION` 出静帧** → shots/ | 改运镜、改 `MOTION` 或改了 prep |
| `b` | xfade 溶解转场串成无字无声的 master.mp4 | 改镜头时长、转场或改了 a |
| `c` | 粒子 + 混音 + 归一 + 烧字幕 → 成片 | 改字幕、scrim、音乐、音效、粒子颜色 |

外加十一个验证/工具命令：`check`（永远先跑它）、
`budget`（**出图之前**，按每镜的运动反推要多大的图，分档抄进任务书）、
`trace`（缺图会跳过，出一张验一张）、
`pixels`（**出图之后**，1:1 原始像素贴片联系表，看素材有没有真细节）、
`motion`（**跑在 `a` 之后**，量每镜首尾帧差；运镜镜要看得出动，静帧镜要真的不动）、
`fx`（生成粒子层，自带方向自验）、`pick`（maximin 选音乐切入点，并自动列低谷）、
`mquality`（**公版配乐必跑**，量底噪/带宽/声道/头尾静音）、
`credits`（导出素材来源表，用了找来的素材时是交付物）、
`still`（烧预览抽静帧，用眼睛看）、`measure`（量字幕底，用数字验）。

出图之后的三道，缺一道就会漏掉一类问题：
`check`（有效分辨率，**要先填 `SRC_NATIVE`**）→ `trace`（字幕底与落幅）→ `pixels`（真细节）。

**改了字幕只跑 `c`**——a/b 两趟不含任何文字和声音，重渲是纯浪费。
**改粒子颜色/浓度/方向只跑 `fx` + `c`。**

讲述模式多一趟 `sync`（量旁白实测时长→推整条时间轴），**排在 `check` 前面**；
而且它的 `SHOTS` 不写 `dur`，改了旁白或气口之后要从 `a` 重跑（每镜时长变了）。

### 讲述模式的中间件对账（`make_story_h.py` / `make_story_v.py`）

`prep` 每出一张 imgNN、`a` 每出一个 shotNN 都记一笔「按什么输入做的」
（`prep_keys.json`、`shots/shotNN.key`），下游用之前先对账，对不上就停：

- **`a` 只补过期的镜**，默认多路并行（`JOBS`，四核开 3 路）。`a 1` 串行看进度，
  `a force` 全部重渲。所以"改了什么跑哪趟"不用再自己算 —— 改完跑 `a`，它自己知道补哪几镜。
- **`a` 拒绝开渲**：imgNN 不是按现在的 `CLIPS` 做的（插过镜、改过裁切/调色、换过图、
  prep 那一镜缺图跳过了）。以前这是"插入点之后整体错一格、每镜单看都正常"。
- **`b` 拒绝拼**：shot 没渲、渲到一半被打断（残文件）、参数或镜长变了没重跑 `a`。
- **不带参数不再等于 `all`**，只打印用法。`all` 要明说。
- `credits` 重写 `素材来源.md` 前会先对指纹，被手改过的**先备份成 `.bak-时间戳`**。
  手写的处理说明仍然另立一份（`素材处理说明.md`）。
- 交付物目录看起来像片库根（底下有两个以上带 `素材/` 或 `build/` 的子目录）时直接停 ——
  脚本错放在项目根、`../素材` 又恰好存在（`ani/素材/` 就是）时，`..` 就是 `ani/`。

回归：`python tests/test_intermediates.py`（仓库根，逐条把被检查的东西弄坏、验它报警）。

## 图从哪儿来：任务书 or 自己找

`IMG_SOURCE` 两个值，选哪个**改的是流水线的方向**：

| | `generated`（默认） | `found` |
|---|---|---|
| 做法 | 写一份自包含的出图任务书交给用户去生成 | 从公版开放数据、图库里找现成的 |
| 方向 | **图跟着分镜走**——"右侧留白"这类硬要求提得出来 | **分镜跟着图走**——一张宋画的留白位置改不了 |
| 主要工作量 | 写提示词、保持风格统一 | 检索、核对、定裁切（`zoom`/`cx`/`cy`） |
| 字幕极性 | 全局定一个，`FLIP_SHOTS` 通常为空 | **多半要一镜一议**，`FLIP_SHOTS` 会真的用上 |
| 分辨率 | 生成时按 `budget` 分档逐镜写 | 常卡在 pp 1.0 上下——**这正是静帧模式的用处** |
| 交付 | 无第三方权利 | **每张登记来源与授权**，`check` 会拦，`credits` 导出 |

具体怎么找、去哪儿找、怎么核对，见 `references/sourcing.md`。
两条容易想反的：

- **`found` 不是省事的那一条。** 省掉的是等出图，换来的是检索和核对，
  而核对那一步有个已经踩过的坑：**永远不要根据文件名、alt 文本或搜索结果的描述
  判断一张图是什么**（见「看过再说」那一节）。
- **"公有领域"是对**作品**说的，不一定对**这一张翻拍/这一次录音**成立。**
  和配乐那条是同一个道理。填不出 `CREDITS` 的五项就是还没查清楚。

## 出图和配乐往往不在这个会话里

不要假设当前会话有图像生成工具（ChatCut 连接器只有 music / video / voice / sound），
配乐的下载接口也要用户的登录会话（Agent 直接取会 401）。
**所以「写一份自包含的出图任务书交给用户」不是退路，它就是这条流水线的正常形态。**
任务书里的尺寸一律来自 `budget`，逐镜（或逐档）写；样图出两张把风格夹住
（情绪核心那张 + 最满最亮、字幕带最难留空那张）。细则在 `references/sourcing.md` 末尾。
在 Codex 里跑，先读 `references/codex.md`。

## 双语音轨（摘要，细则 `references/bilingual.md`）

`LANGS = ["zh", "en"]`：一条画面 + 中英两条音轨 + 两份 SRT。横版（`make_story_h.py` +
`join.py`）和竖版（`make_story_v.py`）都做。

- **时间轴归中文**。英文用 `langfit` 逐句压进中文量出来的槽（atempo 上限 ×1.06），
  压不进去的**不压**，报出这一句还得砍几个词。英文稿是配音改写，不是翻译
- **竖版要先 `SUB_MODE = "srt"`** —— 烧录字幕 + 多语言会让中文字跟着英文轨一起播，
  `check_mode()` 直接拦。竖版顺序：先 `vofit` 定死中文，再 `langfit`
- **上传件单音轨**（视频 + 中文），附加语言是独立 m4a，在 Studio 里加。
  多音轨文件直接传上去，英文轨会被静默丢掉

## 交付

成片规格：H.264 + AAC 48k 立体声，响度归一到 **−15 LUFS**（平台标准 −14~−16）。
双语片的**上传件是单音轨**（视频 + 中文）+ 每种附加语言一个独立音频
（`*_音轨_eng.m4a`，在 Studio 里添加）+ 一个两条轨都在的留档件 ——
**多音轨文件直接传上去，英文轨会被静默丢掉**（横版由 `join.py` 拆，竖版由 `c` 拆）。
字幕中英各一份外挂 SRT，发布文案多一块 `## YouTube (EN)`。
**封面双语片每种语言各一张**（`cover` / `cover en`，同一张图版只换文字；
跑完会自己量文字底下的对比度，判据和正文字幕同一条 —— 离字色 50 级）。
注意 YouTube 的多语言**不覆盖缩略图**，一个视频只有一张，另一张是给别处用的。
封面同时用 `-disposition:v:1 attached_pic` 嵌进 mp4 做封面帧
（脚本没做这一步，`c` 跑完之后手动 remux 一次，`-c copy` 不重编码）。

**用了找来的素材（图或音乐）时，`credits` 导出的素材来源表是交付物的一部分**，
不是附赠——CC-BY 要求署名，而署名要跟着片子走（发布时贴进简介，必要时进片尾）。

交付时要**主动说**三件事：

- 哪几处是妥协的（素材达不到、音效在手机上会很轻、图文对应牵强）
- 哪几处做了跟原计划不同的决定，以及为什么
- 还留了什么可以改的口子（换某一张图只需要重跑哪几趟）

三条轴的取值也要**明说**，不要让它默默生效：这一支是运镜还是静帧（混用的话哪几镜）、
配乐是生成/公版/没有、图是生成的还是找来的。
**"没有背景音乐"和"完全没有音轨"尤其要说**——它们看起来像做漏了。

## 一条贯穿始终的纪律：看过再说

**永远不要根据文件名、alt 文本、搜索结果的描述或接口返回的元数据判断一张图是什么。**
在一个系列里，靠读缩略图上的编号选图，九张里错了三张——
下载回来一张是城堡、一张是红山茶花、一张是森林。而且尺寸校验全部通过，
因为下到的确实是那个 ID 的图，只是那个 ID 不是看中的那张。

正确做法：图多的时候先拼一张**联络表**（`hstack`/`vstack` 排成网格）核对
序号和画面对不对得上，再单独打开有具体风险的那几张看细节。
渲染完成后**抽静帧真正看一眼**——ffmpeg 退出码是 0 不等于画面是对的。

**但也要知道目视的盲区。** 静帧看不出粒子的运动方向、看不出运镜幅度够不够、
看不出音效会不会互相盖。这三类只能量。**看和量都要做，谁也替不了谁。**
