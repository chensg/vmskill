# 双语音轨：细则

> 2026-11-11 从 `storytelling.md` 第十节原样挪出（节内小标题不变，别处写的「第十节」指的就是这份）。

## 十、双语音轨：一条画面，两条音轨（YouTube 多语言音轨）

**适用**：横版讲述长片、小说第一人称连载（`make_story_h.py` + `join.py`），
以及**竖版讲述片**（`make_story_v.py`，2026-08-31 打开，见第九小节）。

竖版原来写的是"不做"，理由是"抖音小红书必须烧字，烧了就不能多音轨"。
**那个理由只对烧录字幕的平台成立**，不是竖版本身的性质 —— 竖版发 YouTube Shorts
时字幕可以外挂、音轨可以多条。所以竖版的双语开关不是"做不做"，而是
**先把 `SUB_MODE` 切到 `"srt"`**。

仍然成立的是那句话的后半截：**烧录字幕 + 多语言是自相矛盾的配置** ——
烧进画面的中文字会跟着英文轨一起播，而你手上放的是中文版，永远发现不了。
所以竖版脚本里 `check_mode()` 直接拦下这个组合，`check` 每次跑它的回归自测。

### 〇、一句话推出全部设计

YouTube 的多语言音轨，画面只有一份、**每种语言一条独立音频**。三条推论：

1. **时间轴归中文所有。** 英文旁白必须塞进中文量出来的槽里。反过来让画面迁就英文，
   两条轨就成了两支片子 —— "多音轨"这三个字本身就没有意义了。
2. **正文字幕一律外挂**，中英各一份 SRT。这是横版本来就有的做法，
   到了双语它从"一个选择"变成"一条硬约束"。
3. **音乐和音效是同一床，侧链按各自的旁白算。** 英文的停顿位置和中文不一样，
   拿中文的包络去躲英文，音乐会在英文正在说话的地方抬起来。

### 一、流程：在原来的序列里插两步

```
（英文稿写完，英文 TTS 生成完，放进 vo_en/）
python make_story_h.py langfit      # 新增：逐句把英文压进中文的槽
python make_story_h.py preview en   # 新增（可选但强烈建议）：单听英文那条
python make_story_h.py check        # 会多出一段「英文轨逐句对槽」
python make_story_h.py c            # 一条画面 + 两条音轨 + 两份 SRT
```

`LANGS = ["zh"]` 时上面这些全部不发生，流水线和以前一模一样 ——
**单语片子不用为双语付任何代价**，这是加这个功能时的硬要求。

### 二、槽：每一句能给英文多少空间

槽 = **中文那一条的实测时长** + **可借的静默**。

可借的静默有一条例外，而它是这一节最要紧的一句：

> **镜末那一句借不到东西。** 镜末的静默正中骑着转场（理由见 `make_story_h.py`
> 的 `timeline()`）。借了就是把话说到转场底下去 —— 而这件事在参数表上看不出来、
> 在波形上看不出来，要放出来听才发现。

镜内的句子可以从后面那段气口里借，但**最多借一半**（`LANG_BORROW = 0.30`）：
剩下的一半是气口本身，把气口借光了，英文那条轨会变成连珠炮。

> 0.30 这个数是**定的，不是量的**。第一支英文片做完要听一遍：借满 0.30 的那几句
> 听起来赶不赶。赶就往下调。

### 三、压：逐句 atempo，压不进去就不压

`langfit` 逐句算倍率，上限 `LANG_TEMPO_MAX = 1.06`。

**为什么是逐句，不是整条一个倍率**（竖版 `vofit` 那样）：`vofit` 解决的是
"整片超硬线"，全片同一个倍率听不出来。这里解决的是"这一句和画面对不上"——
各句超出的比例天差地别。拿全片平均倍率去压，短句被无谓地拉快、长句照样压不进去，
**而且两头都听得出来**。

**为什么上限比 `vofit` 的 1.08 更紧**：整片拉伸是均匀的，耳朵几秒就适应了；
逐句拉伸是**忽快忽慢**的，一句 1.08 紧跟着一句 1.00，落差比绝对速度更显。
> 1.06 同样是**推测**。第一支英文片上要专门听那几条压到上限的句子。

超过上限**不压**，报出这一句还得砍几个词，并把文件**放回原速**——
不是留着上一次压的结果。留着的话，磁盘上的状态取决于你跑过几次，不可复现。

```
!! 1 条压不进去（超过 ×1.06 就不压了）：
   VO_09c      槽 5.62s，现在 6.90s，要 ×1.228 才塞得下 —— **还得砍约 6 个词**
   别把这活交给 atempo：听得出来的毛病换看不出来的错位，不是修好。
   要改的是英文稿，中文那条轨和画面一个字都不用动。
```

"还得砍几个词"用的语速：`EN_RATE` 填了就用它，**没填就用本批实测**。
这比填一个通行值靠谱 —— 英文播报语速取决于音色、emotion 和 performancePrompt，
和中文的 `EST_RATE` 是同一类数，不是常数。

> **`EN_RATE = None` 是有意留空的。** 第一支英文片跑完 `langfit`，
> 它会把实测的词/秒打出来，那时候再回填。**不要照抄网上的 150 wpm。**

### 四、英文稿是"配音改写"，不是翻译

这一条决定了上面那套机器好不好用。**逐句直译一定会长出去**：中文一个字
携带的信息多，同一句话英文平均要长一到三成。

所以写英文稿时按**槽**写，不是按中文句子写：

- 先看 `check` 打出来的那张「英文轨逐句对槽」表，知道每句有多少秒
- 长出去的那几句，**改写**而不是压 —— 换一个更短的说法，同一个意思
- 中文里的成语、四字格、语序倒装，直译过去既长又平，重写一遍
- 专名（人名地名书名）英文常常更长，**它们是砍不动的**，砍旁边的修饰

### 五、字幕：两份 SRT，起点一样，收尾各自

英文 SRT 的**起点和中文完全一样**（槽是中文定的），只有收尾跟着英文音频走 ——
英文那句短一点，字幕就早一点收。文件名：`段一.srt` / `段一.en.srt`，
`join.py` 按文件后缀合并成 `全片.srt` / `全片.en.srt`。

英文一行的字数上限 `SUB_MAX_CHARS_EN = 42`（中文是 20 个全角字，英文按半角算
大约是它的两倍）。断行符还是 `｜`，手工断，不交给自动换行。

### 六、两处会静默出错的地方（这一节真正的价值）

**一、改了翻译、重新生成、忘了跑 `langfit`。**
英文音频长出槽去不会报错、不会崩、波形上也看不出来，只会让那句话说到转场底下去 ——
而你手上放的是中文版，一切正常。
所以 `check_langs()` **每次 check 都从磁盘上的英文文件重新量一遍**，
不是复述 `langfit` 当时的结论。这是唯一拦得住它的地方。

**二、`concat` 默认只留一条音轨。**
ffmpeg 不给 `-map` 时按"每种类型挑最好的一条"选流。两条音轨的段用文件拼完
**只剩一条**，而且返回码是 0、能播、时长对、中文轨也对 —— 只有英文轨没了。
`join.py` 因此显式 `-map 0`，并且**自测里先把这个危险演一遍**
（跑同一条命令去掉 `-map 0`，验证它真的会丢轨），再验加上之后留住了。

同一个形状的第三处：**逐轨归一**。两条轨的说话密度和静默比例不同，整合响度天生不同。
拿其中一条的测量值去归另一条，两条轨就差出一个固定的台阶 ——
而观众正是在**切换音轨的那一刻**听见它。所以 `pass_c` 和 `join.normalize`
都是逐条量、逐条归到同一个目标；`join` 的接缝检查也逐条判台阶。

### 六之二、**上传形态：不能直接传多音轨文件**（2026-08-31 更正）

这一节原来写的是"一条视频 + N 条音轨"，**那个前提是错的**。
YouTube 的多语言音轨**不是**从上传文件里读第二条轨的：
上传的 MP4 里多余的音轨会被忽略，附加语言要在 **Studio 里作为独立音频文件**添加。

音频本身没错，错的是交付形态。所以 `join.py` 拼完之后自动拆三样（全部流拷贝）：

| 文件 | 是什么 | 干什么用 |
|---|---|---|
| `全片.mp4` | 视频 + **默认语言**一条轨 | **这个才是上传件** |
| `全片_音轨_eng.m4a` | 每种附加语言一个独立音频 | 在 Studio 里逐个添加 |
| `全片_多音轨.mp4` | 所有语言在一个文件里 | 留档 / 支持多轨的场合 |

**不拆的后果是不报错的**：多音轨文件传上去能播、时长对、中文轨也对，
只有英文轨没了——而文件本身完全正常。所以 join 拆完会验两件：
上传件是不是只剩默认那条、独立音频和画面是不是等长（差 0.05s 以上就报警，
因为独立音频差一点点就是整条错位，而这在文件里看不出来）。

### 七、交付物

比单语片多三样：

| | 文件 | 说明 |
|---|---|---|
| 上传件 | `全片.mp4` | 视频 + **默认语言一条轨**。多音轨文件不能直接传 |
| 附加语言 | `全片_音轨_eng.m4a` | 每种一个，在 Studio 里添加；和画面等长 |
| 留档 | `全片_多音轨.mp4` | 两条轨都在，给支持多轨的场合 |
| 字幕 | `全片.srt` + `全片.en.srt` | 外挂，两份 |
| 文案 | `发布文案.md` | 多一块 `## YouTube (EN)`，`publish.py check` 默认要求它 |

上传 YouTube 时音轨语言不用手点 —— 元数据在文件里。**没写元数据的样子是
两条轨都叫"未定"**，看不出是谁丢的，所以 `join` 拼完会再验一次音轨和段用文件对得上。

简介里要说一句**怎么切音轨**：多数观众不知道 YouTube 有这个菜单。

### 八、还没实测的（第一支英文片跑完回来改）

1. `EN_RATE` —— 留空的，`langfit` 会打出本批实测值
2. `LANG_TEMPO_MAX = 1.06` 和 `LANG_BORROW = 0.30` —— 定的，不是量的
3. **英文 TTS 的配置**：音色、emotion、`performancePrompt`。
   中文那套（豆包 / 渊博小叔 / storytelling / emotionScale 3）**不能照搬** ——
   第八节那套"去 AI 味"的提示词是按中文的句读和语气词写的。
   英文要重新试，并且**和中文一样，拿本集最难的一段试，不是最好听的一段**
4. `YouTube (EN)` 在 feed 里切在第几个字符 —— 表里填的 70 是估的，`limits` 会标星号

### 九、竖版这一路（`make_story_v.py`）：先定 `SUB_MODE`，再谈双语

竖版比横版多一条轴 —— **字幕烧进画面还是外挂**。它在开工前就要定死，
因为它决定了这支片子能不能有第二条音轨：

| `SUB_MODE` | 字幕 | 能几条音轨 | 发哪儿 |
|---|---|---|---|
| `"burn"`（默认） | 烧进画面 | **只能一条** | 抖音 / 小红书 / 视频号 —— 那些平台没有外挂字幕 |
| `"srt"` | 外挂 SRT，播放器渲染 | 多条 | **YouTube Shorts**（外挂字幕 + 多语言音轨都支持） |

**两种形态的画面是同一份**（`master.mp4` 一模一样），只有 `c` 那一步不同。
所以"抖音版 + YouTube 版"两支片子只要改这一个常数、重跑 `c`：
不用重出图、不用重渲运镜、不用重新对轴。这是这条设计最实用的一点。

判据跟着换：烧录按**像素宽**判一行放不放得下（字号是我们定的），
外挂按**字数**判（`SUB_MAX_CHARS = 20`，播放器的字号我们管不着）。

#### 命令序列

```bash
# 中文那条照旧：sync -> （有硬线就 vofit）-> check
python make_story_v.py vofit        # **先定死中文**：它会把所有的槽改短
python make_story_v.py langfit      # 再压英文（顺序反了，langfit 的结果会被 vofit 作废）
python make_story_v.py preview en   # 单听英文那条，这时候图还没出，改稿最便宜
python make_story_v.py check        # 多两段：check_mode（形态×语言）+ 英文轨逐句对槽
python make_story_v.py c            # 一次出四样，见下
python make_story_v.py srt          # 只改了文案时跑它，不用重渲
```

**`vofit` 在 `langfit` 之前**，这是竖版独有的一条顺序 —— 横版没有硬线、没有 vofit。
反过来做不报错：英文文件还在、长度也没变，只是槽变短了，它们现在长出去了。
`vofit` 跑完会自己提醒一句，`check` 会从磁盘重量一遍拦住。

#### 交付物（多音轨时 `c` 一次出四样）

| 文件 | 是什么 | 干什么用 |
|---|---|---|
| `成片_竖版.mp4` | 视频 + **中文一条轨** | **这个才是上传件** |
| `成片_竖版_音轨_eng.m4a` | 英文独立音频，和画面等长 | 在 Studio 里作为附加语言添加 |
| `成片_竖版.srt` / `.en.srt` | 两份外挂字幕 | 跟着片子一起传 |
| `成片_竖版_多音轨.mp4` | 两条轨都在 | 留档，**不要传这个** |

拆分和横版 `join.py` 同一个道理、同一套验证：拆完验上传件只剩默认那条、
独立音频与画面等长（差 0.05s 以上直接报错，因为差一点点就是整条错位，
而这在文件里看不出来）。多音轨文件传上去只会保留第一条轨，其余静默丢掉。

#### 一支片子发两个平台时

抖音/小红书那一版（`SUB_MODE="burn"`，`LANGS=["zh"]`）和 YouTube Shorts 那一版
（`SUB_MODE="srt"`，`LANGS=["zh","en"]`）**是同一条画面的两次 `c`**。
先渲哪个都行，但**成片文件会互相覆盖**（文件名一样）—— 渲第二版之前
把第一版挪走或改 `OUT_NAME`。
