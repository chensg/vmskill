# 配乐：公版 / 开放授权这一路

> 2026-11-11 从 `music.md` 原样挪出（小标题不变）。

## 二、公版 / 开放授权

### 唯一必须先说清楚的一条：录音权和作品权是两回事

**贝多芬 1808 年写的曲子是公有领域；某乐团 2010 年演奏这首曲子的录音不是。**

这是这条路上最常见、也最贵的错误，因为它在流水线上完全不会被拦：
成片正常、审核正常、发布正常，要到被投诉、被静音、被下架才知道。

所以判断顺序是：

1. **先看这一份录音文件本身的授权声明**（CC0 / CC-BY / PD dedication / 明确的许可）
2. 拿不到明确声明的，**不要靠"作曲家去世多少年"去推**——那管的是作品，不管录音
3. 公版的判定还**因地区而异**（录音的保护期各地不同），按发布平台所在地看；
   拿不准就换一条有明确 CC0/CC-BY 声明的，比研究保护期便宜得多

`MUSIC_CREDIT` 五项（作品 / 演奏 / 来源 / 授权 / 链接）填不出来，
就说明这条录音的授权还没查清楚——`check` 会直接拦下。这不是形式主义，
是把"我以为它是公版"这个念头逼成一句要写下来的话。

### 去哪儿找

**各站的条款逐件看、而且会变**，下面只是常去的地方，不是"这里的都能用"：

| | 有什么 | 注意 |
|---|---|---|
| **Musopen** | 古典曲目的录音与乐谱，不少是 PD/CC0 | 也混着 CC-BY 的，逐条看 |
| **IMSLP** | 以乐谱为主，也有录音 | **逐文件授权不同**，乐谱公版≠录音公版 |
| **Free Music Archive** | 现代创作，逐曲 CC 授权 | 多为 CC-BY，要署名 |
| **archive.org** | 极杂，含大量历史转录（78 转唱片一类） | 逐件看权利声明；老转录底噪重 |
| **Wikimedia Commons** | 音频文件，逐文件授权 | 同上 |

中文古乐（古琴、琵琶）的公版录音**不好找**：多数数字化项目只授权在线试听、
不授权二次使用。这一条是判断，不是实测——真要走这条路，逐件读条款。

**"免版税"（royalty-free）不等于"公版"。** 免版税是一种商业授权，
往往仍有署名、平台、用途的限制。它可以用，但那时 `MUSIC_CREDIT` 里
`license` 要写清楚是哪一份授权，不能写"公有领域"。

### 拿到之后先跑 `mquality`

生成的曲子交回来是干净的：单一来源、现代采样率、没有底噪。
找来的录音不是，而它坏在三处，三处都不是听一耳朵能确定、却都能量：

```bash
python make_v.py mquality
```

它量四样：

1. **底噪** —— 用全曲**最安静的那一刻**当底噪的上界，和整合响度比。
   历史转录带着一层持续嘶声，而片子里音乐要压到 −25 dB 左右，
   嘶声跟着被听见，**在最安静的镜头里最明显**——正好是诗词片最要紧的地方。
   **已实测校准**（库里 19 条生成配乐）：17 条落在 **40~56 dB**，
   两条明显偏低（**20.3** 和 **25.3** dB）。所以 >40 dB 是生成配乐的常态，
   **<30 dB 要单独听一遍**——那两条不一定是坏，但它们的安静段里有东西。
2. **带宽** —— 分四段量 RMS（<120 / 120–2k / 2k–8k / >8k）。
   **分频段一律用 RMS 不用 LUFS**：K 加权会把低频衰掉，
   这个坑在音效上踩过（一条 −53.5 LUFS 的"江风"其实能量全在 120Hz 以下）；
   在老录音上它换个方向出现——高频没了，整体 LUFS 却可能很正常。
   `>8k` 相对全带低 40 dB 以上，基本就是老转录：不刺耳，但和现代生成的音效
   放在一起会显得"蒙"，而且**它自己盖不住自己的嘶声**。
3. **声道** —— 把左右相减看差信号。单声道不是毛病，知道就行。
4. **头尾静音** —— 抓轨常带 1~3 秒引子静音。`MUSIC_IN` 是按曲子内容算的，
   前面多一段静音会把切入点整体推偏。

### 一首不够长时：**在本地合成一条音乐床，不要改脚本**

脚本只吃**一个** `MUSIC` 文件，而且 `check` 要求 `MUSIC_IN + 片长 ≤ 曲长`。
找来的曲子常常只有 2~4 分钟，长片单首必然不够。

**做法：把两首合成一条覆盖全片的床，当单文件喂进去。** 脚本一行不用改，
而且换曲点、静默段、响度配平三件事全部握在自己手里。

《白衣女人》第二集（片长 520.1s，曲 A 218.8s + 曲 B 229.8s）：

```
曲A loudnorm→ 取 0~175s，末 8s 淡出
静默 53.6s
曲B loudnorm→ +2.1dB → 取 0~229.4s，末 8s 淡出
静默 63.5s
```

**两条必须做的事：**

1. **响度要二次配平。** 两首原始 −12.6 / −16.7 LUFS，各自 `loudnorm=I=-16` 之后
   **仍差 2.1 dB**（实测 −13.7 / −15.8）——`loudnorm` 单遍只收了一半。
   不补这 2.1 dB，换曲点会听见一个台阶。**量完再补，别信 loudnorm 的标称值。**
2. **静默段是设计，不是没凑够。** 让音乐在每一幕的落点之前先退掉，
   落点落在静默里。第二集两处静默各自盖住幕二落点和全片落点，
   而音乐在反派进门那一刻回来 —— **换曲点本身成了一个事件**。

合成步骤要抄进 `MUSIC_CREDIT` 的注释里。半年后没人记得这条床是怎么来的，
而它不在任何一个下载目录里。

#### 三首以上：共同电平**由顶余量最小的那条说了算**

上面那条「两首要补 2.1 dB」在多首时要改写法。不要先定一个目标再逐条去够 ——
够不到的那条会削顶，而 `loudnorm` 一遍下来**不报错**。

先量每一条的整合响度 `I` 和真峰值 `TP`，共同电平取

```
LUFS = min( I + (TP_MAX - TP) )      # TP_MAX 一般 -1.0
```

谁的顶余量最小谁说了算，然后**全部用线性增益**打到这个电平
（这些是已经压过的成品音乐，要的只是对齐电平，不要再过一次动态处理）。
床整体低了多少，就在段上的 `MUSIC_GAIN` 里补回来。

《莫森》六条实测 −15.7~−20.4 / TP −0.7~−8.5，原想定 −15.5，
断言拦下：**M3 要加 2.6 dB，真峰值会撞到 0.0**。最后定 −16.37，`MUSIC_GAIN` 从 −12.5 补到 −11.5。

#### 分段片子：**一段一条床，长度等于段长**

脚本的音乐链是 `atrim(MUSIC_IN, MUSIC_IN+total)` 再 `afade` 头尾，
也就是**铺满整段**。片子要是「音乐是标点」（几处定点进出、有几处刻意无乐），
就给**每一段**预混一条**正好段长**的床，音乐摆在该响的秒数上、其余全是静音，
`MUSIC_IN = 0`。

这么做比把音乐当音效塞进去好，理由只有一条但很硬：
**侧链躲闪只作用在 `MUSIC` 这一路上**。音乐走 `SFX` 就不会躲旁白，
而定点音乐落的地方往往正好有话。

两处要对齐的细节：

- 脚本在 `total-3` 处**强制淡出**。所以让最后一个乐句**收在段末**是合算的 ——
  那 3 秒淡出正好当它的收尾；反过来，别让一个乐句**跨过段界**，
  它会在段末被淡掉、又在下一段头上以全电平重新进来。
- 幕界和段界不一定重合。先把每一幕的镜号换算成**段内秒数**再摆床，
  别拿全片秒数去摆。

### 量音频不要用 `-v error`，也不要 `head` 掉 Summary

同一天在同一条床上量错两次，两次都差点当成"合成失败"：

- **`volumedetect` 写在 info 级**，`-v error` 会把它整个吞掉，输出是空的
- **`ebur128` 每 0.1s 打一行瞬时值**，`head -3` 抓到的是文件开头那几帧
  （`I: -70.0` 那种），**不是整条的积分值**。要 `grep -A5 Summary`

两次的表现都是"读出来是静音"，而文件一直是好的。
**量之前先确认自己量的是哪个数。**

**第三次（同一天）：门限是按上一支的场景定的。**
验成片开场的出声点时用了 `RMS > -30dB` 当"旁白出声"的判据——
那是在**没有背景音乐**的集一上定的门限。集二有音乐床，
**音乐在 0.6s 就已经到 −15dB**，于是量到的是音乐，报出"旁白压在淡入上"的假警
（实际 SRT 首条 1.400s，旁白 1.50s 出声，完全正常）。

> **有音乐的片子不要用电平门限去找旁白落点。**
> 旁白落点看 **SRT 首条起点 + 0.10s**（`timeline()` 里字幕比声音早 0.10s），
> 那是时间轴算出来的，不受混音影响。

三次错的共同点是同一个：**判据是按上一个场景定的，场景变了没跟着改。**

### 切入点：多一个候选，而且最终要听

`pick` 在公版模式下会打**两个**候选：

- **maximin 的解**——最大化要紧落点里最弱的那一个（和生成模式一样）
- **让曲子的自然收束正好落在片尾**（`MUSIC_IN = 全曲 − 片长`）

**真曲子有终止式，这是它和生成的环境乐最大的区别。** 观众听得出
"曲子结束了"和"曲子被淡出掐掉了"的差别。所以两个候选的最弱落点
差在 **2 dB 以内就选后者**——让曲子有结尾比多两分贝值钱。

**乐句边界量不出来。** 和"音色贴不贴"是同一类事：
`pick` 只会挑响度，挑不出"这一刀切在了乐句中间"。切入点定完必须听首尾。

### 一条纪律：这条演奏好不好，Agent 判不了

Agent 听不见声音。挑候选时"这个编制更贴这个画种"是从乐器清单推的，
不是听出来的；一条老录音"有味道"还是"就是糊"，量不出来。

**所以公版配乐一律给 2~3 条候选、附上 `mquality` 的实测数据，
把最终选择交回用户。** 这和已经写在本篇「音乐：先要长度」里的"多出一条备选、
把最终选择权交回给用户，比自己拍板诚实"是同一条。
