# 配乐：生成 / 公版 / 不要

脚本里的 `MUSIC_MODE` 有三个值，选哪个是**开工前的决定**，不是做到一半再改的事——
它决定片长怎么排、`pick` 挑什么、以及交付时要不要附一张来源表。

> 2026-11-11：公版那一路挪到 `music-public-domain.md`，不要背景音乐挪到 `music-none.md`，
> 选了那个值再去读。这份留的是：查库、生成、本机生成、片长倒推与切入点、音效。

> **这一篇里标了「实测」的数字来自已交付的片子；标了「推测」的还没有一支片子验过。**
> 跑完一支回来把推测换成实测，这是这个仓库一贯的规矩。

| | `library` | `generated` | `public_domain` | `none` |
|---|---|---|---|---|
| 哪来的 | **素材库里已有的** | ChatCut `submit_music` | 自己找的公版录音 | 没有 |
| 成本 | **零** | 一次额度 | 零（但要查授权） | 零 |
| 长度 | 库里是多少就是多少 | **实测封顶 180~245s 随机**，管不住 | 通常远长于片长 | — |
| 主要风险 | **同系列重复用** | 前奏爬坡、中段 breakdown | **授权判错**、底噪 | 片子撑不住 |
| 交付时 | 无第三方权利 | 无第三方权利 | **必须附来源与授权** | 说明这是有意的 |
| 额外要跑 | `music_index.py find` + `pick` | `pick` | `pick` + `mquality` + `credits` | — |

**对音乐要求不高的片子（书评、故事、冷知识、科普）一律先走 `library`。**
这类片子全程有旁白盖着，音乐只在句间的缝里露出来，"贴不贴"的余地很大。
详见下面「零、先查库」。

## 零、先查库（`MUSIC_MODE = "library"`）

```bash
python music_index.py find --dur 160 --mode story
```

库在 `ani/_素材库/{music,sfx}/`（环境变量 `VMSKILL_LIB` 可覆盖）。
**不在 git 仓库里**：配乐实测 188MB，进 git 会把每次 clone 和两处安装同步都拖垮。
代价是库只在这台机器上；索引里存了提示词，丢了能重生成。

### 库里一大半是「落选的候选」

做一支片子通常生成 2~3 条候选，最后只用一条。**落选的那些付过费、量过、
结构完全可用**，只是当时那一支挑了别的。首批收编 19 条配乐里就有 5 条从没用过。

### `find` 的判据

硬条件只有一条：**全曲 ≥ 片长**。其余都只标注不淘汰：

- **余地 = 全曲 − 片长**。推荐 ≥ 片长的 0.6 倍（诗片）/ 0.4 倍（讲述片），
  不够的标「余地紧」。**不要拿它当硬门槛**——第一版这么做了，
  160s 的片子要求全曲 ≥224s，19 条里只剩 3 条，等于把库废掉一多半。
- **躲不开的谷**：片子可以从 `[0, 余地]` 里任何一点切入，所以曲上时刻 v 的谷，
  只有当 `v ≥ 余地` 且 `v ≤ 片长` 时才是**每个切入点都会撞上**的硬伤。
  在这之外的换个切入点就躲开了。
  第一版按"不在前奏、不在末尾"数，那是和片长无关的粗筛，会把
  "从 0 秒切入就永远够不到"的收尾谷也算成缺陷，把好曲子排到后面。
- **前奏**：曲子进入正常体量（中位响度 −3dB 以内）的时刻。`MUSIC_IN` 至少要躲开它。
- **用过哪几支**：`find` 会打出来。**同一个系列里不要重复用同一条，观众记得住。**
  用 `--exclude-used <系列名>` 直接排掉。

### 定了之后要回去记一笔

```bash
python music_index.py add <mp3> --used "《XXX》"
```

不记的话下一支查库时不知道它已经用过了。脚本里 `MUSIC_FROM_LIBRARY` 填库里的
文件名，`check` 会拦空值——就是为了逼出这一步。

### 什么时候**不要**查库

**诗词片多半要新生成。** 没有旁白时音乐是唯一的音源，而且配器要跟着画种走
（英式水彩配大提琴、工笔重彩配琵琶），复用等于把上一支的气质搬过来。
但**落选候选值得先翻一遍**——同一个画种做第二支时，上一支的候选 B 常常正合适。

## 一、生成（默认）

已经写在本篇「音乐：先要长度」那一节，这里只重复最要紧的两条：

- **片长要倒着从 180s 算。** 真正解决问题的是"切入余地 = 全曲 − 片长"。
  实测：一支片长 164.8s 的只剩 15.1s 余地，怎么挪都有要紧落点撞进谷里；
  另一支压到 137.6s、拿到 193.4s 的曲子，余地 55.9s，宽裕得多。
- **切入点用 maximin，不要用加权和。** 加权和会把开场分拉满、
  却把成片中点和末句推进曲子最弱处。

`pick` 现在会自动把用到的那一段里 **< −25 LUFS 的谷全列出来**，
并说清每一处落在哪一镜。以前这是句手工提醒（"拿到曲子先翻一遍低谷"），
而手工翻要看几百行响度采样，翻漏是必然的。判读方法没变：

- 落在**片尾淡出**里的不算问题（那是曲子自然的收尾）
- 落在正片里的**中段 breakdown** 才是该发第二条候选的理由

## 一·五、本机生成：YuE2 配乐、Stable Audio 3 音效（2026-10-21 起，有 3090 时可选）

走 `comfy_gen.py`（和出图同一个 ComfyUI），不花额度、不用下载页。**图、影片、放大、配乐、音效同一时间只跑一类。**

```
python comfy_gen.py music 配乐_片名 --style "Instrumental, warm solo piano, slow and gentle, ... no vocals" [--secs 200]
python comfy_gen.py sfx 浪 "Gentle ocean waves lapping against a concrete breakwater" --secs 8 [--kind SFX|One-shot] [--enhance]
```

**配乐（YuE2-3B，ComfyUI 原生 int8）默认是纯音乐**，照官方 yue2-music 技能的纯音乐流程分三步：
① YuE2 按风格＋曲式标签写谱（ABC，有 Vocal 和 Ins 两个声部）→ ② 官方 `instrumental.py run --prepare-only`
把 Vocal 的音符全挪到 Ins（纯 CPU，要装 yue2-music 技能）→ ③ 按改好的谱生成。给 `--lyrics-file` 就是带人声的歌。
产出 `素材/配乐/<名>.mp3`（另留 .flac 和 `_yue2_<名>/` 里的原谱、转换后的谱），进片照 `MUSIC_MODE="generated"` 写 `MUSIC`。

- **实测（2026-10-21）**：写谱＋生成 141 秒独奏钢琴，**一共 55 秒**（含换模型加载），峰值 331W / 57°C。
- **长度由谱的段落数定，`--secs` 只是上限**：缺省 8 个曲式标签出了 141 秒。
  `--plan N` 能多给标签，**但写谱的模型常常不照着写完**（2026-10-22《寒席》：给 10 段，四个种子只写了 2~5 段，
  出 75 / 112 / 90 / 130 秒）。**要加长就改谱**：挑一版旋律完整的，把它 `_yue2_<名>/plan.abc` 里的 `% verse` `% chorus`
  两段在谱里再抄一遍（前奏、尾声不动），用 `--abc 改好的谱.abc --seed <原种子> --secs 240` 重生成——调性、配器都接得上。
  那次 130 秒的四段谱（3/4 拍、降 E）重复主副歌后出 **212.6 秒**，每 5 秒响度 −19~−25 LUFS 没断，185 秒后进尾声渐弱。
- **没有耳朵时的两道客观检查**：每 5 秒短时响度（中段掉到 −35 LUFS 以下＝断了）；ElevenLabs scribe 转写
  （转出词＝混进了人声；纯音乐只会给「[outro jingle]」这类标签）。**仍然要人听。**
- 授权：权重 CC BY-NC 4.0，作者另给**个人用户、内容创作者**变现许可（不收费、不分成，署名可选，鼓励写 YuE2）；
  公司商用要另找作者。`publish.py check` 发现用了 YuE2 而说明里没写会提示（不拦）。

**音效（Stable Audio 3 Medium）**：`--kind` 选 SFX / One-shot / Music / Instrument；8 秒海浪 20 秒出完。
`--enhance` 先让 Qwen3.5-2B 改写提示词（要那个 4.5GB 文本编码器）；不加就把 LLM 支路从图里剪掉。
- 授权：Stability AI Community License —— 年收入 <100 万美元免费商用；**商用前要在 Stability AI 登记（用户自己做）**；
  发布处显著写「**Powered by Stability AI**」。`publish.py check` 读 comfy_log：用了 Stable Audio 而说明里没有这句就拦。
- 原有的 ElevenLabs / ChatCut 音效仍可用；本机的好处是不用下载、能批量。

**官方 YuE2 运行时**（`D:\yue2_runtime\.venv`，Python 3.12＋torch 2.10 cu128＋yue2-infer 0.1.5，模型在 `D:\yue2_runtime\models`）：
yue2-music 技能的翻唱、改谱、换词、ABC 编辑这些 ComfyUI 做不了的用它。它要 20GB 空闲显存、24GB 空闲内存 —— **跑它之前先
`comfy_gen.py free` 或关掉 ComfyUI**。Windows 上官方的 `setup_runtime.py install` 会从 PyPI 装到纯 CPU 版 torch，
要自己建环境：`uv venv --python 3.12`（uv 0.13 在 Windows 建版本链接有 bug，设 `UV_PYTHON_INSTALL_DIR` 到 D 盘就绕过）
→ 从 `download.pytorch.org/whl/cu128` 装 `torch==2.10.0` → 再装 `requirements-inference.txt`。
仓库要用 `core.eol=lf` 检出，否则 `verify_bundle.py` 因 CRLF 报「Missing/corrupt bundled file」。
**Windows 还要打一个补丁**：Windows 版 torch 没编译 FlashAttention，而 yue2/cuda_graph.py 的 `auto` 只看算子在不在就选 flash，
一生成就报「USE_FLASH_ATTENTION was not enabled for build」。跑一次 `scripts/yue2_patch_windows.py`（用运行时的 python；
可重复执行），让它改看 `torch.backends.cuda.is_flash_attention_available()`，自动落到 cuDNN 注意力。
打完后官方示例：44 秒生成 33 秒音频，`instrumental.py verify` 通过（10-21）。

## 音乐：**先要长度，再倒推片长**

`MUSIC_MODE` 四个值。下面这一整节写的是 `generated`；
其余三个的取舍、判据和陷阱在 **`references/music.md`**，这里留必须记住的几句：

- **`library`（从素材库挑一条已有的）—— 对音乐要求不高的片子先走这一条。**
  书评、故事、冷知识、科普：全程有旁白盖着，音乐只在句间的缝里露出来，
  库里现成的多半够用，而生成一条要花额度、封顶还是 180~245s 随机不可控。

  ```bash
  python music_index.py find --dur 160 --mode story
  ```

  库在 `ani/_素材库/`，**不在 git 仓库里**（配乐 188MB）。
  首批收编了 19 条配乐 + 14 条音效，其中 **5 条配乐是从没用过的落选候选**——
  做一支片子通常生成 2~3 条只用一条，落选的那些付过费、量过、结构完全可用。

  **诗词片多半仍要新生成**：没有旁白时音乐是唯一的音源，配器还要跟着画种走。
  但落选候选值得先翻一遍——同一个画种做第二支时，上一支的候选 B 常常正合适。

  用完**一定要回去 `music_index.py add --used` 记一笔**，否则下一支不知道它用过了；
  **同一个系列里重复用同一条，观众记得住**。脚本里 `MUSIC_FROM_LIBRARY` 不填 `check` 会拦。

- **`public_domain`（自己找公版）——录音权和作品权是两回事。**
  贝多芬的曲子是公版，某乐团 2010 年的录音不是。这个错在流水线上完全不会被拦，
  要到被投诉才知道，所以 `MUSIC_CREDIT` 五项填不全 `check` 直接不让过。
  拿到之后先跑 `mquality` 量底噪、带宽、声道、头尾静音。
- **`none`（不要背景音乐）——它会改归一化策略，不是少做一步。**
  `loudnorm` 的整合响度带门限，静音段会被剔掉；只剩稀疏音效时，
  归一化会把一层本该若有若无的蝉声硬抬到 −15 LUFS，
  把 SFX 表里逐条写的目标响度全部作废。所以脚本在"只有音效"时**不归一**；
  什么音源都没有时**不产出静音轨**（静音轨会被归一化放大成一片底噪），
  直接出一条无音轨的 mp4，并在 `check` 和 `pass_c` 两处明说。

生成的配乐几乎**一定**自带一段弱前奏或爬坡。再叠一个长淡入，成片开头七八秒
基本是静音——对一支没有诵读、全靠音乐抓注意力的片子，这是致命的。

### 提示词管不住这件事（试过三轮）

- 第一轮写 `full ensemble at bar one`，成品 −20 LUFS 起、一路爬坡
- 第二轮把否定项全列了（no introduction / no build-up / no fade-in / no silence），
  还加了「把第零秒当作全曲最大段落的中间」，成品前 4 秒**仍然**是 −40 → −30 → −22
- 第三轮（《雨霖铃》）写死「至少 4 分 30 秒」，**拿回来 193.4s**

**mureka 的实测范围是 109~245 秒之间随机，提示词管不住。**

下限那个 109s 是《虞美人》踩出来的：同样写死「至少 4 分 30 秒」，拿回 **109.1s**，
比此前记录的下限还低 71 秒。**所以"按最坏的 180s 规划片长"这条以前的建议偏乐观了。**
它的直接后果：93.1s 的片子只剩 16.0s 余地（0.17 倍），
而曲上两处谷相距 59.4s < 片长，**扫遍所有切入点都躲不开**——
这正是"余地不够就怎么挪都撞"的教科书案例。

### 所以片长要倒着从 180s 算

真正解决问题的是**切入余地 = 全曲 − 片长**：

- 《再别康桥》片长 164.8s、曲子 179.9s，只剩 **15.1s**，怎么挪都有要紧落点撞进谷里
- 《雨霖铃》故意把 103 字的词压到 137.6s，拿到 193.4s 时余地 **55.9s**，宽裕得多

**没法靠规划片长来保证余地** —— 拿回 109s 时，除非片子短到 68s 才有 0.6 倍余地，
而那对多数词都不现实。所以真正的做法是**拿到曲子先跑 `pick` 看躲不躲得开**：
谷少而浅就用（《虞美人》两处 0.6/0.7s、降 14~17 dB，接受了），
有中段 breakdown 或长静音才重发。片长仍然别排太长（135~145s 是个好区间），
但要知道那只是提高概率，不是保证。
提示词里仍然要争取时长（写「至少 4 分 30 秒」），但别指望它。
（mureka 提示词上限 **1024 字符**，超了在校验阶段就退回，不消耗额度。）

### 切入点用 maximin 选，不要用加权和

用 `ebur128` 量整首的瞬时响度曲线，扫遍所有可用切入点，按成片上真正要紧的
那几个窗口打分：情绪核心、每段收尾长留、成片中点、末句、诗文页、片尾淡出。

**目标函数是 maximin——最大化这些落点里最弱的那一个**，不是加权求和。
加权和会把开场分拉满、却把成片中点和末句推进曲子最弱处（《清平调》栽过）。
没有诵读的片子怕的不是平均值不够高，是某一处塌下去。

**开场可以故意不放进打分窗口**：片头镜前六七秒只有标题在走、一个字幕都没有，
曲子最弱的一段落在那儿反而合适。把开场让出来，剩下的落点才挑得动。

### 拿到曲子先翻一遍低谷，再决定要不要第二条候选

**`pick` 现在会自动列。** 以前这是句手工提醒，而手工翻要看几百行响度采样，
翻漏是必然的。它把用到的那一段里 < −25 LUFS 的谷全打出来，
并说清每一处落在片上的哪一镜。判读方法没变：

- 《雨霖铃》全曲最低 −70.6，但在 191.1~193.4s——那只是**结尾的自然收尾**，
  不是中段 breakdown；另外只有两处 0.5 秒的浅坑在前奏里，49.5s 切入全避开。
  **判定为干净，第二条候选省了。**
- 《再别康桥》候选 A 在 121~130s 藏了 1.7s 近乎静音，只能弃用

**别盲发第二条候选。** 先量，量出来有中段 breakdown 再发。

音色好坏**量不出来**——挑候选时"这个编制更贴这个画种"是从乐器清单推的，
不是听出来的。多出一条备选、把最终选择权交回给用户，比自己拍板诚实。

淡入收到 0.8 秒左右——听不出是淡入，只避免硬切的瞬态爆音。

## 音效：增益不能写死 dB，要写目标响度

音乐管情绪的底，音效管"这一刻发生了什么"。四五个声音成本极低、质感差一截。

**先查自己的素材库，再查 ChatCut 内置库，最后才生成。**

```bash
python sfx_index.py            # 自己的库：ani/_素材库/sfx，首批 14 条
```

自己的库里存的是 **mp3 + 提示词 + 分频段实测**，而**判一条音效能不能用必须分频段量**
（见下面第 3 条），量一次存下来就不用再量。首批 14 条已经覆盖了
水声 / 桨声 / 夏虫 / 晚钟 ×2 / 秋风 / 雁鸣 / 雨 / 寒蝉 / 檐滴 / 解缆 / 江风 / 晓风。

ChatCut 的 sound-effects 库只有 35 条，全是 UI / 转场 / 器械类，
**没有任何自然环境声**——所以新的自然声确实要 `submit_sound` 生成，
但先把两个库都查过再说，别直接花额度。生成完 `sfx_index.py add` 记进库。

### 三条硬规矩

1. **每一条都必须写死播放长度。** 让音效"放到自然结束"会互相盖掉，
   而混音本身是"成功"的、参数上完全看不出来
   （18 秒的秋风把后面的雁鸣整个埋掉，《声声慢》踩过）。
   一律 `-stream_loop -1` 进来再按长度裁。
   **生成时就要得比播放长度长**，这样实际不会循环、也就没有接缝。

2. **增益写成"目标响度"，让脚本按实测反算。**
   《雨霖铃》五条生成音效实测 −8.3 / −30.6 / −14.8 / −53.5 / −18.6，**跨度 45 dB**。
   同一个 −21 dB 加在蝉声上是刺耳，加在江风上是 −74 LUFS、等于没有。
   写死增益在这种素材上不可能对，错了还看不出来。
   模板里 `SFX` 第三列是目标 LUFS，`build_audio()` 算 `gain = 目标 − 实测`，
   并在需要提超过 +12 dB 时报警（说明素材本身太轻，底噪会一起上来）。

   目标怎么定：音乐实测响度 + `MUSIC_GAIN` = 音乐在混音里的位置，
   音效一律排在它下面 1~9 dB。动作声最近，环境底最远。

3. **判一条音效能不能用要分频段量，LUFS 会骗人。**
   《雨霖铃》的江风第一版 −53.5 LUFS，看着像生成失败。分频段量之后才明白：
   能量几乎全在 120 Hz 以下（<120Hz −45.2，120–2k −65.1，>2k −79.2），
   是**提示词自己要的** "a low-frequency bed, more felt than heard"，
   而 LUFS 的 K 加权对低频衰减极大——**仪表在说实话**。
   但成片发手机，手机喇叭 500 Hz 以下基本没响应，那条在目标平台上等于不存在。

   所以要量 `<120Hz / 120–2k / >2kHz` 三段，和一条正常的音效对照。
   重生成时在提示词里写死 "must be clearly audible on a small phone speaker,
   not a subsonic rumble"。
   （ElevenLabs SFX 提示词上限 **450 字符**，451 就会被打回，校验阶段退回不消耗额度。）
