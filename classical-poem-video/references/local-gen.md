# 本机生成（`comfy_gen.py`，2026-10-20 起有 3090 时的默认）

> 2026-11-11 从 `sourcing.md` 原样挪出（小标题不变）。

本机 ComfyUI 便携版在 `D:\MiniMax-H3`（双击 `Start-MiniMax-H3.cmd`，http://127.0.0.1:8188）。
同一份 `出图任务书.md`，换引擎不用改稿：图那张表沿用 ElevenLabs 那套格式，影片另起一张 ▶ 表。

| 用途 | 模型（授权） | 实测（RTX 3090，20 步/50 步） |
|---|---|---|
| 静帧 | Qwen-Image-2512（Apache-2.0） | 50 步 1664×928 约 3.5 分钟；4 步 Lightning 15~20 秒（冷启动首张约 70 秒）；中文字渲染正确 |

| 放大 | SeedVR2 3B Int8（Apache-2.0） | 768p 8 秒 → 1080 约 9 分钟，显存约 10GB；锐、帧间不闪 |

| 静帧（候选） | MOSS-Image SFT int8（Apache-2.0） | 1920×1088 50 步 75 秒；不守「不露脸」等禁令 → 只进候选（10-26，见下） |

## 流程

```
python comfy_gen.py start                 # 重启电脑后：后台拉起 ComfyUI（不弹浏览器）
python comfy_gen.py check                 # 服务、3090、功耗上限、温度、四份工作流节点号
python comfy_gen.py image --fast          # 4 步全出一遍 → 候选/<档名>/4s-<种子>.png（不进片）
python comfy_gen.py sheet --cand 06_x     # 看一张图的候选；`sheet` 看全部定稿
python comfy_gen.py image 06_x --fast --variants 4   # 一张不行就多出几个种子（一张 10 秒）
python comfy_gen.py promote 06_x 3        # 选定第 3 张转正成 06_x.png（日志记下步数和种子）
python comfy_gen.py image                 # 只给真正上屏的静帧出 50 步定稿
make_story_v.py vidplan write             # 旁白定了以后：影片秒数＝镜长＋余量，写回任务书 ▶ 表
python comfy_gen.py video --res 480       # 影片试稿；首帧图没出会自己补 4 步版；有硬切当场报
python comfy_gen.py strip 01_x            # 6 帧条＋切镜检测
python comfy_gen.py video 01_x --res 768  # 默认是 480p；768p 只给白天、细节多的关键镜（见下）
python comfy_gen.py upscale 01_x --seedvr2   # 关键镜
python comfy_gen.py upscale 05_z --lanczos   # 暗、烟雾、过场
python comfy_gen.py notes                 # 素材/生成/生成记录.md：每个成品怎么来的、显卡时间
```

每个批次开跑前按本项目日志报预计耗时，超过一小时提示放晚上跑。

进片：`CLIPS` 里写 `dict(video="生成/01_x_1080.mp4", ss=0, to="full")` —— **整段用，秒数只在任务书里有一份**
（2026-10-20 任务书和 `to=` 各写一份，手改了三轮）。`check_video` 仍按实际时长拦「比镜长短」「余量不足 0.5 秒」。
H3 把时长吸附到 24fps 的 17k+5 帧网格上，要 6 秒实得 6.58 秒（158 帧）。原声轨 prep 时丢掉（`-an`）。

**2026-10-20 第一次实跑（《我想回家》鏡1，竖版）**：
- 4 步快速图 70 秒（含冷启动加载）；50 步定稿 928×1664 **210 秒**。功耗峰值 332W、显存频率 8999MHz（红线正常）。
- 480p 图生 6 秒影片 **350 秒**（含换模型后的加载）；动作照做了（坐船舷→后仰翻身落水），
  但**落水的水花是一圈不自然的「皇冠」**，「镜头不动」也只做到大半（有缓慢推移）。
  → 动作句里别要求剧烈的物理（落水、爆炸、浪拍），给「慢、小、连续」的动作；要的话剪掉那半秒。
- **768p 比用户给的参考慢得多**：12 秒 **67 分钟**、11.5 秒 **60 分钟**（约 5.3 分钟/秒成片；参考是 8 秒 30 分钟）。
  480p：8 秒 6.7 分钟、11.5 秒 12 分钟、15 秒 18.5 分钟。→ 768p 只给开场/白天细节多的关键镜，
  暗的水下镜 480p 试稿直接放大就够（这一支 5 段影片只有 2 段上 768p）。
- **768p 值不值（10-21 盲比）**：同一镜 768p+SeedVR2 和 480p+SeedVR2 都放大到 1080，左右随机、答案封存，用户看完再揭。
  01（白天、船、山、细节多）用户选 768p；15（暗的水下）用户觉得 **480p 那版细节更丰富**。1:1，而 768p 贵 4~5 倍
  （12 秒 67 分钟 vs 480p 加放大约 26 分钟）→ `video` 默认改 480p，768p 点名才出。清晰度指标（拉普拉斯方差）
  被画面内容带偏，分不出高下，这类只能靠人眼盲比。**样本只有两对**，有新对照就更新这条。
  顺带：01 那段 768p 第 6 秒有一次 H3 自切，是盲比时用户看出来的（当时还没有自动切镜检测）。
- **15 秒的图生影片会自己切镜头**（《我想回家》镜20 第 3 秒从远景切成俯拍船尾）：要长镜头就别贴着 15 秒上限写，或改静帧。
- SeedVR2 480→1080（×2.2545 再裁）6.6 秒 **472 秒**（含加载）；同一帧 540×540 局部对比：
  SeedVR2 拉链、调节器、扣环清楚，lanczos 一片软。和用户给的结论一致。
长任务（影片 768p、整批 50 步）放晚上跑，`run_in_background` 交出去等通知。

## 放大选哪个（逐镜判断，`upscale` 必须点名）

- **SeedVR2**：主角特写、关键镜、开头/结尾、有文字或建筑线条的、封面截帧来源。
- **lanczos**：过场/空镜、快速运动、大片烟雾或黑暗（SeedVR2 也加不出东西）、试稿、赶时间。
- 拿不准：截一帧两种都放大并排看。EDSR（`upscale.py`）只给静态照片，逐帧跑视频会闪。
- **静帧要 4K**（大幅推近、4K 上传、封面要裁局部）：`upscale --image <档名|图片路径>`，默认 SeedVR2 到
  3840×2160（竖 2160×3840），`--to WxH` 改尺寸、`--lanczos` 换软的。**别让 Qwen 直出 4K**：训练约 1.6MP，
  超了会主体重复、构图散，显存也已经贴着 23.6GB。2026-10-22 实测（复杂场景 12+ 人、招牌、船）：
  1664×928 → 4K 一张 **11~20 秒、显存 7.3GB**；4K 下 100% 看，脸的毛孔发丝、招牌笔画、报纸、水面都比 lanczos 实，
  没见伪影；副作用是对比度/饱和度略升。比 CPU 上的 EDSR 快得多，也不会和 ComfyUI 抢内存。

## 硬件红线（脚本拦，别绕）

- 3090 是矿卡：Afterburner **功耗 90%（上限 333W）＋显存 −500**。`comfy_gen` 提交前查上限（> 336W 不交），
  跑的时候每 3 秒采一次：功耗 > 345W 或显存频率 > 9150MHz（−500 没生效时是 9500）就 `/interrupt` 退出。
  正常负载读数是 **331~333W / 8999MHz**（2026-10-20 实测）。
- 内存只有 32GB：**图、影片、放大不能同时跑**——**CPU 上的 EDSR（`upscale.py`）也算一类**：
  928×1664 一张吃 10GB 内存、400 秒（2026-10-20 和 Qwen 出图同时跑，ComfyUI 被整个换出到虚拟内存、
  HTTP 不响应，出图批次停在第 7 张，只能重启 ComfyUI）。生成图放大 1.16 倍这种量级直接交给 prep 的 lanczos，别上 EDSR。
  提交前队列必须空（界面上有人点了任务就等），
  换一类模型前 `POST /free`。虚拟内存固定 48~64GB（C 盘）。

## 工作流节点号会随 ComfyUI 升级变

`comfy/*.api.json` 是前端 `app.graphToPrompt()` 导出的 API 格式；脚本按节点号改参数，
`check` 会核对每个节点的 `class_type`，对不上就拦。重新导出（浏览器面板开 8188，执行一次 JS）：

```js
const srcs = {h3_t2v:'/api/userdata/workflows%2Fvideo_minimax_h3_t2v.json',
  h3_i2v:'/api/userdata/workflows%2Fvideo_minimax_h3_i2v.json',
  qwen2512:'/templates/image_qwen_Image_2512.json',
  seedvr2:'/templates/utility_seedvr2_3b_int8_upscale_video.json'};
for (const [k,u] of Object.entries(srcs)) { await app.loadGraphData(await (await fetch(u)).json());
  const p = (await app.graphToPrompt()).output;
  await fetch('/api/userdata/api%2F'+k+'.json?overwrite=true',{method:'POST',body:JSON.stringify(p,null,1)}); }
```

存到 `ComfyUI/user/default/api/`，拷进仓库 `scripts/comfy/<名>.api.json`，节点号变了就改 `comfy_gen.py` 的 `NODES`。

## Qwen-Image-2512 提示词的四个坑（2026-10-20《我想回家》，18 张图出了三轮）

1. **固定开头里的地点会进每一张。** 开头写「女川町的海边小镇与港湾」，结果医院窗外是海、水下镜顶上露出岸上的房子。
   固定开头只写画风、画幅、年代；地点写进各镜的画面句。
2. **固定结尾里的「或戴着潜水面镜」会给每个人戴上面镜**（医院里的老太太、岸边的男人都戴着）。
   道具只写在需要它的人物描述（`（潛水員）`）里，结尾只管「背影、不露正脸」。
3. **室内加窗的竖构图会被拼成 2~3 格**（06 医院、11 桌面、12 墓、18 床头两轮都分格，「不要分格」写在结尾里不管用）。
   改成近景，并写明「画面上半部是……下半部是……」，一轮就好。
4. **「完全在水下、看不到水面」50 步版仍常在顶上画出水面线和岸**（02、17 两轮都是），4 步 Lightning 版反而守得住。
   影片首帧用 4 步版没关系（H3 会重新渲染）；`--fast --seed N` 换几个种子挑一张，一张 10 秒。

**省时的出图顺序**：`image --fast` 全出一遍（每张 10~20 秒）看构图和道具 → 改任务书 → 再上 50 步。
这一支第一轮直接上 50 步，16 张里 8 张因为上面四条重出，白跑了约 30 分钟。

## 2026-10-26 新装的三个模型：同轮对照结论

用户 10-24/25 装了 MOSS-Image、MOSS-TTS v1.5、SANA-Video 2.0（另有本机网页 `D:\web`，http://127.0.0.1:8190，
图/影片/语音三合一，和 comfy_gen 共用 8188 的 ComfyUI——**两边别同时交任务**）。
用《海圖上找不到的島》的任务书、首帧和旁白做同轮对照（同提示词、同种子、同尺寸），素材在 `D:\ani\新模型试验_1026\`。
三个都是 Apache-2.0（SANA 用的 LTX-2.3 VAE 是 LTX-2 社区许可，年收入 <$1000 万免费；Gemma 编码器可商用）。

| | 结论 | 进技能 |
|---|---|---|
| **MOSS-Image SFT** int8 | 1920×1088 50 步 **75 秒**（Qwen-2512 281~346 秒）。质感像胶片剧照，手、刺青字「AS 1789」都对。**但不守禁令**：三镜里 2 镜露正/侧脸（遞椰子写了「只拍手」，它拍了两个人的侧脸；刺青拍成正脸），Qwen 1 镜半侧；Qwen 那张遞椰子有任务书明令禁止的石屋玻璃窗 | `image --engine moss`，**只进候选**、人挑过才转正；不当默认 |
| **MOSS-TTS v1.5** 8B | 克隆一段参考音逐条出：~2 倍实时（9 秒一条 20 秒，首次加载 80 秒）；不给语速时中文 3.8~4.4 字/秒（同稿豆包 4.0~5.0）。Whisper 核读六条：**无漏字增字**，差的全是同音写法 | `tts-ref` → `tts`，配 `el_tts.py asr --local`；**音色等用户听**（`旁白_moss.mp3` vs `旁白_doubao.mp3`），没定之前中文仍走豆包 |
| **SANA-Video 2.0** 5B 720p | **中文提示词读不懂**（四步版文生：要背影望船，出来是城市前的现代男模正脸）。英文才听得懂，但图生「抬手遮眉」时 0.8 秒内把背影翻成正脸；划艇那镜船往镜头划（应往岛划）。没有声音。720p 5 秒 50 步 9~9.5 分钟（≈110 秒/秒成片，H3 480p≈60、768p≈320） | **不进**。要用得先给英文动作句，且只适合无人物的空镜——还没测过 |

**MOSS-TTS 的用法要点**
- 没装 MOSS-VoiceGenerator，`VoiceDesign` 节点会报错。参考音用 `GenerateSpeech`＋音色描述出（`tts-ref`），
  **同一描述每次出来的音色不一样**，所以整片只认一段参考音（`素材/配音/参考音_zh.flac`）、每条都克隆它。
- 语速：`--cps 4.5` 按字数折成 `target_tokens`（12.5 帧/秒）。不给就由模型定，比豆包慢约 9%。
- 出完照旧：`el_tts.py asr zh --local`（本机 Whisper，不花 ElevenLabs 额度）→ `vo_trim.py apply` → `sync`。
- 授权 Apache-2.0，说明里不用署名。

**10-26 顺手修的**：ComfyUI 进程在跑 Qwen 第二张时无声消失（无崩溃事件、内存够、网页服务没杀它，原因不明）。
`submit` 旧版把「连接被拒」当「没响应」累计，45 秒就报「5 分钟没响应」；现在直接报「进程没了，start 再重跑」。
