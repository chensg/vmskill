# 讲述模式：把一个历史小故事做成短片

诗片和故事片共用同一条渲染流水线（prep / a / b / c、trace、measure、still），
但**开工前定的四件事有三件反过来了**，而且多出一件诗片完全没有的事。
这份文件只写差异——共用的部分看 `SKILL.md`。

| | 诗片 | 故事片 |
|---|---|---|
| 时间轴由什么决定 | 字数 × 0.45 + 1.8 的可读下限 | **旁白实测时长** |
| 字幕 | 竖排、右侧、楷体、一句一列 | **横排、左下、黑体、一句一屏** |
| 每镜停留 | 10~13s | **3~8s** |
| 音乐 | 唯一音源，推到 −9-ish | **侧链躲闪，让位给旁白** |
| 片尾 | 竖排诗文页 | 尾板（或干脆没有） |
| 最大的风险 | 字看不清 | **把推断说成史实** |

---

## 〇、出图之前的两道门禁（**故事片和荐书片都适用**）

**出图是整条流水线上最贵、最不可逆的一步；改稿是最便宜的一步。**
所以这两件事必须在出图之前由**人**确认过 —— 不是由检查通过，是由用户点头。

| | 门禁 | 怎么过 | 它拦住的是 |
|---|---|---|---|
| 一 | **讲述稿人工确认** | 把讲述稿交给用户读一遍 | 哪句是废话、哪个转折跳了、第三幕是不是在替读者下结论 |
| 二 | **只有字幕+声音的检查片** | `python make_story_*.py preview` 出片，交给用户听 | 旁白好不好听、断句与气口、字幕跟不跟得上、**片长** |

两个都在脚本里有位置，**留空就拦住 `budget`**（`budget` 是"出图前跑、把尺寸抄进
任务书"的那一步，也是最后一个还来得及改稿的位置）：

```python
GATE_SCRIPT_OK  = ""   # 讲述稿已人工确认 —— 写人话：谁看的、改了哪几处
GATE_PREVIEW_OK = ""   # 检查片已人工确认 —— 同上
```

**不给布尔开关**，理由和 `PP_ACCEPT_REASON` 一样：`True` 是无痕的，
半年后回看没人知道当时确认了什么。

### 为什么这两件事检查判不出来

第一道：`check_claims` 只管"有没有把推断说成史实"，管不了"好不好听"。
稿子的毛病全是数值判据够不着的那一类。

第二道更实在 —— **它经常直接改数字**。《经度》段五按 `est` 排出来 138.0s，
33 条旁白实测回来是 **130.5s，差 7.5s**。有平台硬线（YouTube Shorts 180s）时
这个差额是致命的，而它只有在旁白全部生成之后、出图之前的这个窗口里才看得见。

### `preview` 出来的是什么

深灰底 + 一条压暗的横带标出字幕位置，上面写着

```
镜 7 / 15   （镜7 / 镜8 共用一张图）   推近 z 1.16→1.32   9.1s
07_受难者版本.png
```

配真旁白、真字幕、真时间轴。**没有音效没有音乐** —— 这一版要验的是话说得对不对，
多铺一层会让人分神去听氛围（而且这时候音效多半还没找）。
真图到了直接替换同名文件，`CLIPS` / `SHOTS` / `NARR` 一个字都不用动。

实现上有一条讲究：**占位板上所有文字都走 ASS 当字幕烧，一个 `drawtext` 都不用。**
带 `drawtext` 的 ffmpeg 在 Git bash 下会 Fontconfig error + 段错误
（见 `references/codex.md`），而 `subtitles=`（libass）这条路整条流水线天天在跑。

### **但要说清楚这一版验不了什么，别让它冒充通过**

| 检查 | 对占位图 | 为什么 |
|---|---|---|
| `motion` | **结构性失效** | 占位板是均匀灰，中位帧差恒为 0。《4321》镜 19 横移 **28%** 也只量到均差 2.2（判据 4.0）。**不是运镜错了** |
| `trace` / `measure` | 不适用 | 量的是字幕底和落幅的真实明暗，纯色板上没有意义 |
| 字幕**排版**（断行、宽度、安全区） | **有效** | 这几项只跟字号和坐标有关，跟画面无关 |

`motion` 那一条要特别小心：它会报一串「看不出在动」，很容易顺手当成假警**全部**放过。
《4321》五条里有一条是真的 —— 镜 5 是纯推近、z 只从 1.08 走到 1.18（9% 行程），
换成真图也一样窄。**分辨办法是看参数不是看数字**：
有大横移/大拉远却报警的是假警，纯推近且 z 跨度 <15% 的是真警。

## 一、事实分级（故事片独有，也是最要紧的一条）

诗片只要不读错字就不会出事。故事片会出事的地方在于：
**一条讲得顺的因果链，中间往往有一环只是假说。**

「1816 年欧洲没有夏天」是史实；「所以德莱斯发明了自行车」是科技史学者的推断。
两句话在稿子里长得一模一样，念出来一样理直气壮，
而评论区里懂行的人一眼就能看出来——被拆穿一次，整条账号的可信度就折一半。

所以开工时先把每个论断归一次类，写进 `CLAIMS` 表，`check` 每次都打出来：

```python
CLAIMS = [
    ("C1", "史实", "1815 年 4 月坦博拉爆发，有确切记载以来规模最大", "VEI 7"),
    ("C8", "概数", "试骑十几公里，不到一小时", "各版本 13~14.4km，稿里不说死"),
    ("C9", "假说", "马匹危机 → 德莱斯发明", "Lessing 提出；德莱斯本人没写过"),
]
```

三个级别，三种处理：

- **史实** — 正常讲
- **概数** — 稿子里就不要给精确值。「上百立方公里」比「150 立方公里」安全，
  而且**听起来一样有力**。数值区间有分歧时，说区间的中间地带，不说端点
- **假说** — 必须在**片内**说出来，不能只写在简介里。看到简介的人不到十分之一

### 假说不要删，要做成第二次反转

删掉假说，故事就散了——它往往正是这个故事之所以有意思的那一环。
正确的处理是**把自我拆解放在结尾，当作第二个包袱**：

> 「多说一句：这条因果链是科技史学界的主流推断，德莱斯本人没有这么写过。
> 　但 1816 年那个没有夏天的年份，是真的。」

先给结论、再自己拆、最后落回一块硬事实。诚实是免费的，
而且这个结构比平铺直叙**更有劲**——观众记住的是"这号还挺实在"。

`check` 会在 `CLAIMS` 里有"假说"、但 `NARR` 的最后三句里一个字都没提到时报警。

## 二、时间轴是**量出来的，不是排出来的**

诗片没有诵读，屏幕上的时间就是全部的时间，所以要按"读得完"排。
故事片反过来：**旁白落点决定一切**，你排的任何数字都会被 TTS 的实际语速推翻。

所以 `make_story_v.py` 里 `SHOTS` **不写 `dur`**。每镜时长由属于它的旁白算出来：

```
镜 i 的内容时长 D_i = Σ(这一镜每条旁白的 pre + 实测时长 + post)
镜 i 的 dur    = D_i + xf(i)        # 补掉 xfade 吃掉的那一段
```

`vo_durs()` 用 ffprobe 量每条 mp3，按 (文件名, mtime, 大小) 缓存到 `vo_times.json`。
**换了配音重新生成，时间轴自动跟着变**，不用手工回填——手工回填一定会漏。

### 旁白还没生成时怎么排片

`NARR` 每条都要写一个 `est=`（估算秒数）。文件不在时用 `est`，并且
`check` 会大字提醒"时间轴是估算的"。这样出图、排分镜、写图片任务书
都能在配音之前先做完，不用干等。

估算公式：**中文讲述约 4.6 字/秒**（比诗慢、比新闻播报快）。
标点不计字数，但每个逗号大约多 0.15s。

### 气口

`pre` / `post` 是这一句前后的静默。默认 (0.25, 0.45)。三处要单独给：

- **冷开场**：第一句的 `pre` 给 1.2~1.6s。上来就说话，观众还没看清画面
- **转折句之前**给 0.6~0.9s（「但真正改写了历史的，是另一件事——」）
- **金句之前**给 0.8s，之后给 1.2s。留白就是重音

### 语速自检

`check` 会用 `字数 / 实测时长` 算每句语速，落在 **3.8~5.5 字/秒** 之外报警：

- 低于 3.8 —— TTS 拖了，或者这句里有它读不顺的专名（人名、地名、外来词）
- 高于 5.5 —— 太赶，字幕跟不上，观众会漏掉信息

数字和外文专名是重灾区：「1815」「卡尔·冯·德莱斯」「曼海姆」这类
不同 TTS 差得很远，**必须实测**，不能按字数估。

## 三、字幕：横排、左下、避开操作栏

**这一节讲的是"烧进画面"那一种**（`SUB_MODE = "burn"`，竖版的默认）。
外挂字幕（`SUB_MODE = "srt"` —— 发 YouTube Shorts，也是竖版做双语的前提）
由播放器排版，下面这些坐标和像素判据一概不适用，判据换成字数：见第十节第九小节。

竖版右侧 x 929~1080 / y 864~1632 是抖音小红书的操作栏（真机验过，见 `SKILL.md`）。
诗片的竖排字幕在右侧那条窄带上，靠**上移**避开；
故事片的横排字幕是宽的，靠**收窄 + 靠左**避开：

```
SUB_CX     = 475          # 列心，不是 540
SUB_MAX_W  = 830          # 文本框最宽，右缘 890 < 操作栏左沿 929
SUB_FS     = 54
SUB_BOT    = 1440         # 字块底，低于它就进发布文案区了
SUB_LH     = 74           # 行高
```

一屏最多 **两行、每行 15 字**（15 × 54 = 810 ≤ 830）。
稿子里用 `｜` 手工标断行位置——**不要交给自动换行**，
自动换行会把「一座火山炸出来的」拆成「一座火山炸出」+「来的」。

`check_safe()` 对每条字幕算外接矩形，撞了就报。它同时防三个区：
顶部导航（y < 173）、右侧操作栏、以及底部发布文案区（y > 1560，**这一条还没在真机
上比过**，是按常见版式估的保守值）。

字体用**黑体不用楷体**。讲述是现代口吻，楷体会把它拉回"读诗"的调子；
而且横排小字号下楷体的可读性明显不如黑体。

## 四、镜数与节奏

一条 90~110s 的故事片排 **12~16 镜**，每镜 3~8s。

诗片可以全片一个转场时长，故事片不行——**转场是叙事标点**：

| 位置 | 转场 |
|---|---|
| 钩子之后 | **0.4~0.5s 硬切**。抛完钩子立刻进正题，溶解会泄气 |
| 段落翻页（天灾 → 人祸这种） | **1.8~2.2s 长溶解**，全片一两处，多了就没有了 |
| 转折句之后 | **0.4s 短切**，要一记硬的 |
| 金句 | **2.0s 长叠化**，金句要叠上去不是切上去 |
| 其余 | 1.0s |

**镜 1 和最后两镜要在视觉上闭环**：钩子用现代画面、中段用历史画面、
金句那一镜把两者叠在一起。这是故事片最便宜也最有效的一个结构，
诗片没有对应物。

## 五、音频：三条轨，音乐要躲

诗片只有音乐一条轨（外加音效）。故事片是**旁白 + 音乐 + 音效**，
而且音乐必须给旁白让路。

**只调低音量是不够的。** 压到听不见音乐就没意义，压不够旁白就发浑。
正确做法是**侧链躲闪**：旁白一进来音乐自动降 6~8dB，旁白一停自动回来。

```
[music][vo]sidechaincompress=threshold=0.06:ratio=6:attack=25:release=350
```

`release` 别给太短，300~400ms 之间——短了音乐会在句间"一鼓一鼓"地喘。

其余数值：

- 旁白在成片里的整合响度目标 **−16 LUFS**，成片总目标仍是 −15
- `MUSIC_GAIN` 比同长度的诗片**低 3~4dB**（诗片 −9，这里 −12~−13）
- 音效增益一律写**目标响度**、由脚本按实测反算，不写死 dB
  （生成的音效响度能差 45dB，见 `SKILL.md`）

### 音乐切入点：要紧的是**旁白不在的地方**

诗片的 maximin 关键窗口是"每句字幕的落点"。故事片全程有旁白盖着，
音乐在那些地方本来就该退到后面——**真正听得见音乐的是旁白之间的缝**。

所以 `pick_music_in()` 的关键窗口自动取：冷开场、每个 ≥1.5s 的长转场、
金句前后的留白、尾板。诗片那套窗口照搬过来会选错点。

## 六、素材

和诗片同一套判据：**尺寸跑 `python make_story_v.py budget` 反推**，
按每一镜自己的运动算（静帧 pp≥1.00 / 运镜 ≥1.20 / 细节镜 ≥1.30），
**不要一律填 4K**——超过 PREP 短边 2160 的部分在 `prep` 第一步就被丢掉。
详见 `references/sourcing.md` 第 1 条。

讲述片在这一条上比诗片更吃香：历史题材常要用档案照片、老版画、地图，
那些东西的分辨率是给定的、改不了。**把这类镜头标成 `motion="static"`，
门槛就从 pp 1.20 降到 1.00**，很多本来判死的素材立刻可用——
而讲述片有旁白连着说，画面停住并不空。

一处反过来：**故事片的字幕在左下，所以出图要求「左下留暗」**，
不是诗片的「右侧留白」或《雨霖铃》的「右上留暗」。
写图片任务书时最容易照抄错的就是这一条——留暗事后补不回来。

### 暗调生成图的调色：不能加反差，也不能用 gamma

讲述片的画面几乎都是暗调实拍，而生成器交回来的这类图**几乎一定是技术性欠曝的**。
《没有夏天的那一年》实测：median 14、p25 1~8、mean 21~24。

对这种图有两个都错的直觉：

- **加反差是负的。** `eq=contrast=1.04` 把 median 从 14 压到 **8**、p25 从 8 压到 2。
  模板里那个看着人畜无害的默认值就是这么把画面压死的
- **`eq=gamma` 会把黑位一起抬起来。** gamma=1.25 时 p1 从 1 涨到 **14** ——
  火山那道黑山脊会变成灰的，画面立刻显得脏

要的是**只抬中间调、保住真黑**，所以用 `curves`：

```
curves=all='0/0 0.08/0.13 0.28/0.42 0.60/0.70 1/1',eq=saturation=0.98
```

实测 median 14→23、p75 29→47，而 p1 仍是 0~1。
连带收益：`trace` 的落幅整帧极差从 125/131 涨到 148/153，运镜明显更看得出来。

**换素材必须重新量再定，不要照抄这条。** 判断依据永远是量出来的直方图。

镜数比诗片多（12~16 vs 8~9），但**不必一镜一图**：
同一场景可以出一张大图、用两次不同的取景窗（`CLIPS` 里 `cx/cy/zoom` 不同）。
12 镜常常 9~10 张图就够，省下的额度用来把关键的两三张出到 4K。

### 六之补、插一段资料视频（`CLIPS` 里给 `video=`）

历史题材有时**存在真的影像**——档案馆的新闻片、早期电影的残片、公版纪录片。
这类素材不是插图的替代品，它是另一种东西：**图是「关于那件事的画面」，
影像是「那件事本身」。** 有它而不用，等于把最硬的证据换成了示意图。

一条 `CLIPS` 给了 `video=` 就是视频镜，它和静帧镜、运镜镜**平级**——
不是贴在静帧片上的一个图层：

```python
CLIPS = [
    dict(video="A.mp4", ss="20:10", to="20:30", tweak=""),   # 视频镜
    dict(src="03_海报.png", zoom=1.00, cx=0.50, cy=0.50, tweak=""),
]
```

`SHOTS` 里那一镜照写（`z`/`f` 会被忽略），**不用也不要写 `motion=`**：
素材是不是一段影片，由 `CLIPS` 一处说了算，不该靠两处配置对上口径才成立。

**`ss`/`to` 接受 `"20:10"` 这种时间码**，也接受秒数。写成 `20.10` 想表示 20:10
是这里最容易犯的错——值合法、位置差了十分钟，而且量不出来。

#### 时长永远由旁白说了算

`to - ss` 是**素材段**，镜长是**旁白算出来的**，两者没有约束关系。
`prep` 把整段归一成 `vidNN.mp4`，`pass_a` 从它头上取镜长那么多秒。

段比镜长短会**冻结末帧补足**——画面僵在那里好几秒，而 ffmpeg 退出码是 0。
所以 `check_video` 拦两级：**短了直接拦**；只多一点（不足 `VIDEO_HEADROOM` 0.5s）
也拦，因为旁白重新生成后镜长会变，**现在刚好够等于以后不够**。

#### 画幅：默认加黑边，不裁

老素材几乎都是 4:3，成片是 16:9。`VIDEO_FIT` 两个值：

| | 做什么 | 什么时候用 |
|---|---|---|
| `"pillarbox"`（默认） | 左右加黑边，画幅完整 | **默认。档案影像本来就该看着像档案** |
| `"crop"` | 裁上下填满画框 | 只在画面上下确实是废边时 |

4:3 裁 16:9 要**丢掉 25% 的画面**。讲残缺、讲遗失、讲「还剩多少」的题材尤其
不能裁——裁掉画面和旁白说的话自相矛盾，那是画面在反驳旁白。

#### 分辨率：视频镜不走 pp 判据

640×480 的残片铺到 1080 高是 2.25 倍放大，按 `pp < 1.0` 那条线一刀切会把
整支片子判死。**而「糊」恰恰是这类素材的内容本身。**
`check_resolution` 因此把视频镜单列一张表，只报事实（原始尺寸、帧率、放大倍数、
裁掉多少），不拦。放大超过 3 倍会标出来——那时该考虑的是换一段，不是改判据。

`motion` 同理**两个方向都不判**：末段那种几乎全是化学斑的档案影像首尾帧差可能
极小，那是内容，不是「运镜看不出来」。

#### 帧率：落到 `FPS`，但不要插值

`prep` 就把视频落到成片 `FPS`。不统一的话 `pass_c` 的 concat 会得到一段
时间戳乱掉的片子，**而且它不报错**。
用的是 `fps` 滤镜的丢/复帧。**不要改成 `minterpolate`**——默片本来就抖，
插出来的中间帧会把那份抖动抹成糊的，而抖动往往正是"这是老片子"的全部信号。

#### 授权登记

视频和图走同一张 `CREDITS` 表，**键是 `video=` 的文件名**，同样五项缺一不可。
`credits` 导出的表会多两列：类型（视频/静图）和**用到的段**（`ss–to`）——
用了别人素材的哪一段，是署名的一部分。

**别把「能下载」当成「能再用」。** 上传者写的 CC0 和这份素材的实际权利是两回事，
两个方向都要查：底层作品（年代、法域）和这一次数字化/修复（可能另起新权利）。
数字修复版尤其要当心——把腐蚀修干净的那一版，既可能有新权利，
也已经洗掉了你要讲的东西。

## 七、荐书片：讲述模式的一个子型（第一支《吞下宇宙的男孩》）

一本书 + 简介 + 内容 + 评论 + 现实意义。共用讲述模式的全部机件（旁白驱动时间轴、
横排左下字幕、事实分级、侧链躲闪），但**结构、片长、版权三处和历史小故事片不一样**。

| | 历史小故事片 | **荐书片** |
|---|---|---|
| 成片长度 | 105~125s | **165~185s** |
| 结构 | 钩子 → 正题 → 反转 → 尾板 | **三幕**：书与人 / 内容 / 追问 |
| 幕的配比 | 不适用 | 约 **30% / 30% / 40%**，第三幕可以最重 |
| 最大的风险 | 把推断说成史实 | **把社会议题外挂上去，把书盖住** |

### 第三幕不是"这本书让我想到什么社会问题"，是"**这本书自己在问什么**"

第一支走了三版才对：

| 版本 | 第三幕 | 结果 |
|---|---|---|
| 初版 | 外挂社会议题（青少年犯罪：数据 + 政策 + 方案） | 20 镜 / **220s**，书被议题盖住 |
| 二版 | 议题压成一个 11s 钩子 + 下集预告 | 15 镜 / 158s，书回来了，但第三幕没有重量 |
| **三版** | **追问原书自己的主题**（「一个人怎么才算好人」） | 14 镜 / 165s，议题变成人的问题 |

**找到那个问题，现实意义会自己长出来，不用外挂；找不到就换一本书。**
而且这件事要在**选题阶段**做完，不是写到第三幕才找——找不到问题的书，
这个形式讲不了，越往后越贵。

连带的好处是**假说只剩一个**：报了社会数据就得背因果（「严刑化导致犯罪下降」是假说），
要在中段和尾板各拆一次；不报就只在尾板拆一次「一本小说证明不了任何事」，干净得多。
议题真的值得做就**单独成片，两支互不引用、互不预告**，各自完整。

### 另外五条

1. **钩子用作者的真事，不用书的情节梗概。** 第一支是「妈妈在坐牢、继父在客厅分海洛因、
   保姆是越狱杀人犯」，三句砸完硬切到「这孩子没进监狱」——比任何情节梗概都有力，
   而且这个反差**本身就是第三幕那个问题**，钩子和结尾是同一件事（讲述片要求的
   「镜 1 和最后两镜视觉闭环」，在荐书片里是**内容上**也闭环）。
2. **尾板自拆一次，落在问题上、不落在结论上，不补劝导句。**
   荐书片天然带一条假说：「这本书说明了某个道理」。第一支拆的是幸存者偏差——
   写出来的那个我们听得见，没写出来的听不见。拆完就停，剩下的交给评论区；
   最后四个字是「他没有回答」，多一句都是减分。
3. **现实意义落在一句观众当天能用的话上**，不要落在"呼吁关注"。
   第一支落在发展韧性研究：童年很糟后来却过得不错的人，几乎都至少有过一个
   稳定、真在乎他的大人，**不限于父母**——那个人可以是你。然后靠一记反转
   替它说话（在主角身边，那个人是个杀人犯），片里一个"你应该"都不用写。
4. **给一张"图眼"，同一张图用三次不同取景窗**：中景介绍 → 推近让论点落在脸上 →
   大幅推远收尾。这张出 4K 并留足推拉行程，是全片最值的一张。
   三次之间的取景必须真的分得开，`check_reuse` 只查相邻两镜，
   隔着几镜"回到同一个地方"是设计、不是跳接，那一条查不到，要自己看。
5. **版权：不用书封、不用剧照。** 书名用字卡压在生成图上。原文引用最多一次、
   15 字以内、注明出处——**第一支是 0 次**，连人物金句也只转述不引。
   概念镜（不是场景镜）全用剪影，不给可辨认的脸——给脸观众会去认人。

### 排片长：用系数，别逐项手算（逐项手算翻过两次车）

**《吞下宇宙的男孩》实测**：520 汉字 / 语音 115.3s / 成片 180.1s，
实测语速 **4.51 字/秒**，**静默＋转场占全片 36%**。

> **默认节奏下，1 个汉字 ≈ 0.346 秒成片 —— 3 分钟只装得下 520 汉字。**

逐项手算两次都漏了东西，而且漏的不是同一项：

| 漏了什么 | 有多大 | 在哪一支上 |
|---|---|---|
| 镜间气口 `GAP_PRE 0.45 + GAP_POST 0.70` = **1.15s/镜界** | 21 镜 = 23s | 《吞下宇宙的男孩》：估 165，实算 180.1 |
| **转场本身**——`镜 i 的 dur = D_i + xf(i)` | 22 个转场 = 20~27s | 《4321》：估 190，实为 250+ |

要**提高节奏**时，能动的就是下面四个数（都在判据以内），
四条一起用能把系数压到 **约 0.26 秒/汉字**，3 分钟装得下 ~690 汉字：

| | 默认 | 紧节奏 | 判据 |
|---|---|---|---|
| TTS 语速 | 4.51 字/秒（实测） | 5.0~5.2 | `check_pace` 允许 3.8~5.5 |
| `GAP_PRE / GAP_POST` | 0.45 / 0.70 | **0.40 / 0.62（就是下限）** | 见下面那一条：再紧 `check` 会报「转场压到字幕」 |
| `XFADE` 默认 | 1.0（实际均值 1.35） | 0.7 | 长溶解只留两处 |
| 句内 `pre / post` | 0.25 / 0.45 | 0.20 / 0.35 | |

**镜界气口没有想象中那么能收。** 它的下限不是审美，是算出来的：
字幕收在 `旁白止 + min(post, 0.35)`，转场落在 `旁白止 + post`，
而 `check` 要求转场离字幕 **0.25s** 以上 → **`GAP_POST` 必须 > 0.60**；
入场那侧字幕早 0.10s 起 → **`GAP_PRE` ≥ 0.35**。
所以最紧只能到 **0.40 / 0.62**，比默认省的是 **0.13s/镜界**——22 镜界才 2.9s，
基本不算一个杠杆。（《4321》按 0.35/0.50 填下去，`check` 一次报了 **20 条**
「转场压到了字幕」。）**真正能省的是语速和转场时长。**

两条附注：**汉字计数算不到数字和外文**（「1.1、1.2」「Ferguson」），要按音节另加；
**系数只是估值**——先把四张表填进脚本跑 `check`，再对用户报数字。

而镜数一定会多：讲述片舒适区是 3~8s/镜，**一句到两句一镜**。
第一支三版排 14 镜时平均 12.4s，结尾两镜各 25s 且共用一张图＝
让观众盯着一张照片看 50 秒；改成 21 镜后平均 8.6s，
**多出来的七镜全部用同一张图的不同取景窗顶，出图额度不变**
（`CLIPS` 的 `src` 可以重复，`cx/cy/zoom` 不同）——这是讲述模式最便宜的一个杠杆，
代价是 `check_reuse` 那条判据要一并顶住。

### 出图之前先交一版检查片

**见「〇、出图之前的两道门禁」** —— 那一节原先只写在这里（荐书片子型里），
但它对**所有故事片**都成立，所以提到最前面去了，并且从"建议"变成了
`budget` 会拦住的硬门禁。荐书片尤其要跑，因为它有 180s 硬线，
而实测语速和估算差个 5%（《经度》段五差 7.5s）就是超线。

### 平台有硬上限时（YouTube Shorts 180s）：`vofit`，别指望 TTS

**"让 TTS 说快一点"保证不了片长。** 语速是要来的，不是控制得住的——
同一套提示词，《吞下宇宙的男孩》实测 **4.51 字/秒**。按 4.8 排片长，回来就是超线：
《4321》643 汉字排到 175.4s，若 TTS 交回 4.51，实际是 **184s**。

所以有硬线时用 `vofit`（`make_story_v.py` 里）：量完实测旁白，
算出把片长压到目标所需的 **atempo 倍率**，逐条拉伸，不变调。

```python
HARD_LIMIT = 180        # 平台硬上限。None = 没有硬线
LIMIT_SAFETY = 2.0      # 留给编码/首尾帧
ATEMPO_MAX = 1.08       # 再快就听得出来了
```

四条设计上的讲究，每条都是踩出来的：

1. **倍率按原件算，不按当前的 vo 算。** 拉伸永远作用在 `vo_raw/` 的原件上
   （这样才不叠加），分子就必须也是原件。第一版拿"已经拉过一次"的时长算倍率、
   再作用到原件上，**第二次调整会走反方向**——实测目标 18.0s 反而从 18.6 变成 18.8，
   而且一声不吭。
2. **原速装得下就放回原速。** 否则历史上最紧的那一次拉伸会永远留在片子里。
   加了这条之后 `vofit` 收敛到"刚好够的倍率"，来回改目标都能回到位。
3. **倍率超过 `ATEMPO_MAX` 就拒绝执行**，并按本批实测语速换算成
   "还得砍掉约 N 个汉字"。把 1.3 倍的活交给 atempo，等于拿一个听得出来的毛病
   换一个看不出来的超时——那不是修好，是藏起来。
4. `check` 里同时加了硬线判据：超了报错，逼近（差 < `LIMIT_SAFETY`）报提示。

**排片长时仍然按 0.26~0.35 秒/汉字 估**，`vofit` 只负责把最后那几秒抹平——
差 5~10 秒它救得了，差 30 秒它会拒绝，那时候该改的是稿子。

**片长 ≥180s 时配乐必须两首**（mureka 实测最坏只有 180s，余地 0），
换曲点放幕二→幕三的长溶解上；只有 ≤165s 才谈得上单曲。
或者干脆走 `MUSIC_MODE="library"`——荐书片全程有旁白盖着，库里现成的多半够用。

## 八、旁白 TTS：**为什么别人生成的有 AI 味**

讲述片的成败一大半在旁白。同一段稿子、同一个引擎，配置差一点出来就是
"机器在念稿"。下面这套是《经度》五段 176 条、《没有夏天的那一年》《吞下宇宙的男孩》
《4321》上反复用出来的，**照抄就行**。

### 定死的四项

```
provider      doubao
voiceId       yuanboxiaoshu          （渊博小叔）
emotion       storytelling
emotionScale  3
speedRatio    **不给**               ← 这一条最容易做错，见下
```

**`speedRatio` 不要设。** 想让它读慢一点、稳一点，本能是把 `speedRatio` 调到
0.9 左右 —— 那是错的方向。变速是**整条等比拉伸**，句子内部该快的地方也慢了，
听感立刻变成"念"。语速该由 `performancePrompt` 里的"停顿留住"去要，
要来的慢是**有轻重的慢**，拉出来的慢是均匀的慢。
（诗词诵读是另一回事：《青玉案》用了 `speedRatio 0.85`，因为诵读本来就该是均匀的稀。）

**`emotionScale` 给 3，不是 5。** 5 会开始"演"，一到转折就上扬，
讲历史听着像讲鬼故事。3 是"有起伏但不表演"。

### 一句一条，不要整段一条

**一条 mp3 = 一句话 = 字幕表里的一行。** 理由有三层，每层都吃过亏：

1. 整段一条没法排时间轴 —— 讲述片的时间轴是**旁白落点推出来的**，
   要的是每句的实测时长，不是整段的。
2. 某一句读坏了，重生成只花一句的额度。整段重来是全额。
3. 一句一条才谈得上**逐句给表演指示**（见下），那是去 AI 味的主力。

命名 `VO_<镜号><序号>.mp3`：`VO_01a` `VO_01b` `VO_06c`。
脚本按这个名字找，`sort_downloads.py` 按这个名字归位。

### `performancePrompt`：**去 AI 味的主力在这里**

给一条统一的底子，然后**挑十来句单独写**。底子（《经度》五段共用）：

```
像讲一个真实的旧故事，沉稳有起伏；句尾略收不上扬；年份、时刻和地名读清楚，
中间的停顿留住；不要播音腔，不要煽情。
```

拆开看每一句在挡什么毛病：

| 这一句 | 挡的是 |
|---|---|
| 像讲一个真实的旧故事 | 定住整体口吻。不给这句它会默认"朗读课文" |
| 沉稳有起伏 | 只说"沉稳"会得到一条平线，**必须同时要起伏** |
| **句尾略收不上扬** | AI 味最大的单一来源。TTS 默认句尾上扬，一段话下来每句都往上挑，像在提问 |
| 年份、时刻和地名读清楚 | 专名是 TTS 最容易含糊带过的，而讲述片全靠专名立信 |
| 中间的停顿留住 | 要慢的正确方式（不是 speedRatio） |
| 不要播音腔 | 挡新闻联播那种腔 |
| 不要煽情 | 挡"感人故事"腔。历史片一煽就假 |

**逐句加写的，按用途分三类**（《经度》段五 33 条里有 10 条加写）：

```
破折号插入语     两个破折号中间那句要略微放慢当插入语；句尾吊住等下一句
句尾要吊住       这一句要吊住，等下一句落下来
                 这一句要慢，「其实不是经度」之后停住等下一句
情绪要挡住       **不要带贬义**，就是陈述来源
                 这一句是回到开头，语气要熟悉、亲近一点
```

第三类最要紧也最容易漏。《经度》段五 `VO_08a`「那个版本主要来自一本1995年的畅销书」——
不加"不要带贬义"，TTS 会把"畅销书"读出轻蔑，那句就从**陈述来源**变成了**在骂书**，
整段自我拆解的立场当场垮掉。**稿子中立不等于读出来中立。**

### 语速是量出来的，不是设出来的

`EST_RATE`（字/秒）**不是常数**，随 emotion 和逐句 `performancePrompt` 变：

| 片子 | 实测 |
|---|---|
| 《吞下宇宙的男孩》 | 4.51 |
| 《经度》段一 / 二 / 三 / 四 | 4.24 / 4.16 / 4.00 / 4.14 |

段三最慢，因为那一段"停顿留住"的指示给得最多。**排片时按 4.1 估，
生成完必须跑 `sync` 回填实测**，段长会变（《经度》段五估 138.0s，实测 130.5s，差 7.5s）。
有平台硬线时这一差额是致命的，所以门禁二（检查片）必须在出图之前过。

### 每条 mp3 自带约 0.6 秒静音——这一条会连着坑三处

**《白衣女人》第一集实测**：121 条，拟合 `时长 = 0.615 + 0.2048 × 汉字`，**R² = 0.963**。

> **每条文件头上 0.446s、尾上 0.433s 是静音，合计 0.879s。**
> 121 条 = **106s 的静音**，占全批 464.2s 的 **23%**。

**回归截距不等于边缘静音，别拿它当气口用（这一条踩过）。**
同一批数据两种量法给两个数：

| 量法 | 结果 | 它其实是什么 |
|---|---|---|
| 汉字数对时长做回归，取截距 | 0.615s | **偏低**。斜率把「逗号带来的句内停顿」一起吸收了，截距因此被压小 |
| **直接量头尾的 RMS 包络** | **0.879s** | **边缘静音的真值**，也就是会和 `GAP_*` 双重计入的那一截 |

**折气口要用直接量的那个，不是截距。** 差 0.26s/条，121 条就是 32 秒。
回归仍然有用——它的**斜率**是排片用的（`0.2048 s/字`），只是截距别当静音用。

**量法（本机只有 ffmpeg，够用）**：按 0.05s 窗取 RMS 包络，高于阈值的窗算说话，
头尾各取第一个/最后一个说话窗的位置。**已经做成 `scripts/vo_trim.py`**，
`measure` 干量、`apply` 真剪（原件备份到 `vo_orig/`）。
**`silencedetect` 在这里一条都判不出来**——TTS 全程有底噪，连 −65dB 都不触发，
所以不要用它。

> **两个都会静默出错的坑，都在 2026-08-25《潘多拉的瓮》上踩过：**
>
> **一、`astats` 的 `reset` 单位是「帧数」，不是秒。** 写 `reset=0.05` 会被当成 0 ——
> 也就是**从不重置**，于是拿到的是**累积平均**而不是瞬时包络：开头从 −105dB
> 一路缓慢爬升、结尾恒定在全曲平均值附近（实测 −22.7dB），**永远不会掉回静音**。
> 结果是尾部静音一条都检不出来，44 条只"剪"出 9.1s，而脚本报"量完了"。
> **它坏掉的样子很好认：每条的「说话止」都恰好等于文件总长**——那个整整齐齐
> 的巧合就是警报。正确写法是先 `asetnsamples` 把每帧固定成 0.05s，再 `reset=1`。
>
> **二、阈值要为每个音色重新量，不要照抄。** −45dB 是 `zhixingnv` 那批的数；
> `yuanboxiaoshu` 实测**说话中位 −25.6dB / 底噪峰值 −44.8dB**，−45 会把底噪峰
> 当成说话。量法：取十来条的全部 RMS 点排序看分位数，阈值放在底噪峰之上、
> 说话中位之下（这一批取 **−40dB**）。分布多半**没有干净的双峰**
> （实测最大断层只有 0.8dB），所以别指望自动找谷。
>
> **改完一定要做回归自测**：给一条 mp3 前后各 `adelay` / `apad` 注入 1.000s 静音，
> 检出的头尾必须各多 1.000s。坏的那一版在这个测试上会当场露馅。

**坑一：历史上记的"语速"全都不是纯说话语速。** 4.20 / 4.51 / 4.00 这些数字里
都含着这 0.6 秒；句子越短含得越多。它们仍然能用来排片（因为排片要的就是含静音的
总时长），但**不能拿来判断 TTS 读得快不快**。

**坑二：不要拿「整段一条」的试听去估「一句一条」的批次。**
同一段 74 字，整段一条实测 4.39 字/秒；**同样的文本拆成 121 条，整体只有 4.10**。
差 7%，而且方向是"批次更慢"。原因就是那 0.6 秒按条计，条数越多摊得越多。
**试听要按将来真正的切分方式做**，否则估出来的语速系统性偏快。

**坑三（最要命）：`GAP_PRE` / `GAP_POST` 会和它双重计入。**
脚本按文件边界排时间轴，然后在每条前后再加 `0.45 / 0.70`——
可文件头尾已经各有 0.44 秒了，于是每句实际被 **1.33 秒**静音包着。

**做法：配置值 = 你想要的气口 − 量出来的那一截**，别在默认值上直接排。

《白衣女人》第一集（53 镜 / 121 条）三种排法：

| | 配置 `GAP_PRE/POST` | 可听气口 | 转场 | 成片 |
|---|---|---|---|---|
| 默认值直接排 | 0.45 / 0.70 | 0.90 / 1.13 | 1.6 | **10:55** |
| 折掉，目标 0.45/0.70 | 0.00 / 0.27 | 0.45 / 0.70 | 1.6 | **9:23** |
| **折掉，目标 0.70/0.95** | **0.25 / 0.52** | **0.70 / 0.95** | **2.0** | **10:13** |

**看第三行**：可听气口比默认那一行**更长**（0.70/0.95 对 0.45/0.70），
片长却**短了 42 秒**。折掉的不是节奏，是听不出原因的拖沓——
**这就是为什么这件事值得量**：不量的话，你以为自己在"留白"，
其实只是在每句话前后各挂了半秒没人要的空气。

字幕落点那条下限（`GAP_POST > 0.60`）仍然要守，但它守的是
**可听的语音止点**，不是文件止点——文件尾部那截静音本来就在替它兜底。

### 开场标题字卡：`t1` 必须收在**镜1 溶解开始之前**

`check` 验烧录文字的底子，但它只验**字卡所在那一镜**。
字卡的 `t1` 比镜1 长的话，它会溢到镜2 上，而镜2 的底子没人验过。

《白衣女人》第一集第一版 `TITLE_CARD t1=6.4`，镜1 在 4.3s 就开始溶解到
镜2（早餐桌，一张亮图）——**副标题正好压在明亮的窗框上，对比度掉下来**。
`check` 全绿，`measure` 全绿，**是抽帧看出来的**。

> **`t1` ≤ 转场落点 − xf/2。** 排完 `sync` 从 `check` 打印的「转场落点」第一个数
> 减去半个转场，就是字卡的死线。

### 冷开场那句 `pre` 别用默认值 —— 它会压在淡入上（**已加 `check_coldopen` 拦住**）

第二节写过「冷开场第一句的 `pre` 给 1.2~1.6s」。**这一条极容易漏**，
因为不写也能跑、`check` 也不报。

《白衣女人》第一集漏了：`PRE_DEF=0.25` → 旁白 0.95s 出声，
而 `FADE_IN=1.2`——**第一句话压在淡入里**，画面还没落定人就开口了。
补 `pre=1.50` 之后实测出声点 1.55s，在淡入之后 0.35s。

**这一条连着漏了两支，第二支就在把它写进技能之后。**
《白衣女人》集一漏了，写进第二节；做集二时用脚本批量生成 NARR 表，
`pre` 是要手工加的一项，于是**原样又漏了一遍**——集二实测旁白 0.70s 出声，
`FADE_IN` 1.2s，同一个毛病。

> **教训不是"记牢一点"，是"光写进文档不管用"。**
> 一条不写也能跑、别的检查也不报的规矩，迟早会漏。
> 已经加了 `check_coldopen()`：`SEG_FIRST` 且 `FADE_IN > 0` 时，
> 第一条旁白的落点必须在 `FADE_IN + 0.2s` 之后，否则 `check` 直接拦。

**一个连带的坑**：改了第一句的 `pre`，**整条时间轴往后移**（集二 520.1 → 520.9s）。
如果配乐是照着旧时间轴造的音乐床（见 `music.md`），**换曲点会偏，必须重造**。
凡是"照时间轴造出来的素材"都有这个依赖，改时间轴时要一起想到。

**顺带一条容易算错的**：`GAP_PRE` **不叠加**在句内 `pre` 上。
`pads()` 对一镜里的第一条取的是显式 `pre`，不是 `GAP_PRE + pre`。
（我按 0.70+1.50=2.20 报过一次，实测 1.55。）

### 折气口撞上脚本的硬下限 —— 正确做法是**剪文件**，不是调配置

把 `GAP_PRE/POST` 往下折到 0.25/0.52 之后，《白衣女人》第一集**每一个镜界都报
「转场压到了字幕」**（53 镜全中）。原因不是气口判据太严，是**折错了地方**：

> 脚本按**文件边界**排字幕和转场，它不知道文件头尾各有半秒静音。
> 而那条下限（`GAP_POST > 0.60` / `GAP_PRE ≥ 0.35`）守的正是文件边界。
> **你折掉的那一截，恰恰是判据赖以成立的那一截。**

**正确做法：把边缘静音从 mp3 里剪掉**（原件留一份 `vo_orig/`），
让"文件边界"重新等于"说话边界"。剪完之后 `GAP_*` 直接填**你想要的可听值**，
不用折算，下游所有计算——字幕落点、转场位置、镜长、片长——自动全对。

```bash
python vo_trim.py measure     # 先干量
python vo_trim.py apply       # 再真剪，原件进 vo_orig/
```

《白衣女人》第一集剪掉 **88.6 秒**，然后 `GAP 0.70/0.95` 一次通过。
《潘多拉的瓮》44 条剪掉 **16.5s**（0.374s/条，另刻意保留 `KEEP_HEAD 0.06`
+ `KEEP_TAIL 0.10` 的安全边，所以实际边缘静音约 0.53s/条），
片长 **180.9s → 164.4s**，从超硬线变成余量 15.6s。
**剪之前那个 180.9s 不是稿子长，是双重计入**——这一条最容易被误读成"要砍稿子"。
**这比改脚本的时间轴逻辑便宜得多，也比在配置里折算可靠得多。**

### 手算片长会往**多**了算：转场已经含在镜长里

第七节记过一条「漏算转场」（`镜 i 的 dur = D_i + xf(i)`，逐项手算容易漏）。
**反过来的错也会犯，而且更隐蔽**：知道了这条公式之后，在外面又加了一遍转场。

《白衣女人》第一集手算 10:13，脚本实排 **8:33**，差一分四十 ——
53 个转场 × 2.0s = 106 秒被重复计了。

> **别手算片长。填进脚本跑 `sync`，那个数才是数。**
> 手算只该用来判断"稿子大概是不是这个量级"，不该拿去对用户报数字。

### 换项目时 `SRC_NATIVE` 必须重填，不能继承

从上一支复制脚本时，`SRC_NATIVE` 带着**上一支生成器的封顶值**过来了
（《廷巴克图》是 `(1672, 941)`）。《白衣女人》的图是真 4K，于是
**53 镜全部误报「在放大」**——一屏红字，全是假的。

同类的还有 `PP_ACCEPT_REASON`、两个门禁字符串 `GATE_SCRIPT_OK` / `GATE_PREVIEW_OK`，
**以及连载片的 `ENDCARD`（下集预告板）**：
前三个是上一支的签字，继承过来等于替这一支签了字；
`ENDCARD` 更直接 —— 《白衣女人》集二带着集一的板子渲完了整片，
成片里写着「下一集 · 黑水园」，**而黑水园就是这一集自己**。
`check_seg` 只验 ENDCARD 该不该存在、不验里面写了什么，所以一路全绿，
**是用户看片时发现的**。已加 `check_endcard()`：预告板的 head 里出现本集 `TITLE` 就拦。

复制脚本后第一件事是把这五个清空重填。

### `check_pace` 的「字/秒」判据对短句系统性误报

同一批 121 条，`check_pace` 的 3.8~5.5 判据报了 **39 条**，
**全部偏慢、且全部是短句**——`是荒唐。`(4 字) 算出来 2.05 字/秒。
那不是读慢了，是 0.6 秒的常数在 4 个字上摊成了大头。

**换成残差判据**：按 `a + b × 汉字` 预测，只看偏离。
39 条报警塌成 **3 条**，而这 3 条**恰好是给了停顿指示的那几句**
（「三个短句，一句一句落下来」+1.17s；「略带干巴的讽刺」+0.95s），
**都是想要的效果，一条都不用重出**。

> 短句不要用字/秒判。**用残差，阈值取 2σ**（这一批 σ = 0.30s）。
> 好处是它顺带能验一件别的办法验不了的事：**逐句表演指示到底落没落地。**

### 提交完要按脚本核对，不要用眼睛数

批量提交很容易漏几条（实撞过：以为发了 32 条，实际只有 20 条，
因为按"每批 4 条"数成了 8 条）。**一句断言解决**：

```python
want = {n["vo"] for n in NARR}
got  = {os.path.splitext(f)[0] for f in os.listdir("build/vo")}
assert want == got, "对不上！缺 %s，多 %s" % (sorted(want - got), sorted(got - want))
```

### 下载下来的文件

浏览器批量下载会带 ` (1)` ` (2)` 后缀，而脚本按精确文件名找 ——
带后缀的文件**不会报错，只会"缺素材"**。`sort_downloads.py` 专治这个：

```bash
python sort_downloads.py <段目录>          # 先看计划
python sort_downloads.py <段目录> --apply  # 再真动
```

**归位后立刻跑上面那句断言。** 《经度》有一次整批下成了另一段的旁白
（38 条 vs 33 条、最大镜号 14 vs 15），断言一秒钟就抓住了；
靠眼睛看文件名列表是看不出来的，因为前面三十个名字一模一样。

### 八之补、EST_RATE 是「剪静音后的纯语音语速」，别拿含静音的那个数填

**同一个坑咬了《白衣女人》集一和集二，第三集才看出来。**

脚本里 `_est()` 只做一件事：`汉字数 / EST_RATE = 这一条 mp3 的时长`。
它要的是**剪掉边缘静音之后的纯语音**语速。

而各集《制作说明》和《全集总谱》的实测表里记的是**「含静音语速」**——
那个数把「按条计的静音」摊进了「按字计的说话」，条数越多它越小，两者天生不是一个量。

集一、集二都把含静音的 **4.10** 填进了 `EST_RATE`，于是**出图前的片长估算一律长两成**
（集二估 ~620s，`sync` 实测 **520.9s**）。片长在出图前只是参考，所以两次都没被发现；
**但有平台硬线的片子上，这个方向的误差会让人白砍稿子**。

同口径的实测：集二 **1937 汉字 / 373.6s（剪静音后）= 5.19 字/秒**。

> 这和第八节那条「秒/汉字单一系数把两种时间混成一个数」是**同一个错误的另一面**。
> 判据：**填 `EST_RATE` 之前先问一句——我量的这个数，分母里含不含句间静音。**

换音色、换 `emotion`、换 `performancePrompt` 都要重新量。

## 九、小说第一人称模式：让书里的一个人自己说

> **第一支还没跑完。下面凡是标「待实测」的都不要当数**——它们是按已验过的
> 系数外推的，第一集交付后必须回来换成实测。这一节的其余部分（人称合约、
> 忠实度分级、版权那三条）是设计判断和已知的坑，不依赖实测。

### 它是什么，不是什么

**不是荐书片。** 荐书片站在书外面介绍一本书；这个站在书里面，由一个角色
对着观众把他自己那段经历讲一遍。观众要的不是"这本书好在哪"，是"后来怎么了"。

| | 荐书片（第七节） | **小说第一人称** |
|---|---|---|
| 谁在说话 | 一个读过这本书的人 | **书里的一个人** |
| 观众看完记得的 | 这本书值不值得读 | **这个人后来怎么了** |
| 片长 | 165~185s，一本书一支 | **600s ± 60**，一本书**连载多集** |
| 结构 | 三幕：书与人 / 内容 / 追问 | **一集一个完整的故事** |
| 版式 | 竖版、烧录字幕 | **横版 1920×1080 + 外挂 SRT**（同《经度》） |
| 每镜停留 | 3~8s | **8~15s** |
| 最大的风险 | 把社会议题外挂上去 | **"我"知道得太多**；**抄中译本** |

机件共用讲述模式的全部：旁白驱动时间轴、`sync` 量实测、侧链躲闪、两道门禁、
`make_story_h.py` 分段 + `join.py` 拼接。下面只写不一样的。

### 一、人称合约：四个问题，第一集之前答完，答完不许改

这个形式唯一不可逆的决定，缺一条后面每集都会晃：

1. **谁在讲？**
2. **他在什么时候讲？** 事发当时 / 多年以后 / 临死前。
   **这一条决定他知道多少**，是四条里最容易漏、代价最大的。
3. **他在对谁讲？** 对观众 / 对法官 / 对一个已经死了的人 / 对自己。这一条决定语气。
4. **他为什么现在要讲？** 讲述动机。**全片的能量从这里来**——
   没有动机的第一人称，就是把小说念一遍、换了个人称代词。

**第二条错了会以很难发现的方式毁掉片子**：叙述者顺口说出他当时不可能知道的事。

> 「那时候我还不知道，他已经在楼下等我了。」——合法，"那时候我还不知道"把时点交代了
> 「他已经在楼下等我了。」——**越权**，这一句"我"不在场

**写稿时每一句都要能回答"他是怎么知道的"。** 稿子里把越权句标 `[越权]`，
`check` 判不出来，只能人查——但标出来就查得动，不标就一定漏。

### 二、选谁当"我"：不一定是主角

标准只有一条：**选那个知道得比观众以为的多、又比全知少的人。**

| 选谁 | 好处 | 代价 |
|---|---|---|
| 主角 | 情感最直接 | 常常什么都知道，悬念要另想办法 |
| 旁观者（仆人 / 医生 / 律师 / 后来的人） | 天然有信息差，悬念自己长出来 | 情感隔一层 |
| **被误解的一方** | **最强的一路**：观众带着成见进来，第一句就被推翻 | 要求原著里这个人真有话说，不能硬安 |

### 三、忠实度分级：`CLAIMS` 的机件原样用，三级换掉

故事片的事实分级（史实/概数/假说）防的是"把推断说成史实"。小说是虚构的，
那张表不适用——**但风险没有消失，只是换了地方**：观众会拿这一集当原著转述。

| 级别 | 意思 | 规矩 |
|---|---|---|
| `原著` | 书里明写的 | 正常讲 |
| `暗示` | 书里有依据但没写死 | 可以讲，**不能讲成定论** |
| `我加的` | 原著没有，为讲述而加 | **只许补感官细节和内心，不许改变任何情节结果** |

**「我加的」有三条红线，每条都对应一种真实发生过的错法**（荐书片上踩的，
当时的表现是"大框架全对、细节全错"）：

1. **不许把两个人物揉成一个。** 最常见也最隐蔽——讲述上确实更顺，
   但从此这一集和原著对不上了
2. **不许把两场戏并成一场。** 同上
3. **不许补"似是而非的细节"**（具体日期、服饰、器物、地名）。
   **越具体越要查，查不到就写模糊的。** 大框架不会错，
   错的永远是那些为了让画面好看而补上去的具体东西

真要动情节结果（合并、删角色、改结局），**片尾必须说一句**，不能只写在简介里——
和故事片"假说必须在片内自拆"是同一条规矩，那段代码不用改。

### 四、切集：不按章节切，按"我"的状态切

一集要是一个**完整的故事**，不是一个章节区间。判据一句话：

> **这一集结束时，"我"和开始时还是同一个人吗？** 还是，就没到切点。

每集的骨架（和故事片的钩子→正题→反转→尾板不一样）：

| | 占比 | 干什么 |
|---|---|---|
| 冷开场 | ~5% | 一句话把人钉住。**每集都要换一句，不要有系列口号** |
| 我是谁 | ~5% | 给中途进来的人 8~12s。**每集换一种说法说同一件事**，不复用同一段 |
| 幕一 | ~25% | 这一集的"我"想要什么 |
| 幕二 | ~30% | 挡在中间的是什么 |
| 幕三 | ~30% | 代价，以及"我"变成了谁 |
| 钩子 | ~5% | 下一集。**落在一个问题上，不是一段预告** |

**每集自足**：不看上一集也看得懂，看完这一集也是完整的。做不到就是切点选错了。

### 四之补、下集预告板：**独立一镜、独立一图、不出声**

连载必须给观众一个进下一集的入口。但它和第四条那个「钩子」是**两件不同的东西，
不许互相打架**：

| | 钩子 | 预告板 |
|---|---|---|
| 是什么 | 最后一句**旁白** | 结尾之后的一张**静帧** |
| 落在哪 | 一个问题 | 下一集的名字 + 一句不揭底的话 |
| 有没有声音 | 有（它就是声音） | **没有，一个字都不念** |

**三条规矩，第二条最要紧：**

1. **独立一镜、独立一张图，不要压在结尾那一镜上。**
   最后一镜通常是和镜 1 闭环的那一张，它是本集的收尾画面，要让它自己收完。
2. **不出声。** 最后一句旁白后面那段静**是结尾的一部分**——
   给预告配旁白等于把结尾踩掉，整段会从「一个问题」变成「一段预告片」。
   《白衣女人》第一集最后一句是「是一个日子。」，那句后面必须是静的。
3. **不剧透。** 连载都有一张底牌（本系列是「为什么她们长得像」），
   **预告板一集都不许碰**。挑图也照这条：**没有脸的画面最安全**。

**实现（脚本本来就支持，不用改代码）：**

- `SHOTS` 里加最后一镜，写 `dur=`（`timeline()` 对没有旁白的镜就是读这个），
  `motion="static"`，`xf` 给长溶解（2.5s）
- `ENDCARD = dict(head="下一集 · X", sub="一句话", t0=, t1=, y=)` 压在这一镜上
- 片尾 `FADE_OUT` 自然落在预告板上，正好

**这一张图是本集第二张有留白要求的图**（另一张是压开场标题的那张）。
字幕外挂虽然删掉了留白要求，但**烧进画面的标题和预告板不在豁免之列**，
出图任务书里要给那条横带写死。

**顺带一条切集的经验**：《白衣女人》原定 8 集，写完第一集变成 7 集——
第一集的稿子自然收在了原定属于第二集的材料上，剩下的撑不起一整集。
**这不是排错了，是第四条那个判据在起作用**（一集在「我」的状态变化上收口，
不在章节区间上收口）。**分集表要允许在写稿过程中改**，写死在总谱里的是判据，不是集数。

### 五、片长与镜数（**待实测**）

600s ± 60。**一集 = 一支完整的片子，一次渲出来，不分段。**

`make_story_h.py` 是《经度》的**分段**脚本，但它对单段是通的、而且是干净的：
`SEG_INDEX = SEG_TOTAL = 1` → `SEG_FIRST` / `SEG_LAST` 同时为真 →
开场淡入、片尾淡出、标题字卡、尾板、假说自拆检查**全部自动打开**，
`*_预览.mp4`（归一 + 头尾淡场）就是交付物，**不用跑 `join.py`**。

**为什么第一支不分幕**（这一条改过一次，记下来免得来回摇）：
`join.py` 和分段制度整套是**为接缝服务的**——逐段归一的响度台阶、
每隔几分钟黑一次、段长不是整帧的 A/V 漂移、SRT 偏移。
**一集就是一支完整的片子时，一个接缝都没有**，那套机件全部空转。
分段剩下的唯一好处是「改一幕只重渲一幕」，而那是**推测的**迭代成本，没有实测。
所以第一支按单段跑，**跑完记下四趟渲染各自的实测耗时**，再决定要不要分。

（分段仍然是对的，当一集真的长到不得不分、或者几集要拼成一支合集的时候。）

排片长系数：**先按 0.36 秒/汉字排**。依据是荐书片默认节奏实测 0.346，
第一人称的气口比转述多（见第七条"该停的地方停住"），所以往上估一点。

> 600s ≈ **1600~1700 汉字/集**。第一集跑完必须回来把这个数换成实测。

镜数 **45~60 镜/集，每镜 8~15s**——比故事片（3~8s）慢一倍，理由见下一条。
**出图额度不是 45~60 张**：「同一张图不同取景窗」那个杠杆在这里比荐书片还划算
（一段回忆本来就该停在同一个地方），实际出图 **25~35 张/集**。

### 六、画面：静帧/缓动不是省钱，是这个形式的正解

第一人称是**记忆**，记忆是静止的画面加上一个声音。画面一动，
观众就从"听他回忆"掉回"看一段影片"。所以：

- `MOTION` 默认 **`static`**，缓动是**逐镜覆盖的例外**，不是默认。
  和其余所有模式相反（那些默认 `kenburns`）
- 要动的那几镜，行程压得比故事片更小：故事片 Ken Burns 门槛 pp ≥ 1.20，
  这里的"缓动"档**待实测**，先按 **z 行程 1.04~1.08、镜长 ≥ 10s** 排
- 转场**以长溶解为主（1.5~2.5s）**，硬切留给"我"被打断的地方——
  和故事片正好相反（那边硬切是常态、长溶解全片一两处）

### 七、声音：全片最大的一处改动，**不要照抄第八节**

第八节那套（渊博小叔 / storytelling / scale 3）是**讲述者**的声音——
一个读过资料的人在给你讲。第一人称要的是**角色**的声音，一个人在说自己的事。
照抄会得到"一个纪录片旁白假装自己是主角"，比 AI 味更难受，因为它每一句都对。

| | 讲述模式 | **第一人称** |
|---|---|---|
| `voiceId` | 渊博小叔 | **试听选，像画种一样不可逆，不要替用户定** |
| `emotionScale` | 3 | **4**（说自己的事该更有情绪）。**5 仍然是"演"** |
| `speedRatio` | 不给 | **同样不给**，理由一样。要快要慢**从 `performancePrompt` 里要** |
| 目标语速 | 实测 4.0~4.5 | **比历史基准快 5%**：基准 4.20 → **目标约 4.40 字/秒** |

**语速快 5% 的正确做法是砍指示，不是调参。** 先把逐句 `performancePrompt` 里的
「略停」「吊住」「等下一句落下来」这类指示删掉一批（只留真正的转折句和落点），
**不要去动 `speedRatio`**——变速是整条等比拉伸，句子内部该快的地方也快了，
听感立刻变回"念"。砍指示要来的快是**有轻重的快**。
连带：句间静默也跟着少，所以**整片时长的降幅大于 5%**（语音只占全片约六成，
但砍掉的静默是净减），排片时按 **秒/汉字系数 × 0.95** 估，跑完实测覆盖。
| `performancePrompt` 底子 | 「像讲一个真实的旧故事…」 | **整条重写**，见下 |
| **句尾略收不上扬** | 有 | **原样保留**。它挡的是 AI 味，和人称无关 |

底子改成（**待实测**）：

```
像一个人在对着一个人说自己的事，不是在讲故事；句尾略收不上扬；
该停的地方停住，不要赶；克制，越难过的地方越不要用力。
```

最后一句是这个形式独有的。**第一人称最容易翻的车是"读得太投入"**：
角色在讲自己最痛的一段，TTS 一用力就变成朗诵比赛。
「越难过的地方越不要用力」必须写进**底子**，不能只逐句加写——
因为难过的地方不止十来句。

**声音试听是一道门禁，和画种同级。** 挑这一集里**最难的一段**、30s 左右，
用 2~3 个 `voiceId` 各出一条交用户听。最难的一段 = 情绪最重、或专名最多的那一段。
**拿最好听的一段去试听等于没试。**

### 八、版权：三条硬规矩，第三条极容易踩

1. **只用公版原著**（作者逝世满 70 年），而且**核对到具体年份**，
   不要"应该是公版吧"。
2. **不抄任何中译本。** 从原文自己读、自己写。这是这个形式最容易犯、
   后果最重的一条——**中译本是有版权的独立作品**，抄了就是侵权，
   "只是参考了措辞"在法律上不成立。**手边不要放译本，放了就会渗进来。**
   原文引用最多一次、15 字以内、自己译、注明出处。
3. **影视形象不是公版。原著公版 ≠ 那个角色长什么样是公版。**
   最典型的：**弗兰肯斯坦的怪物那个平顶头加脖子上两颗螺栓，
   是 1931 年环球影业的美术设计，至今在版权内**——小说 1818 年早已公版，
   形象不公版。**出图任务书里必须明写禁止**，否则生成器一定会给你那个形象
   （它训练数据里全是）。同类的坑：福尔摩斯的猎鹿帽（是插画师 Sidney Paget 的）、
   各版电影海报与剧照、书封。

片尾固定一行：`改编自《原著名》（作者，年份，公版）。中文文本为本片原创。`

### 九、连载合约：《全集总谱》

一本书多集，**跨集不一致比单片翻车更难发现**——每一集单看都对。
所以开一份《全集总谱》，位置和作用同《经度》的《全片总谱》：**唯一真相来源**。
必须写进去、各集脚本从这里读的量：

- 人称合约那四条（谁 / 何时 / 对谁 / 为什么）
- `voiceId` 与 `performancePrompt` 底子
- 画种 + `GRADE`
- **忠实度分级表（全书的，不是本集的）**——和《经度》的 `CLAIMS` 一样，
  某条"我加的"可能第二集埋、第五集才说明，所以自拆检查只在最后一集跑
- 每集的切点，和"我"在这一集里的状态变化
- 片头片尾的固定件（标题版式、版权行）
- **各集实测表**：汉字数 / 语音时长 / 成片时长 / 实测语速。
  这张表是下一集排片长的唯一依据，比任何系数都准

## 十、双语音轨：一条画面，两条音轨（YouTube 多语言音轨）

**适用**：横版讲述长片、小说第一人称连载（`make_story_h.py` + `join.py`），
以及**竖版讲述片**（`make_story_v.py`，2026-08-31 打开，见第九小节）。

竖版原来写的是"不做"，理由是"抖音小红书必须烧字，烧了就不能多音轨"。
**那个理由只对烧录字幕的平台成立**，不是竖版本身的性质 —— 竖版发 YouTube Shorts
时字幕可以外挂、音轨可以多条。所以竖版的双语开关不是"做不做"，而是
**先把 `SUB_MODE` 切到 `"srt"`**。

仍然成立的是那句话的后半截：**烧录字幕 + 多语言是自相矛盾的配置** ——
烧进画面的中文字会跟着英文轨一起播，而你手上放的是中文版，永远发现不了。
所以竖版脚本里 `check_mode()` 直接拦下这个组合，`check` 每次跑它的回归自测。

### 〇、一句话推出全部设计

YouTube 的多语言音轨，画面只有一份、**每种语言一条独立音频**。三条推论：

1. **时间轴归中文所有。** 英文旁白必须塞进中文量出来的槽里。反过来让画面迁就英文，
   两条轨就成了两支片子 —— "多音轨"这三个字本身就没有意义了。
2. **正文字幕一律外挂**，中英各一份 SRT。这是横版本来就有的做法，
   到了双语它从"一个选择"变成"一条硬约束"。
3. **音乐和音效是同一床，侧链按各自的旁白算。** 英文的停顿位置和中文不一样，
   拿中文的包络去躲英文，音乐会在英文正在说话的地方抬起来。

### 一、流程：在原来的序列里插两步

```
（英文稿写完，英文 TTS 生成完，放进 vo_en/）
python make_story_h.py langfit      # 新增：逐句把英文压进中文的槽
python make_story_h.py preview en   # 新增（可选但强烈建议）：单听英文那条
python make_story_h.py check        # 会多出一段「英文轨逐句对槽」
python make_story_h.py c            # 一条画面 + 两条音轨 + 两份 SRT
```

`LANGS = ["zh"]` 时上面这些全部不发生，流水线和以前一模一样 ——
**单语片子不用为双语付任何代价**，这是加这个功能时的硬要求。

### 二、槽：每一句能给英文多少空间

槽 = **中文那一条的实测时长** + **可借的静默**。

可借的静默有一条例外，而它是这一节最要紧的一句：

> **镜末那一句借不到东西。** 镜末的静默正中骑着转场（理由见 `make_story_h.py`
> 的 `timeline()`）。借了就是把话说到转场底下去 —— 而这件事在参数表上看不出来、
> 在波形上看不出来，要放出来听才发现。

镜内的句子可以从后面那段气口里借，但**最多借一半**（`LANG_BORROW = 0.30`）：
剩下的一半是气口本身，把气口借光了，英文那条轨会变成连珠炮。

> 0.30 这个数是**定的，不是量的**。第一支英文片做完要听一遍：借满 0.30 的那几句
> 听起来赶不赶。赶就往下调。

### 三、压：逐句 atempo，压不进去就不压

`langfit` 逐句算倍率，上限 `LANG_TEMPO_MAX = 1.06`。

**为什么是逐句，不是整条一个倍率**（竖版 `vofit` 那样）：`vofit` 解决的是
"整片超硬线"，全片同一个倍率听不出来。这里解决的是"这一句和画面对不上"——
各句超出的比例天差地别。拿全片平均倍率去压，短句被无谓地拉快、长句照样压不进去，
**而且两头都听得出来**。

**为什么上限比 `vofit` 的 1.08 更紧**：整片拉伸是均匀的，耳朵几秒就适应了；
逐句拉伸是**忽快忽慢**的，一句 1.08 紧跟着一句 1.00，落差比绝对速度更显。
> 1.06 同样是**推测**。第一支英文片上要专门听那几条压到上限的句子。

超过上限**不压**，报出这一句还得砍几个词，并把文件**放回原速**——
不是留着上一次压的结果。留着的话，磁盘上的状态取决于你跑过几次，不可复现。

```
!! 1 条压不进去（超过 ×1.06 就不压了）：
   VO_09c      槽 5.62s，现在 6.90s，要 ×1.228 才塞得下 —— **还得砍约 6 个词**
   别把这活交给 atempo：听得出来的毛病换看不出来的错位，不是修好。
   要改的是英文稿，中文那条轨和画面一个字都不用动。
```

"还得砍几个词"用的语速：`EN_RATE` 填了就用它，**没填就用本批实测**。
这比填一个通行值靠谱 —— 英文播报语速取决于音色、emotion 和 performancePrompt，
和中文的 `EST_RATE` 是同一类数，不是常数。

> **`EN_RATE = None` 是有意留空的。** 第一支英文片跑完 `langfit`，
> 它会把实测的词/秒打出来，那时候再回填。**不要照抄网上的 150 wpm。**

### 四、英文稿是"配音改写"，不是翻译

这一条决定了上面那套机器好不好用。**逐句直译一定会长出去**：中文一个字
携带的信息多，同一句话英文平均要长一到三成。

所以写英文稿时按**槽**写，不是按中文句子写：

- 先看 `check` 打出来的那张「英文轨逐句对槽」表，知道每句有多少秒
- 长出去的那几句，**改写**而不是压 —— 换一个更短的说法，同一个意思
- 中文里的成语、四字格、语序倒装，直译过去既长又平，重写一遍
- 专名（人名地名书名）英文常常更长，**它们是砍不动的**，砍旁边的修饰

### 五、字幕：两份 SRT，起点一样，收尾各自

英文 SRT 的**起点和中文完全一样**（槽是中文定的），只有收尾跟着英文音频走 ——
英文那句短一点，字幕就早一点收。文件名：`段一.srt` / `段一.en.srt`，
`join.py` 按文件后缀合并成 `全片.srt` / `全片.en.srt`。

英文一行的字数上限 `SUB_MAX_CHARS_EN = 42`（中文是 20 个全角字，英文按半角算
大约是它的两倍）。断行符还是 `｜`，手工断，不交给自动换行。

### 六、两处会静默出错的地方（这一节真正的价值）

**一、改了翻译、重新生成、忘了跑 `langfit`。**
英文音频长出槽去不会报错、不会崩、波形上也看不出来，只会让那句话说到转场底下去 ——
而你手上放的是中文版，一切正常。
所以 `check_langs()` **每次 check 都从磁盘上的英文文件重新量一遍**，
不是复述 `langfit` 当时的结论。这是唯一拦得住它的地方。

**二、`concat` 默认只留一条音轨。**
ffmpeg 不给 `-map` 时按"每种类型挑最好的一条"选流。两条音轨的段用文件拼完
**只剩一条**，而且返回码是 0、能播、时长对、中文轨也对 —— 只有英文轨没了。
`join.py` 因此显式 `-map 0`，并且**自测里先把这个危险演一遍**
（跑同一条命令去掉 `-map 0`，验证它真的会丢轨），再验加上之后留住了。

同一个形状的第三处：**逐轨归一**。两条轨的说话密度和静默比例不同，整合响度天生不同。
拿其中一条的测量值去归另一条，两条轨就差出一个固定的台阶 ——
而观众正是在**切换音轨的那一刻**听见它。所以 `pass_c` 和 `join.normalize`
都是逐条量、逐条归到同一个目标；`join` 的接缝检查也逐条判台阶。

### 六之二、**上传形态：不能直接传多音轨文件**（2026-08-31 更正）

这一节原来写的是"一条视频 + N 条音轨"，**那个前提是错的**。
YouTube 的多语言音轨**不是**从上传文件里读第二条轨的：
上传的 MP4 里多余的音轨会被忽略，附加语言要在 **Studio 里作为独立音频文件**添加。

音频本身没错，错的是交付形态。所以 `join.py` 拼完之后自动拆三样（全部流拷贝）：

| 文件 | 是什么 | 干什么用 |
|---|---|---|
| `全片.mp4` | 视频 + **默认语言**一条轨 | **这个才是上传件** |
| `全片_音轨_eng.m4a` | 每种附加语言一个独立音频 | 在 Studio 里逐个添加 |
| `全片_多音轨.mp4` | 所有语言在一个文件里 | 留档 / 支持多轨的场合 |

**不拆的后果是不报错的**：多音轨文件传上去能播、时长对、中文轨也对，
只有英文轨没了——而文件本身完全正常。所以 join 拆完会验两件：
上传件是不是只剩默认那条、独立音频和画面是不是等长（差 0.05s 以上就报警，
因为独立音频差一点点就是整条错位，而这在文件里看不出来）。

### 七、交付物

比单语片多三样：

| | 文件 | 说明 |
|---|---|---|
| 上传件 | `全片.mp4` | 视频 + **默认语言一条轨**。多音轨文件不能直接传 |
| 附加语言 | `全片_音轨_eng.m4a` | 每种一个，在 Studio 里添加；和画面等长 |
| 留档 | `全片_多音轨.mp4` | 两条轨都在，给支持多轨的场合 |
| 字幕 | `全片.srt` + `全片.en.srt` | 外挂，两份 |
| 文案 | `发布文案.md` | 多一块 `## YouTube (EN)`，`publish.py check` 默认要求它 |

上传 YouTube 时音轨语言不用手点 —— 元数据在文件里。**没写元数据的样子是
两条轨都叫"未定"**，看不出是谁丢的，所以 `join` 拼完会再验一次音轨和段用文件对得上。

简介里要说一句**怎么切音轨**：多数观众不知道 YouTube 有这个菜单。

   英文要重新试，并且**和中文一样，拿本集最难的一段试，不是最好听的一段**
4. `YouTube (EN)` 在 feed 里切在第几个字符 —— 表里填的 70 是估的，`limits` 会标星号

### 九、竖版这一路（`make_story_v.py`）：先定 `SUB_MODE`，再谈双语

竖版比横版多一条轴 —— **字幕烧进画面还是外挂**。它在开工前就要定死，
因为它决定了这支片子能不能有第二条音轨：

| `SUB_MODE` | 字幕 | 能几条音轨 | 发哪儿 |
|---|---|---|---|
| `"burn"`（默认） | 烧进画面 | **只能一条** | 抖音 / 小红书 / 视频号 —— 那些平台没有外挂字幕 |
| `"srt"` | 外挂 SRT，播放器渲染 | 多条 | **YouTube Shorts**（外挂字幕 + 多语言音轨都支持） |

**两种形态的画面是同一份**（`master.mp4` 一模一样），只有 `c` 那一步不同。
所以"抖音版 + YouTube 版"两支片子只要改这一个常数、重跑 `c`：
不用重出图、不用重渲运镜、不用重新对轴。这是这条设计最实用的一点。

判据跟着换：烧录按**像素宽**判一行放不放得下（字号是我们定的），
外挂按**字数**判（`SUB_MAX_CHARS = 20`，播放器的字号我们管不着）。

#### 命令序列

```bash
# 中文那条照旧：sync -> （有硬线就 vofit）-> check
python make_story_v.py vofit        # **先定死中文**：它会把所有的槽改短
python make_story_v.py langfit      # 再压英文（顺序反了，langfit 的结果会被 vofit 作废）
python make_story_v.py preview en   # 单听英文那条，这时候图还没出，改稿最便宜
python make_story_v.py check        # 多两段：check_mode（形态×语言）+ 英文轨逐句对槽
python make_story_v.py c            # 一次出四样，见下
python make_story_v.py srt          # 只改了文案时跑它，不用重渲
```

**`vofit` 在 `langfit` 之前**，这是竖版独有的一条顺序 —— 横版没有硬线、没有 vofit。
反过来做不报错：英文文件还在、长度也没变，只是槽变短了，它们现在长出去了。
`vofit` 跑完会自己提醒一句，`check` 会从磁盘重量一遍拦住。

#### 交付物（多音轨时 `c` 一次出四样）

| 文件 | 是什么 | 干什么用 |
|---|---|---|
| `成片_竖版.mp4` | 视频 + **中文一条轨** | **这个才是上传件** |
| `成片_竖版_音轨_eng.m4a` | 英文独立音频，和画面等长 | 在 Studio 里作为附加语言添加 |
| `成片_竖版.srt` / `.en.srt` | 两份外挂字幕 | 跟着片子一起传 |
| `成片_竖版_多音轨.mp4` | 两条轨都在 | 留档，**不要传这个** |

拆分和横版 `join.py` 同一个道理、同一套验证：拆完验上传件只剩默认那条、
独立音频与画面等长（差 0.05s 以上直接报错，因为差一点点就是整条错位，
而这在文件里看不出来）。多音轨文件传上去只会保留第一条轨，其余静默丢掉。

#### 一支片子发两个平台时

抖音/小红书那一版（`SUB_MODE="burn"`，`LANGS=["zh"]`）和 YouTube Shorts 那一版
（`SUB_MODE="srt"`，`LANGS=["zh","en"]`）**是同一条画面的两次 `c`**。
先渲哪个都行，但**成片文件会互相覆盖**（文件名一样）—— 渲第二版之前
把第一版挪走或改 `OUT_NAME`。
