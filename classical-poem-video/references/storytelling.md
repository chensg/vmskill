# 讲述模式：把一个历史小故事做成短片

诗片和故事片共用同一条渲染流水线（prep / a / b / c、trace、measure、still），
但**开工前定的四件事有三件反过来了**，而且多出一件诗片完全没有的事。
这份文件只写差异——共用的部分看 `SKILL.md`。

> 2026-11-11：第七~十一节（荐书、旁白 TTS、小说、双语细则、外部参考模块）挪到各自的文件，
> 原处只留指针。做一支普通故事片读这份（〇~六）＋ `tts.md` 的速查就够。

| | 诗片 | 故事片 |
|---|---|---|
| 时间轴由什么决定 | 字数 × 0.45 + 1.8 的可读下限 | **旁白实测时长** |
| 字幕 | 竖排、右侧、楷体、一句一列 | **横排、左下、黑体、一句一屏** |
| 每镜停留 | 10~13s | **3~8s** |
| 音乐 | 唯一音源，推到 −9-ish | **侧链躲闪，让位给旁白** |
| 片尾 | 竖排诗文页 | 尾板（或干脆没有） |
| 最大的风险 | 字看不清 | **把推断说成史实** |

## 〇、出图之前的两道门禁（**故事片和荐书片都适用**）

**出图是整条流水线上最贵、最不可逆的一步；改稿是最便宜的一步。**
所以这两件事必须在出图之前由**人**确认过 —— 不是由检查通过，是由用户点头。

| | 门禁 | 怎么过 | 它拦住的是 |
|---|---|---|---|
| 一 | **讲述稿人工确认** | 把讲述稿交给用户读一遍 | 哪句是废话、哪个转折跳了、第三幕是不是在替读者下结论 |
| 二 | **只有字幕+声音的检查片** | `python make_story_*.py preview` 出片，交给用户听 | 旁白好不好听、断句与气口、字幕跟不跟得上、**片长** |

两个都在脚本里有位置，**留空就拦住 `budget`**（`budget` 是"出图前跑、把尺寸抄进
任务书"的那一步，也是最后一个还来得及改稿的位置）：

```python
GATE_SCRIPT_OK  = ""   # 讲述稿已人工确认 —— 写人话：谁看的、改了哪几处
GATE_PREVIEW_OK = ""   # 检查片已人工确认 —— 同上
```

**不给布尔开关**，理由和 `PP_ACCEPT_REASON` 一样：`True` 是无痕的，
半年后回看没人知道当时确认了什么。

### 为什么这两件事检查判不出来

第一道：`check_claims` 只管"有没有把推断说成史实"，管不了"好不好听"。
稿子的毛病全是数值判据够不着的那一类。

第二道更实在 —— **它经常直接改数字**。《经度》段五按 `est` 排出来 138.0s，
33 条旁白实测回来是 **130.5s，差 7.5s**。有平台硬线（YouTube Shorts 180s）时
这个差额是致命的，而它只有在旁白全部生成之后、出图之前的这个窗口里才看得见。

### `preview` 出来的是什么

深灰底 + 一条压暗的横带标出字幕位置，上面写着

```
镜 7 / 15   （镜7 / 镜8 共用一张图）   推近 z 1.16→1.32   9.1s
07_受难者版本.png
```

配真旁白、真字幕、真时间轴。**没有音效没有音乐** —— 这一版要验的是话说得对不对，
多铺一层会让人分神去听氛围（而且这时候音效多半还没找）。
真图到了直接替换同名文件，`CLIPS` / `SHOTS` / `NARR` 一个字都不用动。

实现上有一条讲究：**占位板上所有文字都走 ASS 当字幕烧，一个 `drawtext` 都不用。**
带 `drawtext` 的 ffmpeg 在 Git bash 下会 Fontconfig error + 段错误
（见 `references/codex.md`），而 `subtitles=`（libass）这条路整条流水线天天在跑。

### **但要说清楚这一版验不了什么，别让它冒充通过**

| 检查 | 对占位图 | 为什么 |
|---|---|---|
| `motion` | **结构性失效** | 占位板是均匀灰，中位帧差恒为 0。《4321》镜 19 横移 **28%** 也只量到均差 2.2（判据 4.0）。**不是运镜错了** |
| `trace` / `measure` | 不适用 | 量的是字幕底和落幅的真实明暗，纯色板上没有意义 |
| 字幕**排版**（断行、宽度、安全区） | **有效** | 这几项只跟字号和坐标有关，跟画面无关 |

`motion` 那一条要特别小心：它会报一串「看不出在动」，很容易顺手当成假警**全部**放过。
《4321》五条里有一条是真的 —— 镜 5 是纯推近、z 只从 1.08 走到 1.18（9% 行程），
换成真图也一样窄。**分辨办法是看参数不是看数字**：
有大横移/大拉远却报警的是假警，纯推近且 z 跨度 <15% 的是真警。

## 一、事实分级（故事片独有，也是最要紧的一条）

诗片只要不读错字就不会出事。故事片会出事的地方在于：
**一条讲得顺的因果链，中间往往有一环只是假说。**

「1816 年欧洲没有夏天」是史实；「所以德莱斯发明了自行车」是科技史学者的推断。
两句话在稿子里长得一模一样，念出来一样理直气壮，
而评论区里懂行的人一眼就能看出来——被拆穿一次，整条账号的可信度就折一半。

所以开工时先把每个论断归一次类，写进 `CLAIMS` 表，`check` 每次都打出来：

```python
CLAIMS = [
    ("C1", "史实", "1815 年 4 月坦博拉爆发，有确切记载以来规模最大", "VEI 7"),
    ("C8", "概数", "试骑十几公里，不到一小时", "各版本 13~14.4km，稿里不说死"),
    ("C9", "假说", "马匹危机 → 德莱斯发明", "Lessing 提出；德莱斯本人没写过"),
]
```

三个级别，三种处理：

- **史实** — 正常讲
- **概数** — 稿子里就不要给精确值。「上百立方公里」比「150 立方公里」安全，
  而且**听起来一样有力**。数值区间有分歧时，说区间的中间地带，不说端点
- **假说** — 必须在**片内**说出来，不能只写在简介里。看到简介的人不到十分之一

### 假说不要删，要做成第二次反转

删掉假说，故事就散了——它往往正是这个故事之所以有意思的那一环。
正确的处理是**把自我拆解放在结尾，当作第二个包袱**：

> 「多说一句：这条因果链是科技史学界的主流推断，德莱斯本人没有这么写过。
> 　但 1816 年那个没有夏天的年份，是真的。」

先给结论、再自己拆、最后落回一块硬事实。诚实是免费的，
而且这个结构比平铺直叙**更有劲**——观众记住的是"这号还挺实在"。

`check` 会在 `CLAIMS` 里有"假说"、但 `NARR` 的最后三句里一个字都没提到时报警。

## 二、时间轴是**量出来的，不是排出来的**

诗片没有诵读，屏幕上的时间就是全部的时间，所以要按"读得完"排。
故事片反过来：**旁白落点决定一切**，你排的任何数字都会被 TTS 的实际语速推翻。

所以 `make_story_v.py` 里 `SHOTS` **不写 `dur`**。每镜时长由属于它的旁白算出来：

```
镜 i 的内容时长 D_i = Σ(这一镜每条旁白的 pre + 实测时长 + post)
镜 i 的 dur    = D_i + xf(i)        # 补掉 xfade 吃掉的那一段
```

`vo_durs()` 用 ffprobe 量每条 mp3，按 (文件名, mtime, 大小) 缓存到 `vo_times.json`。
**换了配音重新生成，时间轴自动跟着变**，不用手工回填——手工回填一定会漏。

### 旁白还没生成时怎么排片

`NARR` 每条都要写一个 `est=`（估算秒数）。文件不在时用 `est`，并且
`check` 会大字提醒"时间轴是估算的"。这样出图、排分镜、写图片任务书
都能在配音之前先做完，不用干等。

估算公式：**中文讲述约 4.6 字/秒**（比诗慢、比新闻播报快）。
标点不计字数，但每个逗号大约多 0.15s。

### 气口

`pre` / `post` 是这一句前后的静默。默认 (0.25, 0.45)。三处要单独给：

- **冷开场**：第一句的 `pre` 给 1.2~1.6s。上来就说话，观众还没看清画面
- **转折句之前**给 0.6~0.9s（「但真正改写了历史的，是另一件事——」）
- **金句之前**给 0.8s，之后给 1.2s。留白就是重音

### 语速自检

`check` 会用 `字数 / 实测时长` 算每句语速，落在 **3.8~5.5 字/秒** 之外报警：

- 低于 3.8 —— TTS 拖了，或者这句里有它读不顺的专名（人名、地名、外来词）
- 高于 5.5 —— 太赶，字幕跟不上，观众会漏掉信息

数字和外文专名是重灾区：「1815」「卡尔·冯·德莱斯」「曼海姆」这类
不同 TTS 差得很远，**必须实测**，不能按字数估。

## 三、字幕：横排、左下、避开操作栏

**这一节讲的是"烧进画面"那一种**（`SUB_MODE = "burn"`，竖版的默认）。
外挂字幕（`SUB_MODE = "srt"` —— 发 YouTube Shorts，也是竖版做双语的前提）
由播放器排版，下面这些坐标和像素判据一概不适用，判据换成字数：见第十节第九小节。

竖版右侧 x 929~1080 / y 864~1632 是抖音小红书的操作栏（真机验过，见 `SKILL.md`）。
诗片的竖排字幕在右侧那条窄带上，靠**上移**避开；
故事片的横排字幕是宽的，靠**收窄 + 靠左**避开：

```
SUB_CX     = 475          # 列心，不是 540
SUB_MAX_W  = 830          # 文本框最宽，右缘 890 < 操作栏左沿 929
SUB_FS     = 54
SUB_BOT    = 1440         # 字块底，低于它就进发布文案区了
SUB_LH     = 74           # 行高
```

一屏最多 **两行、每行 15 字**（15 × 54 = 810 ≤ 830）。
稿子里用 `｜` 手工标断行位置——**不要交给自动换行**，
自动换行会把「一座火山炸出来的」拆成「一座火山炸出」+「来的」。

`check_safe()` 对每条字幕算外接矩形，撞了就报。它同时防三个区：
顶部导航（y < 173）、右侧操作栏、以及底部发布文案区（y > 1560，**这一条还没在真机
上比过**，是按常见版式估的保守值）。

字体用**黑体不用楷体**。讲述是现代口吻，楷体会把它拉回"读诗"的调子；
而且横排小字号下楷体的可读性明显不如黑体。

## 四、镜数与节奏

一条 90~110s 的故事片排 **12~16 镜**，每镜 3~8s。

诗片可以全片一个转场时长，故事片不行——**转场是叙事标点**：

| 位置 | 转场 |
|---|---|
| 钩子之后 | **0.4~0.5s 硬切**。抛完钩子立刻进正题，溶解会泄气 |
| 段落翻页（天灾 → 人祸这种） | **1.8~2.2s 长溶解**，全片一两处，多了就没有了 |
| 转折句之后 | **0.4s 短切**，要一记硬的 |
| 金句 | **2.0s 长叠化**，金句要叠上去不是切上去 |
| 其余 | 1.0s |

**镜 1 和最后两镜要在视觉上闭环**：钩子用现代画面、中段用历史画面、
金句那一镜把两者叠在一起。这是故事片最便宜也最有效的一个结构，
诗片没有对应物。

## 五、音频：三条轨，音乐要躲

诗片只有音乐一条轨（外加音效）。故事片是**旁白 + 音乐 + 音效**，
而且音乐必须给旁白让路。

**只调低音量是不够的。** 压到听不见音乐就没意义，压不够旁白就发浑。
正确做法是**侧链躲闪**：旁白一进来音乐自动降 6~8dB，旁白一停自动回来。

```
[music][vo]sidechaincompress=threshold=0.06:ratio=6:attack=25:release=350
```

`release` 别给太短，300~400ms 之间——短了音乐会在句间"一鼓一鼓"地喘。

其余数值：

- 旁白在成片里的整合响度目标 **−16 LUFS**，成片总目标仍是 −15
- `MUSIC_GAIN` 比同长度的诗片**低 3~4dB**（诗片 −9，这里 −12~−13）
- 音效增益一律写**目标响度**、由脚本按实测反算，不写死 dB
  （生成的音效响度能差 45dB，见 `music.md`「音效」）

### `SFX` 两条会让人写错表的事（2026-09-15《莫森》）

**一、`shot=` 是段内下标，不是全局镜号。** `NARR` 的 `shot=` 也是。
分段片子里这一条**几乎必然踩**：段一的 1–18 和全局镜号碰巧重合，
表写出来看着全对，到段二以后才错位 —— 而且错位不报错，
只是音效落在别的镜上（越界才会被 `check_sfx()` 拦）。

做法：**表用全局镜号写，让脚本换算**。换算那一步再顺手断言一句
「这一段的下标都在 1~len(SHOTS) 之间」。

**二、`SFX` 条目没有逐条滤镜。** 只有 `f / tgt / fi / fo / off / span|dur`，
没有地方挂 `lowpass`。同一条风要「屋外」「隔一层帐篷布」「隔一堵木墙」三种质地，
得**预先滤好存成三个文件**（`wind_lp800.mp3` / `wind_lp500.mp3`），
在表里当三条不同素材用。

顺带：循环是 `-stream_loop -1` 接 `atrim`，所以**尾部做过淡出的素材必须先裁尾**，
否则每一圈都凹一下。裁法是从尾巴往回找 RMS 回到头部 ±3 dB 的位置切掉。
**别用 `acrossfade` 去「做循环件」** —— 那个滤镜是拼两条用的，
拿它接自己只会把长度翻倍，接缝一点没改善。

### 音乐切入点：要紧的是**旁白不在的地方**

诗片的 maximin 关键窗口是"每句字幕的落点"。故事片全程有旁白盖着，
音乐在那些地方本来就该退到后面——**真正听得见音乐的是旁白之间的缝**。

所以 `pick_music_in()` 的关键窗口自动取：冷开场、每个 ≥1.5s 的长转场、
金句前后的留白、尾板。诗片那套窗口照搬过来会选错点。

## 六、素材

和诗片同一套判据：**尺寸跑 `python make_story_v.py budget` 反推**，
按每一镜自己的运动算（静帧 pp≥1.00 / 运镜 ≥1.20 / 细节镜 ≥1.30），
**不要一律填 4K**——超过 PREP 短边 2160 的部分在 `prep` 第一步就被丢掉。
详见 `references/sourcing.md` 第 1 条。

讲述片在这一条上比诗片更吃香：历史题材常要用档案照片、老版画、地图，
那些东西的分辨率是给定的、改不了。**把这类镜头标成 `motion="static"`，
门槛就从 pp 1.20 降到 1.00**，很多本来判死的素材立刻可用——
而讲述片有旁白连着说，画面停住并不空。

一处反过来：**故事片的字幕在左下，所以出图要求「左下留暗」**，
不是诗片的「右侧留白」或《雨霖铃》的「右上留暗」。
写图片任务书时最容易照抄错的就是这一条——留暗事后补不回来。

### 暗调生成图的调色：不能加反差，也不能用 gamma

讲述片的画面几乎都是暗调实拍，而生成器交回来的这类图**几乎一定是技术性欠曝的**。
《没有夏天的那一年》实测：median 14、p25 1~8、mean 21~24。

对这种图有两个都错的直觉：

- **加反差是负的。** `eq=contrast=1.04` 把 median 从 14 压到 **8**、p25 从 8 压到 2。
  模板里那个看着人畜无害的默认值就是这么把画面压死的
- **`eq=gamma` 会把黑位一起抬起来。** gamma=1.25 时 p1 从 1 涨到 **14** ——
  火山那道黑山脊会变成灰的，画面立刻显得脏

要的是**只抬中间调、保住真黑**，所以用 `curves`：

```
curves=all='0/0 0.08/0.13 0.28/0.42 0.60/0.70 1/1',eq=saturation=0.98
```

实测 median 14→23、p75 29→47，而 p1 仍是 0~1。
连带收益：`trace` 的落幅整帧极差从 125/131 涨到 148/153，运镜明显更看得出来。

**换素材必须重新量再定，不要照抄这条。** 判断依据永远是量出来的直方图。

镜数比诗片多（12~16 vs 8~9），但**不必一镜一图**：
同一场景可以出一张大图、用两次不同的取景窗（`CLIPS` 里 `cx/cy/zoom` 不同）。
12 镜常常 9~10 张图就够，省下的额度用来把关键的两三张出到 4K。

### 六之补、插一段资料视频（`CLIPS` 里给 `video=`）

历史题材有时**存在真的影像**——档案馆的新闻片、早期电影的残片、公版纪录片。
这类素材不是插图的替代品，它是另一种东西：**图是「关于那件事的画面」，
影像是「那件事本身」。** 有它而不用，等于把最硬的证据换成了示意图。

一条 `CLIPS` 给了 `video=` 就是视频镜，它和静帧镜、运镜镜**平级**——
不是贴在静帧片上的一个图层：

```python
CLIPS = [
    dict(video="A.mp4", ss="20:10", to="20:30", tweak=""),   # 视频镜
    dict(src="03_海报.png", zoom=1.00, cx=0.50, cy=0.50, tweak=""),
]
```

`SHOTS` 里那一镜照写（`z`/`f` 会被忽略），**不用也不要写 `motion=`**：
素材是不是一段影片，由 `CLIPS` 一处说了算，不该靠两处配置对上口径才成立。

**`ss`/`to` 接受 `"20:10"` 这种时间码**，也接受秒数。写成 `20.10` 想表示 20:10
是这里最容易犯的错——值合法、位置差了十分钟，而且量不出来。

#### 时长永远由旁白说了算

`to - ss` 是**素材段**，镜长是**旁白算出来的**，两者没有约束关系。
`prep` 把整段归一成 `vidNN.mp4`，`pass_a` 从它头上取镜长那么多秒。

段比镜长短会**冻结末帧补足**——画面僵在那里好几秒，而 ffmpeg 退出码是 0。
所以 `check_video` 拦两级：**短了直接拦**；只多一点（不足 `VIDEO_HEADROOM` 0.5s）
也拦，因为旁白重新生成后镜长会变，**现在刚好够等于以后不够**。

#### 画幅：默认加黑边，不裁

老素材几乎都是 4:3，成片是 16:9。`VIDEO_FIT` 两个值：

| | 做什么 | 什么时候用 |
|---|---|---|
| `"pillarbox"`（默认） | 左右加黑边，画幅完整 | **默认。档案影像本来就该看着像档案** |
| `"crop"` | 裁上下填满画框 | 只在画面上下确实是废边时 |

4:3 裁 16:9 要**丢掉 25% 的画面**。讲残缺、讲遗失、讲「还剩多少」的题材尤其
不能裁——裁掉画面和旁白说的话自相矛盾，那是画面在反驳旁白。

#### 分辨率：视频镜不走 pp 判据

640×480 的残片铺到 1080 高是 2.25 倍放大，按 `pp < 1.0` 那条线一刀切会把
整支片子判死。**而「糊」恰恰是这类素材的内容本身。**
`check_resolution` 因此把视频镜单列一张表，只报事实（原始尺寸、帧率、放大倍数、
裁掉多少），不拦。放大超过 3 倍会标出来——那时该考虑的是换一段，不是改判据。

`motion` 同理**两个方向都不判**：末段那种几乎全是化学斑的档案影像首尾帧差可能
极小，那是内容，不是「运镜看不出来」。

#### 帧率：落到 `FPS`，但不要插值

`prep` 就把视频落到成片 `FPS`。不统一的话 `pass_c` 的 concat 会得到一段
时间戳乱掉的片子，**而且它不报错**。
用的是 `fps` 滤镜的丢/复帧。**不要改成 `minterpolate`**——默片本来就抖，
插出来的中间帧会把那份抖动抹成糊的，而抖动往往正是"这是老片子"的全部信号。

#### 授权登记

视频和图走同一张 `CREDITS` 表，**键是 `video=` 的文件名**，同样五项缺一不可。
`credits` 导出的表会多两列：类型（视频/静图）和**用到的段**（`ss–to`）——
用了别人素材的哪一段，是署名的一部分。

**别把「能下载」当成「能再用」。** 上传者写的 CC0 和这份素材的实际权利是两回事，
两个方向都要查：底层作品（年代、法域）和这一次数字化/修复（可能另起新权利）。
数字修复版尤其要当心——把腐蚀修干净的那一版，既可能有新权利，
也已经洗掉了你要讲的东西。
